# Честный знак в WMS

Как WMS работает с марками Честного знака (ЧЗ): что читает, где хранит, как марка проходит склад
от приёмки до УПД. Решения - [ADR-0017](adr/0017-chestny-znak-true-api-read.md), задачи фазы -
[`cz/README.md`](cz/README.md).

## Граница

- **WMS только читает ЧЗ** через True API: товар, владелец, статус, дата производства и срок
  годности по марке, состав упаковки по коду агрегации. В ЧЗ WMS ничего не пишет и ничего не
  подписывает: документы (УПД, расформирование) подписывает СБИС.
- **Вход - подписью сотрудника с МЧД**, роль в ЧЗ «без права подписи». Токен - на организацию,
  живёт около 10 часов, бэкенд получает и обновляет его сам (CZ-02).
- **Подписант - служба `cz-signer` на хосте**, бэкенд ходит к ней через unix-сокет; пароль копии
  ключа бэкенд не видит, в бэкапы ключ не попадает. Лицензия КриптоПро CSP на сервере пробная -
  долг 31 в `dev-context.md`.
- **Читаются только товарные группы с договором** у организации; по остальным ЧЗ отдаёт лишь GTIN.

## Коды

| Что                 | Штрихкод      | Код в WMS                                       |
|---------------------|---------------|-------------------------------------------------|
| Марка единицы       | DataMatrix    | КИ: `01` + GTIN + `21` + серийный, часть до GS   |
| Групповая упаковка  | DataMatrix    | тот же вид, что у марки; вид - по ответу ЧЗ     |
| Транспортный короб  | GS1-128       | `00` + SSCC                                     |

- Криптохвост после GS не хранится и в запросы не идёт: True API ищет марку по КИ.
- Сервер сам срезает префикс AIM (`]d2`, `]C1`) и хвост после GS.
- Товар марки - по GTIN через `barcodes`: GTIN-14 - это EAN-13 товара с ведущим нулём.
  Незнакомый GTIN - привязка ШК поиском, как у любого незнакомого ШК.
- **Партия - дата производства единицы**, а не упаковки: у упаковки это время агрегации.

## Хранение

- **`cz_marks`** - марка: товар, партия, статус и место. Место ровно одно, пока марка на складе:
  в ГЕ (`load_unit_id`) или россыпью (`cell_id` + внутренний склад). Отгруженная, списанная,
  возвращённая марка места не имеет (`shipped`, `written_off`, `returned`).
- **`cz_aggregates`** - упаковка: код, вид (`BOX`, `GROUP`), вложенность (`parent_code`:
  групповая в коробе, один уровень), ГЕ короба и признак «вскрыт» (`opened_at`).
- **Короб ЧЗ - это ГЕ WMS** без своего QR-ярлыка, узнаётся сканом SSCC. Свой короб с QR - для
  россыпи, в ЧЗ он не регистрируется.
- **В какой упаковке марка пришла** (`aggregate_code`) и **где она сейчас** - разные вещи:
  первое меняется только расформированием в ЧЗ, второе - каждым движением.
- **Маркируемый товар** (`goods.cz_marked`) - по факту: признак ставит привязка ШК из марки и
  принятая марка, правит admin. Такой товар двигается только марками.

## Путь марки

### Приёмка (CZ-05)

- Скан марки или короба сразу читается из ЧЗ - только со связью: кладовщик видит состав и
  расхождения на месте. Сама приёмка уходит очередью `receipt_submit` с уже прочитанными данными.
- Короб ЧЗ - одним сканом: ГЕ с составом из ЧЗ, групповые упаковки внутри - агрегатами. Кладовщик
  выбирает только ячейку.
- Марки россыпью - по одной в строку россыпи или своего короба; групповая упаковка - одним сканом,
  набором своих марок.
- Расхождение (владелец не наша организация - `CZ_OWNER_INN`, марка не в обороте) приёмку не
  останавливает: товар принят и при проводке уходит проблемой склада в «Изолятор» (`foreign_mark`,
  `retired`). Короб с расхождением - проблемой на всю ГЕ.
- Повтор принятой марки или короба - отказ операции, а не повтор очереди.

### Движение (CZ-06)

- Размещение, перемещение, пометка проблемы, возврат поставщику - марками. Короб ЧЗ целиком
  переезжает сканом SSCC, его марки едут с ним.
- Без связи марки ищутся в снимке содержимого склада; сервер при проводке проверяет, что каждая
  лежит в источнике строки и принадлежит её товару и партии.
- **Вскрытие - по факту.** Упаковка вскрыта, когда её марка ушла со склада, ушла из её короба ЧЗ
  или (у групповой) разошлась с остальными её марками. Групповую упаковку, перенесённую целиком,
  это не вскрывает. Признак не снимается.
- Решение офиса по проблеме берёт ровно её марки: «списать» - `written_off`, «разместить» -
  метка снята вместе с остатком. Возврат поставщику - `returned`.
- Пересчёт (P10) считает марки поштучно, перепривязка ШК маркируемого товара - через «Пересорт»
  (ADHOC-53).

### Сборка и отгрузка (P9, CZ-07)

- Маркируемый товар собирается только марками: сканом каждой марки или короба ЧЗ (засчитываются
  все его марки). Марка в сборке другой операцией не двигается.
- «Завершить сборку» переносит марки в короба отгрузки. **Короб ЧЗ, все марки которого легли
  вместе в один короб отгрузки, остаётся целым**; взятый частично или разложенный по двум коробам
  отгрузки - вскрыт. Проверка - один раз после всех пиков заказа.
- Возврат на места после правки реестра переносит марки в ячейку россыпью и вскрывает упаковку.
- Отгрузка ставит марки «отгружены» без места.

### УПД (CZ-07)

Оператор делает УПД по выгрузке Excel «Сборка-отгрузка», лист **«Марки для УПД»**: собранные и
отгруженные заказы, только перенесённое в короба отгрузки.

| Что уехало                          | Строки                                                 |
|-------------------------------------|--------------------------------------------------------|
| Целый короб ЧЗ                      | «короб ЧЗ» с кодом агрегации, ниже его марки «в коробе ЧЗ» |
| Целая групповая упаковка вне целого короба | «упаковка ЧЗ», ниже её марки «в упаковке ЧЗ»     |
| Вскрытый короб, свой короб, россыпь | марки по одной, вид «марка»                            |

Целая упаковка - не вскрыта, все её марки в перенесённых пиках этого заказа и в одном коробе
отгрузки. На листе «Сборка» то же под фактом позиции.

## Сценарии

`apps/backend/internal/service/cz_scenarios_integration_test.go` (CZ-08D) проходит путь марки
по живой базе теми же операциями очереди, что ТСД:

- **`TestCZScenario_wholeBoxShipped`** - приёмка короба ЧЗ (упаковка и марка в коробе) и россыпи,
  товар стал маркируемым; размещение россыпи марками; заказ коробом ЧЗ и заказ маркой; завершение и
  отгрузка короб не вскрывают, марки отгружены; в УПД - код короба с тремя марками и марка россыпи.
- **`TestCZScenario_openedBox`** - перемещение вынуло марку из короба: короб вскрыт, упаковка цела;
  заказ упаковкой и вынутой маркой - в УПД упаковка своим кодом, марка отдельно, кода короба нет.
- **`TestCZScenario_partialBox`** - короб взят частично: до завершения цел, после - вскрыт вместе с
  упаковкой; УПД собранного заказа - марками.

Шаги по отдельности и отказы - тесты задач: приёмка с эталоном формата ТСД
(`handler/receiving_cz_http_test.go`), движение и вскрытие (`repository/cz_movement_integration_test.go`),
проблемы (`repository/cz_problem_integration_test.go`), целые короба в сборке
(`repository/picking_cz_boxes_integration_test.go`), лист УПД (`report/picking_xlsx_test.go`).

```bash
colima start
cd apps/backend
export DOCKER_HOST="unix://$HOME/.colima/default/docker.sock" TESTCONTAINERS_RYUK_DISABLED=true
go test ./internal/service -run TestCZScenario -v
colima stop
```
