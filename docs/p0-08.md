# P0-08 · CI: lint + test + build (Go + Flutter) + docker-образы

**Статус:** ✅ пайплайн написан и статически проверен (actionlint чист; все команды джобов прогнаны локально зелёными). Первый реальный прогон — на первом push/PR в `dev`.
**Задача:** на каждый PR/пуш в интеграционные ветки автоматически гонять lint + test + build обоих стеков и собирать docker-образ бэкенда.
**Критерий готовности:** пайплайн зелёный на PR, образы собираются.

Файл: [`.github/workflows/ci.yml`](../.github/workflows/ci.yml).

---

## Политика триггеров (решение)

```yaml
on:
  pull_request: { branches: [dev, main] }   # гейт перед мержем
  push:         { branches: [dev, main] }    # post-merge + публикация образа
```

- **Гейт — PR `p0-XX → dev`** (и `dev → main`): `dev` — интеграционная ветка, куда вливается каждая задача, поэтому проверять надо здесь, а не только на редком PR→main (иначе поломки всплывают поздно и пачкой).
- **push в dev/main** — те же проверки + сборка/публикация docker-образа (только из влитого кода, не из PR).
- **Фиче-ветки** отдельно не гоняем — их вершину покрывает событие `pull_request` (экономия минут Actions; `concurrency` отменяет устаревшие прогоны).

Чтобы красный **физически блокировал мерж**, нужен branch protection — но на приватном free-тарифе он не enforced (см. «Блокировка мержа»); пока — самодисциплина.

## Джобы

| Джоб                  | Что делает                                                                                                                                                        |
|-----------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **backend (Go)**      | `go build` · `go vet` · `go test` · **golangci-lint** (пин `v2.12.2`), Go `1.25`.                                                                                 |
| **flutter (Android)** | JDK 17 → Flutter `3.41.2` → `pub get` → **`build_runner`** (генерённые файлы в .gitignore) → `flutter analyze` → тесты (если есть `test/`) → `flutter build apk --debug`.                                                                                                                                                                                   |
| **docker (→ GHCR)**   | Только на `push` (dev/main). Сборка `apps/backend/Dockerfile` и публикация в **GHCR** (`ghcr.io/<owner>/craft-wms-backend`), теги `:<ветка>` и `:<sha>`. Логин по `GITHUB_TOKEN` (без внешних секретов).                                                                                                                                                      |

### Ключевые решения

- **Версии зафиксированы** (Go 1.25, Flutter 3.41.2, golangci-lint v2.12.2) — детерминизм: новые релизы не «покраснят» пайплайн неожиданно.
- **golangci-lint ставится install-скриптом на пиненую версию** (не через action с плавающим мажором) — та же версия, что проверена локально.
- **Codegen обязателен в CI:** `*.freezed/*.g/*.gr/*.config.dart` в .gitignore, без `build_runner` анализ/сборка падают.
- **Тест-джоб не падает на пустоте:** пока нет `test/` — шаг пропускается; наполнится реальными тестами (см. «Осталось»).
- **Образ — тот же, что в docker-compose (P0-01):** в прод уедет ровно то, что прошло проверки.
- **Реестр GHCR:** встроен в Actions, бесплатен для репо, без внешних секретов.

## Блокировка мержа (branch protection) — ⚠️ недоступна на текущем тарифе

Цель «красный CI физически запрещает мерж» требует **branch protection / rulesets**, но на **приватном репозитории с бесплатным личным аккаунтом GitHub они не enforced** (GitHub прямо предупреждает: *«Your rules won't be enforced on this private repository until you move to a GitHub Team or Enterprise organization account»*). Правило создать можно — но реально блокировать мерж оно не будет.

Варианты:
- **Текущее решение — самодисциплина (соло-пилот).** CI гоняется на каждом PR и показывает ✅/❌; правило — **не мержить красный PR**. Единственный коммиттер видит статус — этого достаточно. Стоимость $0, настройка не нужна.
- **GitHub Pro** (~$4/мес) — включает protection для приватных репо; тогда выбрать *Require status checks* → `Backend (Go)`, `Flutter (Android)` для `dev`/`main` (чеки появляются после первого прогона CI).
- **Публичный репозиторий** — protection бесплатен, но проект клиентский → как правило нет.

Итог: **enforced-блокировка отложена** до перехода на Pro; ценность P0-08 — сам зелёный/красный пайплайн на каждом PR.

## Проверка локально (эквивалент джобов)

```bash
# backend
cd apps/backend && go build ./... && go vet ./... && go test ./...
golangci-lint run ./...            # v2.12.2

# flutter
cd apps/craft_wms && flutter pub get
dart run build_runner build --delete-conflicting-outputs
flutter analyze && flutter build apk --debug

# docker-образ бэкенда
docker build -f apps/backend/Dockerfile apps/backend
```
