# ADR-0002 · Бэкенд на Go + chi

**Статус:** Принято

## Контекст
Нужен бэкенд: REST, JWT-middleware, работа с PostgreSQL, простое развёртывание в контейнере,
предсказуемая производительность для склада. Рассматривались Go (chi / echo / gin) и альтернативные
рантаймы.

## Решение
**Go** — статический бинарь, минимальный образ (alpine), низкое потребление, сильная стандартная
библиотека `net/http`. Роутер — **chi**: тонкая надстройка над `net/http` (не фреймворк),
идиоматичные `http.Handler`/middleware, без «магии» и лишних зависимостей.

Почему chi, а не echo/gin: chi не навязывает свой тип контекста и не уводит от стандартного
`http.Handler` — код остаётся переносимым, middleware совместимы со всей экосистемой `net/http`.
Для объёма пилота возможности echo/gin избыточны.

## Последствия
- **+** Малый, статически слинкованный образ; быстрый старт; минимум зависимостей.
- **+** Стандартные `http.Handler` — легко тестировать и переносить.
- **−** Меньше «батареек» из коробки, чем у фреймворков (валидация, биндинг) — пишем явно; для
  текущего объёма приемлемо.
