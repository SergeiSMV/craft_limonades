# ADR-0001 · Монорепозиторий (`apps/` + `infra/`)

**Статус:** Принято

## Контекст
Проект состоит из двух стеков — Flutter-приложение (ТСД) и Go-бэкенд — плюс инфраструктура
(compose, nginx, миграции). Разработчик один. Нужно решить: один репозиторий или несколько.

## Решение
Один репозиторий. Раскладка: `apps/craft_wms` (Flutter) и `apps/backend` (Go) симметрично под
`apps/`; окружения — в `infra/` (compose-файлы, nginx); документация — в `docs/`. Миграции и
`Dockerfile` живут рядом с бэкендом (`apps/backend/`), а не в отдельном каталоге. Общей обёртки над
несколькими сервисами нет — сервис один.

## Последствия
- **+** Одна точка правды, атомарные коммиты через оба стека, единый CI, простая навигация для соло-разработчика.
- **+** Схема БД описана в одном месте (`apps/backend/migrations`), без дублирующего `db/`.
- **−** CI собирает оба стека на изменение любого — смягчено (см. [ADR-0009](0009-ci-github-actions-ghcr.md)).
- Пустые «на вырост» каталоги не заводим — создаём по факту надобности.
