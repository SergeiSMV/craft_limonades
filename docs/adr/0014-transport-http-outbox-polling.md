# ADR-0014 · Транспорт: HTTP + Outbox + polling (без брокера и WebSocket)

**Статус:** Принято

## Контекст
С появлением заданий на сборку ([P9](../roadmap.md)) данные пошли в обе стороны: не только
«устройство → сервер» (операции), но и «сервер → устройство» (задания), плюс «сервер → портал»
(статусы). Возник вопрос, нужен ли для этого постоянный канал — WebSocket — или брокер сообщений
(RabbitMQ), особенно с учётом нестабильной сети на складе.

Важно развести понятия: **RabbitMQ — брокер между серверными компонентами**, он не разговаривает
с браузером и ТСД напрямую; **WebSocket — транспорт клиент↔сервер**. Это не альтернативы друг другу.
И главное — **ни то, ни другое не решает нестабильную связь**.

## Решение
**Транспорт — обычный HTTP. Надёжность — на Outbox и идемпотентности. Актуальность — на polling.**

- **Устройство → сервер:** операция пишется в локальный Outbox с `operation_id` и уходит при
  появлении сети с ретраями и backoff ([ADR-0007](0007-offline-first-outbox.md), P2-03/04/05).
  Это и есть ответ на обрывы связи.
- **Сервер → устройство (задания):** опрос при активном экране + кнопка «Обновить».
  Постоянный WebSocket на складском Wi-Fi — источник полуоткрытых соединений (сокет «жив», данные
  не идут), бесконечных реконнектов и расхода батареи. Задержка в полминуты для кладовщика
  не существует. Push через FCM не берём: на Urovo может не быть сервисов Google.
- **Сервер → портал (статусы):** опрос раз в 5–10 с. При потребности в «живом» обновлении —
  **SSE** (`text/event-stream`): односторонний поток, реконнект по спецификации, один хендлер на Go.
  WebSocket нужен для двустороннего интерактива, которого в портале нет.
- **Брокер не вводится.** Один бэкенд, один склад, десятки операций в день. Очередь уже есть —
  это таблицы Outbox в Postgres. RabbitMQ добавил бы контейнер, мониторинг и бэкап
  на ноутбук-сервер в обмен на ноль пользы.

## Последствия
- **+** Нет нового рантайма в проде; эксплуатация не усложняется.
- **+** Поведение при обрыве связи предсказуемо и уже покрыто тестами P2.
- **+** Нет класса багов «висящий сокет»: каждый опрос — независимый запрос.
- **−** Задание доезжает до ТСД с задержкой до интервала опроса (десятки секунд).
- **−** Лишние пустые запросы при простое; смягчается интервалом и опросом только активного экрана.
- Пересмотреть, если появятся: несколько складов, потребность в мгновенной раздаче заданий
  или второй серверный компонент, которому нужна развязка через очередь.
