# ADR-0017 · Честный знак: чтение через True API по МЧД, марка — по КИ

**Статус:** Принято (разведка CZ-01 на проде, только чтение)

## Контекст

WMS внедряет Честный знак (ЧЗ) только на чтение: по скану марки или кода агрегации узнать
товар, владельца, дату производства и срок годности, раскрыть состав упаковки и вести учёт
марки на складе — в ячейке и в коробе. Документы в ЧЗ подписывает СБИС, WMS ничего не
подписывает и не отправляет.

До кода нужно было проверить на живых данных, что это вообще возможно: пустит ли True API
пользователя с ролью «без права подписи», что приходит по марке и по упаковке, что отдаёт
сканер DT50S. Проверка шла на боевом сервере WMS (Ubuntu 22.04) с реальным токеном и марками
товара со склада.

## Что проверено

### Вход в True API

- **Подпись:** КЭП физлица (сотрудника) на Рутокен Lite, сертификат УЦ «Тензор». На сервере —
  КриптоПро CSP 5.0 R3 для Linux и служба смарт-карт `pcscd`; токен вставлен в сервер.
- **Вход:** `GET /auth/key` → строка подписывается присоединённой подписью CAdES-BES →
  `POST /auth/simpleSignIn` (`uuid` + подпись в base64). Получен токен (`HTTP 200`).
- **Токен — на организацию, а не на физлицо:** в нём ИНН участника, идентификатор и номер МЧД
  (доверенность создана в СБИС). Пользователь в ЧЗ — «без права подписи»; читать марки этой
  роли достаточно.
- **Срок токена — около 10 часов.** В токене — товарные группы участника и их статусы.

### Товарные группы

Марки читаются только по группам, где у организации есть договор с оператором. По марке
группы, которой у участника нет, приходят лишь GTIN и группа, а подробности — отказ `403`
«Отсутствует действующий договор по товарной группе». Так ответила марка упакованной воды
(`water`): этой группы у организации в ЧЗ нет.

### Марка: искать по КИ

- **Код с криптохвостом (`…<GS>93…`) True API не находит (`404`); находит КИ — часть до GS:**
  `01` + GTIN + `21` + серийный номер. Ключ марки в WMS — КИ.
- По марке единицы (`UNIT`) приходят: наименование, GTIN, группа, ТН ВЭД, производитель,
  владелец и адрес его места деятельности (склад Шабулина), статус (`INTRODUCED` — в обороте),
  **дата производства** и **срок годности**, декларация соответствия. Проверено на пиве
  (`beer`), безалкогольном пиве (`nabeer`) и лимонаде (`softdrinks`).
- **DT50S отдаёт разделитель GS (`0x1D`)** в коде марки: марка приходит целиком.

### Упаковки: два вида агрегата

| Вид           | Штрихкод          | Код в ЧЗ                          | GTIN       | Тип в ЧЗ       |
|---------------|-------------------|-----------------------------------|------------|----------------|
| Транспортная  | GS1-128, `]C1`    | `00` + SSCC (без `00` — `404`)    | нет        | `BOX`          |
| Групповая     | DataMatrix, `]d8` | как у единицы: `01`…`21`…         | свой       | `GROUP`        |

- **Состав приходит одним запросом** (`child` — КИ вложенных марок): 24 марки в транспортном
  коробе, 12 и 6 — в групповых упаковках. У вложенной марки есть **`parent`** — упаковка, в
  которой она лежит.
- **Групповую упаковку по формату не отличить от марки единицы** — тот же вид кода. Различает
  ответ ЧЗ (`packageType`) или GTIN упаковки в справочнике товаров.
- **Дата производства групповой упаковки — момент агрегации** (лимонад: упаковка 14.10, бутылки
  в ней — 13.10). Срок годности у них одинаковый.

## Решение

1. **Чтение ЧЗ — через True API по токену организации**, полученному подписью КЭП сотрудника
   с МЧД; роль «без права подписи». WMS в ЧЗ ничего не пишет.
2. **Марка в WMS — КИ** (часть кода до GS); криптохвост не хранится и в запросы не идёт.
3. **Код агрегата транспортной упаковки — `00` + SSCC** со штрихкода GS1-128; групповой —
   тот же формат, что у марки единицы, вид определяется по ответу ЧЗ или GTIN.
4. **Партия товара — дата производства единицы, а не упаковки:** у упаковки это время
   агрегации.
5. **Марка уникальна, и учёт идёт по ней** (решение 2026-10-22): на размещении марку
   привязывают к ячейке, а россыпь можно собрать в свой короб с QR — это внутренний код
   агрегации склада; в ЧЗ он не регистрируется.

## Последствия

- **CZ-02:** сервер получает токен сам и обновляет его до истечения. Где живёт ключ — решить
  в CZ-02: сейчас это личная КЭП сотрудника на токене в сервере, а на токене лежат и чужие
  ключи. Варианты — отдельная подпись на сотрудника под эту задачу или копия контейнера
  только с этим ключом. Лицензия КриптоПро на сервере — пробная, на 90 дней.
- **CZ-03:** ключ марки — КИ; у агрегата — код (`00`+SSCC или КИ групповой упаковки), состав
  и признак «вскрыт».
- **CZ-04:** раскрытие агрегата одним запросом; вид упаковки — по `packageType`; дата партии —
  у единицы.
- **CZ-05:** скан GS1-128 с AI `00` — код агрегата, а не штрихкод товара (сейчас ТСД считает его
  товаром). DataMatrix — марка или групповая упаковка, без связи вид не узнать — это долг
  «проверка марок без связи».
- **Товар группы, которой нет у участника** (вода), по ЧЗ не читается; это вопрос к учёту
  компании, а не к WMS.

## Не проверено

- Снеки (`grocery`): статус группы у участника отличается от остальных.
- Вложенность выше одного уровня — паллета или транспортный короб с групповыми упаковками:
  что приходит в `child`, упаковки или единицы.
- Отгрузка части агрегата без расформирования — правила ЧЗ, чтением это не проверить.

## Как повторить

Скрипты разведки — `scripts/cz-probe/`: `token.sh` (токен; `CZ_THUMB` — отпечаток сертификата,
PIN спросит КриптоПро) и `info.sh` (марки и агрегаты по токену). Только чтение.
