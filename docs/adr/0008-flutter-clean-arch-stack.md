# ADR-0008 · Flutter: чистая архитектура и стек

**Статус:** Принято

## Контекст
Приложение ТСД будет расти (справочники, приёмка, размещение, перемещение, офлайн). Нужны
предсказуемая структура, тестируемость и отсутствие «магических чисел»/хардкода текста.

## Решение
**Чистая архитектура**: `presentation → domain → data`, зависимости внутрь. Стек:
- **auto_route** — декларативная типобезопасная навигация (гейт по auth-состоянию);
- **flutter_bloc + freezed** — состояние (sealed-union состояния, `AuthCubit`);
- **get_it / injectable** — DI через кодогенерацию;
- **dio + JWT-интерсептор** — сеть (см. [ADR-0006](0006-jwt-two-token-secure-storage.md));
- **either_dart + `Failure`** — типизированные ошибки (`Either<Failure,T>`), `fold` в состояние, без try/catch в UI;
- **talker** — логирование (dio + bloc + экран логов на устройстве, т.к. у ТСД нет консоли);
- **slang** — весь UI-текст в `assets/i18n` (i18n), константы UI в `core/constants` (без магических чисел).

Сгенерированные файлы (`*.freezed/*.g/*.gr/*.config.dart`) — в `.gitignore`, генерируются
`build_runner` (в т.ч. обязательно в CI).

## Последствия
- **+** Единообразие, тестируемость (см. `docs/p0-08-1.md`), локализуемость, наблюдаемость на устройстве.
- **−** Кодогенерация — обязательный шаг после клона/правок аннотаций; учтено в CI.
- **−** Больше «церемонии» на мелких экранах — оправдано ростом функционала.
