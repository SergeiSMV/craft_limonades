# ADR-0003 · PostgreSQL + pgx v5 + golang-migrate

**Статус:** Принято

## Контекст
Нужна СУБД для остатков в разрезе ячейка × товар × партия, с транзакционной атомарностью
(приход/расход остатка не должен уходить в минус при конкуренции) и управляемой эволюцией схемы.

## Решение
**PostgreSQL** — транзакции, надёжность, богатый SQL (оконные функции, `uuid`, индексы под запросы
«где и сколько товара»). Драйвер — **pgx v5 / pgxpool** (нативный, быстрый пул, `RowToStructByName`).
Миграции — **golang-migrate/v4** с **встроенными** (`embed`) `.sql`-файлами: схема едет вместе с
бинарём, отдельный раннер `cmd/migrate` (`make migrate-up/down`).

Первичные ключи сущностей — `uuid` (`gen_random_uuid()`): суррогатный, развязан с бизнес-данными
(логин из бейджа можно менять), непредсказуем, генерируется без координации (пригодится для
файлового импорта справочников).

## Последствия
- **+** Атомарность остатков в транзакциях; быстрые запросы по индексам.
- **+** Схема — единый источник (`apps/backend/migrations`), версионируется, применяется одной командой.
- **−** `uuid`-ключи чуть тяжелее `bigint` — для append-only лога (`audit_log`) намеренно взят
  `bigint identity`.
