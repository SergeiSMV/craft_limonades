# ADR-0005 · Авторизация по бейджу (16→8/8) + argon2id + роли

**Статус:** Принято

## Контекст
Кладовщик работает на ТСД и должен входить быстро, без набора логина/пароля на маленьком экране.
У сотрудников есть карты-бейджи. Нужны также разграничение прав (управление пользователями) и защита
от перебора.

## Решение
Вход по **скану бейджа**: 16 цифр → сервер режет на `login` (первые 8) и `secret` (последние 8).
`secret` хранится только как **argon2id**-хеш (PHC-строка с солью и параметрами) — исходный секрет из
БД не восстановить. На `/auth/login` — **rate limiting** (10/мин по реальному IP клиента) против
перебора 8-значного секрета.

Роли: **`employee`** (кладовщик) и **`admin`** (управление пользователями). Роль лежит в JWT и
проверяется middleware без похода в БД. Это ревизия плана v3 (где ролей не было).

## Последствия
- **+** Мгновенный вход одним сканом; секрет не хранится в открытом виде; перебор ограничен.
- **+** Роль в токене → дешёвая авторизация на защищённых роутах.
- **−** 8-значный секрет — умеренная энтропия; компенсируется rate limit и argon2.
- Позже добавляется второй путь входа (логин/пароль для admin со смартфона) — см.
  [ADR-0010](0010-dual-login-by-device.md).
