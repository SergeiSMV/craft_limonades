# P1-10D · Документация: модель данных и форматы файлов импорта

**Статус:** готово (ветка `p1-10d-data-model-docs`).

## Задача

Свести в один документ схему БД (таблицы, ключи, связи, инварианты) и ожидаемые форматы файлов
импорта номенклатуры и ячеек — чтобы модель была понятна без чтения миграций и кода парсеров.

## Критерий

Есть `docs/data-model.md`, описывающий таблицы и форматы импорта.

## Что сделано

- Создан **[`docs/data-model.md`](data-model.md)** — производный от миграций справочный документ:
  - обзор модели (ER-диаграмма mermaid + группировка таблиц по областям и миграциям);
  - общие соглашения (uuid-PK, `timestamptz`, триггер `set_updated_at()`, soft-delete `is_active`,
    `numeric` для веса, разделение бизнес-ключей 1С и внутреннего `id`);
  - все 10 таблиц (`users`, `audit_log`, `warehouses`, `cells`, `nomenclature_groups`, `suppliers`,
    `goods`, `barcodes`, `batches`, `stock`) — колонки, типы, ограничения, ключи, индексы, инварианты;
  - ключевые доменные решения со ссылками на ADR (суррогатный ключ товара, партия=дата, денормализация
    `stock.good_id` + составной FK, отсутствие зон);
  - планируемое изменение схемы по ADR-0016 (внутренний склад — измерение остатка, ещё не в БД);
  - **форматы импорта:** номенклатура `.xls` (колонки, правило группа-vs-товар, линейная иерархия
    одна-ветка-на-файл, ключ апсерта `Код`, хак `demangleCode`, отчёт) и ячейки `.xlsx` (колонки
    `cell`/`floor`, разбор `floor`, склад параметром, апсерт по `(warehouse_id, address)`, отчёт).

## Решения

- **Документ производный, а не первоисточник.** Источник истины по схеме — миграции
  `apps/backend/migrations/*.up.sql`; при изменении схемы `data-model.md` обновляется вместе с
  миграцией. Доменные обоснования не дублируются — ссылки на ADR и задачные `docs/p1-0X.md`.
- **Только модель, без DDL** — точные `CREATE TABLE` остаются в миграциях, документ описывает смысл,
  ключи и инварианты.
- **Форматы импорта зафиксированы по реальным выгрузкам** заказчика (номенклатура — `Кальмары.xls`
  и `testdata/nomenclature_sample.xls`; ячейки — файл 125 ячеек, 25 напольных).

## Проверка

Документация — код не менялся, проверок сборки/тестов нет. Ревью:

```bash
# просмотр документа (mermaid рендерится на GitHub / в совместимом просмотрщике)
sed -n '1,60p' docs/data-model.md
```

Сверка с фактической схемой (по желанию): `apps/backend/migrations/*.up.sql`,
парсеры `apps/backend/internal/importer/{goods,cells}.go`, отчёты
`apps/backend/internal/service/import.go`.

## Границы

- Описана схема на конец P1 (миграции `000001`–`000006`). Будущие таблицы (внутренние склады по
  ADR-0016; документы приёмки/сборки/инвентаризации P4/P9/P10) добавляются своими миграциями и
  дополняют `data-model.md`.
- Формат расходного ордера (P9, открытый вопрос №8) в объём не входит — появится отдельным разделом,
  когда заказчик даст пример файла.

**P1-10D завершает фазу P1.** Дальше по порядку исполнения — фаза **P2** (офлайн-ядро).
