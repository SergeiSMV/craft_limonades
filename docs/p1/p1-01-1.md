# P1-01-1 · Расширение auth на бэкенде (логин/пароль)

**Статус:** ✅ код готов, статический контур зелёный (build/vet/16 сервис-тестов/golangci-lint/gofmt). Runtime E2E (миграция + сид + эндпоинт против БД) — см. «Проверка».
**Задача:** учётки логин/пароль для admin/менеджера (вход со смартфона/web, не по бейджу); эндпоинт `/auth/login/password` наряду с бейджем; обе пары токенов — одной природы.
**Критерий готовности:** admin входит по логину/паролю; работник — по бейджу; оба получают ту же пару токенов.

Решение модели данных — [ADR-0005](../adr/0005-auth-badge-argon2-roles.md) / [ADR-0010](../adr/0010-dual-login-by-device.md).

---

## Что сделано

- **`migrations/000002_users_username.{up,down}.sql`** — отдельный `username`: `login` → nullable; добавлен `username text UNIQUE` (3–64 симв.); CHECK-XOR «ровно одно из (login, username)». Работник — по `login` (8 цифр); admin — по `username`.
- **`internal/model/user.go`** — поле `Username` (nullable → пусто у работника).
- **`internal/repository/user.go`** — `login`/`username` через `COALESCE(...,'')`; `GetByUsername`; `CreateUsernameAdminIfNotExists`.
- **`internal/service/auth.go`** — `GetByUsername` в интерфейсе `userRepo`; метод `LoginWithPassword(username, password)` — тот же поток, что бейдж, без разреза; переиспользует `VerifyPassword`/`issuePair`.
- **`internal/handler/auth.go`** — хендлер `LoginPassword` (`POST /auth/login/password {username,password}`), общий 401 без деталей.
- **`internal/handler/router.go`** — роут `/auth/login/password` в rate-limited группе (10/мин по IP, как `/auth/login`).
- **`cmd/seed/main.go`** — опциональный username-admin из `ADMIN_USERNAME`/`ADMIN_PASSWORD` (min 3/8 симв.); бейдж-admin остаётся.
- **`.env.example`** — `ADMIN_USERNAME` / `ADMIN_PASSWORD`.
- **`internal/service/auth_test.go`** — 6 тестов `LoginWithPassword` (успех, неверный пароль, нет username, заблокирован, пустые, бейдж-работник не входит по паролю-пути).

### Ключевые решения

- **Отдельный `username`** — чётко разделяет бейдж-идентичность и username; сохраняет CHECK «login = 8 цифр» для работников. XOR-констрейнт гарантирует «либо бейдж, либо username».
- **Отдельный эндпоинт** `/auth/login/password` — не ломает бейдж-контракт `/auth/login` и его тесты; оба под одним rate-limit.
- **Nullable-скан:** `login`/`username` читаем через `COALESCE(...,'')` → в модели остаются `string` (пусто = отсутствует), без указателей и правок существующего кода.
- **Пароль-политика — минимум** (username ≥ 3, пароль ≥ 8 при сидинге). Полная политика (сложность, сброс, кто заводит) — открытый вопрос №8, реализуется с админ-управлением пользователями.
- **Единая природа токенов:** оба пути идут через `issuePair` → одинаковые access/refresh; middleware и `/auth/refresh` не различают источник входа.

## Границы задачи

- **Только бэкенд.** Выбор пути входа по устройству/роли (детект ТСД vs смартфон/web, ветвление экрана) — **P2-01** ([ADR-0010](../adr/0010-dual-login-by-device.md)). До него `/auth/login/password` доступен по API; UI-путь появится в P2-01.
- **Заведение учёток admin** — пока сидером из env; полноценное админ-управление пользователями — отдельная задача.

## Проверка

Два уровня — они проверяют **РАЗНОЕ**, оба нужны:

- **Статический контур** (`go test`) — гоняет бизнес-логику сервиса на **fake-репозитории в памяти, БЕЗ базы данных**. Проверяет правила входа (успех/ошибки, argon2, активность), но **НЕ** затрагивает миграцию `000002` и реальный HTTP-эндпоинт — там нет ни Postgres, ни роутера.
- **Runtime E2E** — реальная миграция + `POST /auth/login/password` против **живого Postgres** через поднятый стек. **Только он** подтверждает, что схема применяется, констрейнты верны и эндпоинт отдаёт токены.

Т.е. зелёный `go test` — необходимое, но **не достаточное**: миграцию и эндпоинт закрывает именно Runtime E2E.

### 1. Статический контур (без стенда)
```bash
cd apps/backend
go build ./... && go vet ./... && go test ./internal/...   # ok auth, ok service (16)

# golangci-lint не в PATH по умолчанию (ставится в ~/go/bin) — вызываем по полному пути.
# Подробнее (установка, добавление в PATH) — docs/p0-08-1.md. Линт не обязателен: его гоняет CI.
"$(go env GOPATH)/bin/golangci-lint" run ./...             # 0 issues

# (cached) в выводе теста — норма: Go переиспользует кеш, если код/тесты не менялись;
# форс-прогон: go test -count=1 ./internal/...
```

### 2. Runtime E2E (миграция + сид + эндпоинт)
```bash
# из корня проекта; пересборка бэкенда обязательна — роут новый
colima start && make up && make migrate-up

# сид username-admin (без правки .env — переменные разово):
ADMIN_USERNAME=admin ADMIN_PASSWORD=supersecret123 make seed

# вход по логину/паролю → пара токенов:
curl -s -X POST http://localhost:8080/auth/login/password \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"supersecret123"}'      # {"access":"…","refresh":"…"}

# регрессия: вход по бейджу по-прежнему работает:
curl -s -X POST http://localhost:8080/auth/login \
  -H 'Content-Type: application/json' -d '{"badge":"1000000012345678"}'

# негатив: неверный пароль → 401
curl -s -o /dev/null -w "%{http_code}\n" -X POST http://localhost:8080/auth/login/password \
  -H 'Content-Type: application/json' -d '{"username":"admin","password":"wrong"}'

make down && colima stop   # остановка
```
Ожидаемо: оба логина отдают `{access, refresh}`; неверный пароль — `401`.

> ⚠️ Миграция `000002` безопасна для существующих данных: у текущего бейдж-админа `login` задан,
> `username` = NULL → XOR-констрейнт проходит, `ADD CONSTRAINT` не падает.
