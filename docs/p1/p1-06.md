# P1-06 · API чтения справочников (товары, ячейки, остатки)

**Статус:** ✅ код готов, весь контур зелёный (build/vet, gofmt, golangci-lint 0 issues, integration на реальных данных, сквозной E2E через стек).
**Задача:** read-API поверх справочников — список/поиск/фильтры/пагинация по товарам, группам, поставщикам, ячейкам и остаткам; на этом строятся экраны ТСД (P1-07).
**Критерий готовности:** данные отдаются клиенту; поиск и фильтры работают; пагинация корректна.

---

## Объём (решения по задаче)

- **Только чтение** (GET). Справочники наполняются импортом (P1-04/05); ручное создание/правка/удаление на пилоте не нужно и рискует рассинхроном с 1С — если понадобится, отдельной задачей.
- **Измерение внутреннего склада на `stock` — отложено в P4** ([ADR-0016](../adr/0016-internal-warehouse-as-stock-dimension.md)): P1-06 читает текущую грань остатка `(cell, good, batch, qty)`. Когда приёмка P4 введёт брак, добавится `internal_warehouse_id` и колонка/фильтр в этом же API (расширение, не ломающее список).

## Эндпоинты (все под `/api/v1`, требуют аутентификации — любой сотрудник)

| Метод | Путь                   | Параметры                                                                | Ответ                  |
|-------|------------------------|--------------------------------------------------------------------------|------------------------|
| GET   | `/goods`               | `q` (имя/код), `group_id`, `supplier_id`, `limit`, `offset`              | `Page<Good>`           |
| GET   | `/goods/{id}`          | —                                                                        | `Good` (404 если нет)  |
| GET   | `/nomenclature-groups` | —                                                                        | `[]Group` (всё дерево) |
| GET   | `/suppliers`           | `q`                                                                      | `[]Supplier`           |
| GET   | `/cells`               | `q` (адрес), `warehouse_id`, `is_floor`, `limit`, `offset`               | `Page<Cell>`           |
| GET   | `/stock`               | `good_id` (где лежит товар), `cell_id` (что в ячейке), `limit`, `offset` | `Page<StockItem>`      |

- **`Page<T>`** = `{ items: [...], total, limit, offset }`. `items` — всегда `[]` (не `null`) при пустом результате.
- **Пагинация**: `limit` дефолт 50, потолок 200 (защита от «выгрузи всё»); `offset ≥ 0`. Приведение границ — в сервисе.
- **`total`** — общее число под фильтр (окно `COUNT(*) OVER()` в том же запросе, без второй поездки в БД).
- **`group_id` — фильтр по ПОДДЕРЕВУ** (рекурсивный CTE): товар привязан к самой глубокой группе пути (листу), поэтому выбор родительской группы («Матрица …», «-Товары/…») возвращает товары всех её подгрупп, а не пусто.

## Что сделано

- **`internal/model/catalog.go`** — read-DTO `Good` (с присоединёнными `group_name`/`supplier_name`), `NomenclatureGroup`, `Supplier`, `Cell`, `StockItem` (адрес ячейки + дата партии + `qty` decimal). JSON-теги snake_case.
- **`internal/repository/catalog_read.go`** — методы `List`/`GetByID` на существующих репозиториях (goods/groups/suppliers/cells/stock): фильтры через `($n IS NULL OR ...)`, `ILIKE '%q%'` для поиска, `COUNT(*) OVER()` для total, пустой результат → непустой слайс. `ErrNotFound` для точечного чтения. `qty::text` → `decimal` без потерь.
- **`internal/service/catalog.go`** — `CatalogService` (зависимости — интерфейсы read-репозиториев), дженерик `Page[T]`, `clampPaging` (limit/offset к безопасным границам), методы `ListGoods`/`GetGood`/`ListGroups`/`ListSuppliers`/`ListCells`/`ListStock`.
- **`internal/handler/catalog.go`** — `CatalogHandler`, GET-обработчики + разбор query (`optStr`/`optBool`/`paging`); 404 на `ErrNotFound`, 500 на внутренних ошибках чтения.
- **`internal/handler/router.go`** — группа под `Authenticator(tokens)` **без** `RequireRole` (чтение доступно сотруднику, не только admin; импорт остаётся admin-only). Wiring в `cmd/server/main.go` — общие репозитории переиспользуются импортом (запись) и каталогом (чтение).

### Ключевые решения

- **Доступ — аутентифицированный сотрудник, не admin.** Эти данные кормят экраны ТСД (P1-07), а не админку. Импорт (запись) остался admin-only.
- **Присоединённые имена группы/поставщика в `Good`** (LEFT JOIN) — чтобы карточка товара не делала N доп-запросов за именами.
- **`total` окном `COUNT(*) OVER()`** — одна поездка в БД вместо «список + отдельный count».
- **Группы и поставщики — без пагинации** (справочники маленькие): отдаём целиком, клиент строит дерево групп сам.
- **`stock` читается по текущей грани** (без внутреннего склада) — сознательно, ADR-0016; API расширяемо под P4.
