# P1-05 · Импорт ячеек склада из файла (.xlsx)

**Статус:** ✅ код готов, весь контур зелёный (build/vet, gofmt, golangci-lint 0 issues, юнит + integration на реальном файле, сквозной E2E через стек).
**Задача:** импорт справочника **физических ячеек** одного склада из `.xlsx`: парсер (адрес + признак напольной), upsert по `(warehouse_id, address)` — повторный импорт не плодит дубли; проблемные строки видны в отчёте.
**Критерий готовности:** повторный импорт того же файла идемпотентен; заводятся ячейки, привязанные к физическому складу, с корректным признаком `is_floor`.

---

## Формат файла (разобрано на реальном файле заказчика)

`.xlsx` (Excel), первый лист, **строка заголовка** + строки-ячейки. Колонки:

| `cell`     | `floor` |
|------------|---------|
| `M1-1-1-1` | `true`  |
| `M1-1-2-1` | `false` |

- **`cell`** — адрес ячейки латиницей (напр. `M1-1-2-1`); **ключ апсерта** вместе со складом. Хранится **как есть** (opaque text) — разбор на стеллаж/секцию/полку и «стрелка вниз» для напольных пойдут позже, на генерации PDF-ШК (P4). В реальном файле — 125 адресов, все уникальны, префикс `M1`.
- **`floor`** — напольная ячейка (нижний ярус): `true/false` (принимаются также `1/0`, `да/нет`, пусто = `false`). В реальном файле — 25 `true` / 100 `false`.
- **Склад в файле не задан** — приходит **параметром импорта** (см. ниже), т.к. на пилоте склад один.

## Модель: физический склад vs внутренний (ADR-0016)

Заказчик уточнил: **одна физическая ячейка может держать товар «основного» склада и товар «брака»
одновременно.** Значит «внутренний склад» (основной/брак/…) — это **измерение остатка**, а не свойство
ячейки. Поэтому:

- **Физический склад** («Шабулина») = таблица `warehouses`; ему принадлежат `cells` (ключ `(warehouse_id, address)`).
- **Внутренний склад** — измерение `stock`, заводится **позже** (P1-06/P4), в P1-05 не участвует.

Подробно и с последствиями для `stock` — [ADR-0016](../adr/0016-internal-warehouse-as-stock-dimension.md).

## Что сделано

- **`migrations/000006_cells_is_floor.up.sql`:** `ALTER TABLE cells ADD COLUMN is_floor boolean NOT NULL DEFAULT false;` (из колонки `floor`). Схема складов/ячеек не меняется — двухуровневая модель складов на ячейке **отвергнута** (ADR-0016).
- **`internal/importer/cells.go`** — парсер `.xlsx` (`github.com/xuri/excelize/v2`): колонки маппятся **по заголовку** (устойчиво к порядку), `floor` разбирается терпимо (`parseBool`: true/false/1/0/да/нет/пусто), нераспознанное значение — в `Errors` (не тихо `false`). Результат `CellsParseResult{Cells, Errors}`.
- **`internal/repository/warehouse.go`** — `WarehouseRepository.Upsert` (по `code`, через `Querier`).
- **`internal/repository/cells.go`** — `CellRepository.Upsert` (`ON CONFLICT (warehouse_id, address)`, `created` через идиому `xmax = 0`, при повторе обновляет `is_floor`).
- **`internal/service/import.go`** — `ImportService.ImportCells(r, warehouseCode, warehouseName)`: парсинг → апсерт склада → апсерт ячеек **в одной транзакции**; отчёт `CellsImportReport{Warehouse, CellsCreated, CellsUpdated, Skipped}`. Конструктор сервиса расширен репозиториями склада/ячеек.
- **`internal/handler/import.go`** + роут — `POST /import/cells` (multipart, поле `file`; необязательные `warehouse_code`/`warehouse_name`; **admin-only**). Лимит загрузки 32 МиБ.
- **testdata:** реальный файл заказчика скопирован в `internal/importer/testdata/cells_sample.xlsx`.

### Ключевые решения

- **`.xlsx` читаем через `excelize/v2`** (у номенклатуры P1-04 был `.xls` → `extrame/xls`; это другой формат — новый парсер, а не переиспользование). Моно-Go, без внешних конвертеров.
- **Ключ ячейки — `(warehouse_id, address)`** (существующий `UNIQUE` из P1-01). «Внутренний склад» в ключ ячейки **не входит** — он на остатке (ADR-0016). Адрес — уникален в рамках склада: один и тот же адрес в разных складах — разные ячейки (проверено: WH2 получил свои 125).
- **Склад — параметр импорта** с пилотными дефолтами `SHB`/«Шабулина» (переопределяются полями формы). ⚠ **Код склада `SHB` — плейсхолдер, согласовать с заказчиком** (короткий идентификатор для отчётов/адресации).
- **Транзакция «всё-или-ничего»** для валидных строк; невалидные (без адреса / нераспознанный `floor`) — в `Skipped`, импорт не валят.

## Границы задачи

- **Только физические ячейки.** Справочник внутренних складов + измерение `internal_warehouse_id` на `stock` — отдельно (P1-06/P4, [ADR-0016](../adr/0016-internal-warehouse-as-stock-dimension.md)).
- Чтение/поиск/пагинация ячеек (API) — **P1-06**. Flutter/портал-кнопка импорта ячеек — позже (портал: отдельная вкладка; сейчас на портале рабочая только Номенклатура).
- Разбор адреса на компоненты и генерация PDF-ШК со стрелкой для напольных — **P4** (признак `is_floor` уже заведён).
