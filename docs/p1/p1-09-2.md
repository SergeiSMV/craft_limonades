# P1-09-2 · CI для Flutter Web: гейт сборки портала + артефакт-бандл

**Статус:** ✅ готово. `actionlint` чист; web-сборка портала проверена локально на Flutter 3.41.2 (совпадает с пином в CI) — `build/web/index.html` собирается.
**Задача:** добавить в CI сборку веб-портала (Flutter Web, точка входа `lib/main_portal.dart`), чтобы компиляция портала стала гейтом перед мержем, а готовый web-бандл публиковался артефактом прогона.
**Критерий готовности:** ломающая web-компиляцию портала правка красит workflow; чистая сборка — зелёная; web-бандл доступен как артефакт (задел под воспроизводимый деплой P1-09-3).

---

## Зачем

Портал (P1-09-1) собирается той же кодовой базой, что и ТСД-приложение, но с другой точкой входа
(`lib/main_portal.dart`). До этой задачи CI собирал только APK — правка, ломающая именно
web-компиляцию (недоступный на web плагин, ошибка в `lib/portal/**`), проходила бы незамеченной до
ручной пересборки при деплое. Теперь web — часть гейта. Артефакт-бандл — задел под воспроизводимый
деплой портала (P1-09-3): деплой сможет брать готовый бандл из прогона, а не пересобирать вручную.

## Что сделано

- **`.github/workflows/ci-flutter.yml`** — в существующий джоб `flutter` (после сборки/загрузки APK)
  добавлены три шага:
  - `Prepare .env (CI stub for web build)` — `cp .env.example .env`. Реальный `.env` в `.gitignore`
    (свой на каждой машине), в CI подставляется заглушка из шаблона: так честно проходим путь
    `--dart-define-from-file` и ловим ошибки чтения конфига, не завися от секретов.
  - `Build web (portal)` — `flutter build web -t lib/main_portal.dart --dart-define-from-file=.env --release`.
  - `Upload portal web bundle artifact` — `build/web` как артефакт `portal-web-bundle` (`if-no-files-found: error`).
- Джоб переименован `Flutter (Android)` → `Flutter (Android + Web портал)`; шапка workflow обновлена.

### Ключевые решения

- **Web собирается в ТОМ ЖЕ джобе, что и APK, а не отдельным.** Причина — экономия минут Actions на
  free-тарифе: переиспользуются `checkout` / `setup-flutter` / `pub get` / codegen (отдельный джоб
  продублировал бы весь этот setup). Плюс держим один required-чек — на Pro отдельные джобы по
  path-фильтру рискуют «зависать» как required (известная заметка по этому workflow).
- **`.env` из шаблона, а не хардкод `--dart-define`.** `BASE_URL` в `AppConfig` имеет `defaultValue`,
  и формально сборка прошла бы и без `.env`. Но прод-сборка портала всегда идёт через внешний `.env`
  (`--dart-define-from-file`), поэтому CI воспроизводит именно этот путь — иначе гейт не поймал бы
  поломку самого механизма чтения конфига.
- **Гейт — красный весь `flutter`-джоб.** Отдельного «web-only» статуса нет: провал web-сборки валит
  джоб целиком, чего достаточно для блокировки мержа.

## Границы задачи

- **Воспроизводимый деплой портала — отдельная задача P1-09-3.** Здесь только гейт + артефакт;
  раскладка бандла на прод (`infra/nginx/craft-wms.conf.template` под split, `deploy/`-скрипты кладут
  бандл в `/opt/craft-wms/portal`, в идеале — из этого артефакта) остаётся ручной.
- **APK по-прежнему `--debug` без `.env`** (компайл-гейт ТСД) — не меняли, вне объёма задачи.

## Проверка

```bash
# Линт workflow (на прод/CI-машине — actionlint):
actionlint .github/workflows/ci-flutter.yml            # без ошибок

# Локальная эквивалентность CI-шага (Flutter 3.41.2, как пин в CI):
cd apps/craft_wms
cp .env.example .env   # ⚠ если есть реальный .env — не перезаписывать; собирать с ним
flutter pub get
dart run build_runner build --delete-conflicting-outputs
flutter build web -t lib/main_portal.dart --dart-define-from-file=.env --release
ls build/web/index.html                                 # бандл собран
```

Проверено локально (2026-08-04): `actionlint` — чисто; `flutter build web -t lib/main_portal.dart
--dart-define-from-file=.env --release` на Flutter 3.41.2 — успешно, `build/web/index.html` создан.
Финальная проверка гейта — по прогону workflow на PR (push этой ветки).
