## Задача

Цикл заказа сборки через API для ТСД: список доступных заказов, взятие в работу с закреплением
за исполнителем, заказ с подсказкой источников (P9-03), короба отгрузки, недобор по строке, не
роняющий заказ. Правила - [`../picking.md`](../picking.md).

## Критерий готовности

Заказ проходит через API цикл «список → взять → короба → отметка «не хватает» → отказаться», с
пересчётом позиции по нехватке.

## API

Все ручки - под правом `tsd.picking`, только со связью.

| Ручка                                              | Ответ                                       |
|----------------------------------------------------|---------------------------------------------|
| `GET /picking/orders`                              | список «СБОРКА»                             |
| `GET /picking/orders/{id}`                         | заказ с подбором по строкам и коробами      |
| `POST /picking/orders/{id}/take`                   | 204; 409 - занят, удалён, нераспознан, собран |
| `POST /picking/orders/{id}/release`                | 204; 409 - заказ у другого                  |
| `POST /picking/orders/{id}/boxes`                  | `{load_unit_id, seq}`; 409 - ярлык занят    |
| `POST /picking/orders/{id}/lines/{lineId}/shortage` | `{stocktake_number, stocktake_created}`    |

Отказы по состоянию заказа - 409 с текстом по-русски, ТСД показывает его как есть («заказ удалён
в 1С», «заказ уже взял другой сотрудник», «заказ не у вас в работе: возьмите его заново»).

## Ключевые решения

### Список - все несобранные заказы любой даты

Кладовщику важно, что ещё не собрано, а не дата (`picking.md`, «Сборка на ТСД»). Удалённые в 1С
в список не попадают. Заказ в работе у другого виден занятым (`busy`, кто держит), зависший -
свободным. Порядок - дата накладной, затем номер сборки: сначала то, что отгружать раньше.

### Взятие - как у заданий склада

Строка заказа блокируется на время взятия: двое, одновременно взявшие заказ, не запишут оба
своё взятие. Повтор своим исполнителем - не ошибка; заказ без движения 8 ч берёт другой
кладовщик, собранное остаётся в коробах. Не берутся удалённый в 1С, с нераспознанными
позициями, собранный и отгруженный. Отказ возвращает заказ в «новый» без исполнителя.

Любое действие по заказу (короб, «не хватает») проверяет, что заказ в работе именно у этого
кладовщика, и продлевает его от зависания. Удалённый реестром во время сборки заказ отвечает
«заказ удалён в 1С» - так ТСД узнаёт об удалении.

### Короб отгрузки

UUID ярлыка выдаёт ТСД, как у коробов приёмки: ярлык печатается до ответа сервера. Сервер
заводит грузовую единицу без места (товар ляжет в неё при «Завершить сборку», P9-07) и номер
«короб N» - следующий за последним в заказе; блокировка заказа держит номер единственным. Повтор с
тем же ярлыком отдаёт уже выданный номер: ответ мог не дойти. Ярлык другого короба - отказ.
«N из M» на ярлыке считается при печати, когда коробов уже не прибавится.

### «Не хватает» и пересчёт позиции

Отметка по строке ставится и снимается. Поставленная - заводит пересчёт в той же транзакции:
область - товар строки (ячейки, где WMS его числит), плюс ячейка реестра, даже если там товара
по учёту нет; основание - заказ сборки (`stocktakes.picking_order_id`), задание - в общем пуле.
Открытый пересчёт по нехватке того же товара второй не заводит - ответ отдаёт его номер.
Advisory-блокировка по товару держит это правило и при двух одновременных отметках.

Если товара нет ни в одной ячейке и ячейки реестра нет в WMS, отметка ставится без пересчёта:
пустой пересчёт ничего не посчитает, а отказ откатил бы саму отметку. Снятие отметки пересчёт
не отменяет - он уже в пуле, и посчитать товар не вредно.
