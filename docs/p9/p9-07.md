# P9-07 · «Завершить сборку», ярлыки «короб N из M», отгрузка, журнал заказа

**Статус:** ✅ готово (`flutter analyze` чист, `flutter test` зелёный; бэкенд: gofmt и
`golangci-lint` чисты, `go test ./...` зелёный, миграция 49 проверена up → down → up).
**Категория:** плановая, фаза P9.

## Задача

Закрыть сборку заказа на ТСД. Кнопка «Завершить сборку» переносит взятое из ячеек в короба
отгрузки, а короба ставит в служебную ячейку `ОТГРУЗКА`. На каждый короб печатается ярлык
«короб N из M». Отгрузка - сканом ярлыков всех коробов заказа. Попутно заведён журнал событий
заказа: кто взял, отказался, снят, завершил, отгрузил. Он нужен будущим отчётам (топ работников,
топ отгрузок). Правила - [`../picking.md`](../picking.md).

## Критерий готовности

Кладовщик собрал заказ и нажал «Завершить сборку». После этого:

- товар списан из ячеек и лежит в коробах в `ОТГРУЗКЕ`;
- ярлыки напечатаны;
- после скана всех коробов заказ «отгружен», а товар и марки ушли со склада;
- в портале у заказа видна история.

## Ключевые решения

### API ТСД (право `tsd.picking`)

| Маршрут                                        | Что делает                                                    |
|------------------------------------------------|---------------------------------------------------------------|
| `POST /picking/orders/{id}/complete`           | «Завершить сборку» - только исполнитель; ответ - заказ к отгрузке |
| `GET /picking/orders/{id}/shipment`            | собранный заказ: шапка и короба (номер, печатался ли, отгружен) |
| `POST /picking/orders/{id}/labels {box_ids}`   | отметить печать ярлыков; повтор - по праву `tsd.picking.reprint` (иначе 403) |
| `POST /picking/orders/{id}/ship {box_ids}`     | «Отгрузить»: набор должен совпасть со всеми коробами заказа    |

В списке `GET /picking/orders` есть собранные заказы (`picked`) с `is_partial` и числом коробов.

### «Завершить сборку» - одной транзакцией

1. **Проверка строк.** Отказ (409) с перечнем строк, если по строке:
   - «в сборке» больше плана - лишнее вернуть пиком;
   - взято меньше плана без отметки «не хватает».

   Неполный заказ (есть «не хватает») - собран частично (`is_partial`).
2. **Короба.** Пустой короб (без пиков) убирается: ставится `dropped_at`, удалить нельзя - на него
   ссылаются возвращённые пики. Живые короба нумеруются заново 1..M. Если номера сдвинулись или
   M изменилось с прошлого завершения, отметка печати сбрасывается: старый ярлык «N из M»
   неверен. Ни одного короба с товаром - отказ.
3. **Перенос.** Каждый открытый пик:
   - становится `moved`;
   - товар списывается из ячейки-источника (из короба хранения - из его содержимого) в `ОТГРУЗКУ`
     с тем же внутренним складом;
   - попадает в содержимое короба отгрузки;
   - марки маркируемого переходят в короб.

   Пик ставится `moved` до списания: `takeFromLoadUnit` вычитает открытые пики, свой пик
   иначе мешал бы сам себе. Марки двигаются прямой правкой: `moveMarks` не пускает марки
   открытого пика. Не хватило остатка - 409 «товара в источнике меньше, чем в сборке».
4. **Ячейка `ОТГРУЗКА`.** Короба ставятся в неё журналом размещений с источником `picking`.
   Ячейка заводится сама (`EnsureShipping`), если на складе её ещё нет.
5. **Заказ.** Заказ становится «собран»: исполнитель снят, `picked_by/at` заполнены. В журнал
   пишется событие `completed` с числом коробов и штук.

Перед «Завершить» ТСД отправляет свою очередь пиков. Если отправить не вышло - «нужна связь»:
сервер должен видеть все пики. После успеха слепок заказа на терминале удаляется.

### Ярлык «короб N из M»

Рулон 58×40. Слева сверху - QR короба в формате ГЕ (`CWLU1:<uuid>`): его сканируют на отгрузке.
Справа от QR:

- номер сборки «СБ-…» крупно;
- накладная, заказ и дата - каждый факт своей строкой с подписью;
- «Короб N из M» крупно.

Под QR во всю ширину - клиент, направление и адрес с переносом, не больше 4 строк. Вес не
печатается (долг 36).

Печать идёт через сервер: сначала сервер отмечает `labels_printed`, потом печатает принтер ТСД.
Так сервер знает, печатался ли ярлык. Повтор разрешён только по праву, иначе испорченный ярлык
перепечатывает старший смены.

Экран печатает ярлыки сам сразу после «Завершить». Кнопка «Напечатать ярлыки» печатает ещё не
печатавшиеся, а если все напечатаны - все повторно. Касание короба - ярлык только этого короба.

### Отгрузка - сканом всех коробов

Скан ярлыка отмечает свой короб. Чужой или повторный скан - подсказка. Когда отмечены все,
ТСД сам отправляет «Отгрузить» (нужна связь). Сервер в одной транзакции:

- списывает остаток из `ОТГРУЗКИ` по перенесённым пикам;
- обнуляет содержимое коробов;
- ставит марки ЧЗ «отгружены» без места;
- коробам - «отгружен» без ячейки;
- заказу - «отгружен»;
- пишет событие `shipped`.

Уже отгруженный заказ - успех без действий: повтор после пропажи связи не ломается.

Остаток в `ОТГРУЗКЕ` хранится по внутреннему складу пика. У короба отгрузки внутренний склад
остаётся по умолчанию, поэтому отгрузка списывает по пикам, а не по коробу.

### Журнал заказа `picking_order_events`

| Событие            | Когда                                           | Кто / с кого                        |
|--------------------|--------------------------------------------------|-------------------------------------|
| `taken`            | взял свободный заказ                             | исполнитель                         |
| `taken_over`       | перехватил зависший (8 ч)                        | новый, `prev` - прежний             |
| `released`         | отказался                                        | исполнитель                         |
| `released_by_lead` | снят из портала                                  | старший смены, `prev` - снятый      |
| `completed`        | «Завершить сборку» (короба, штуки)               | исполнитель                         |
| `reopened`         | реестр изменил собранный заказ                   | кто загрузил, `prev` - кто собирал  |
| `shipped`          | отгружен (короба, штуки)                         | кто сканировал                      |

Событие пишется в той же транзакции, что и действие. В окне заказа портала - блок «История».
Индекс `(user_id, at)` - под отчёты по работникам.
