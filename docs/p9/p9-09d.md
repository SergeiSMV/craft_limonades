# P9-09D · Сценарные тесты сборки и документация процесса

**Статус:** ✅ готово (`go test ./...` и `golangci-lint` чисты). Код приложения не менялся,
миграций нет. Flutter не затронут.
**Категория:** плановая, фаза P9, завершающая задача фазы.
**Процесс:** [`picking.md`](../picking.md).

## Задача

Проверить сборку и отгрузку целиком по живой базе - так, как её проходят офис и склад. Отдельные
шаги и отказы покрыты тестами P9-01…P9-08, но не их стык: реестр → подбор → пик → завершение →
отгрузка → сверка с 1С. Дописать `docs/picking.md` до полного процесса.

## Критерий готовности

- Сценарий полной сборки: от загрузки реестра до отгрузки, товар ушёл со склада, портал видит
  отгруженный заказ, сходящийся с 1С.
- Сценарий частичной сборки: «не хватает», пересчёт позиции, «собран частично», «Расходится с 1С»,
  сверка повторной загрузкой реестра, причины правок.
- Сценарий двух сборок на один остаток: без резерва второй кладовщик получает нехватку и отказ пика.
- В `docs/picking.md` - сквозная цепочка процесса со ссылкой на сценарии.

## Ключевые решения

### Уровень сервисов, а не HTTP

Сценарии собирают сервисы так, как их собирает `main`: `PickingLoadService`,
`PickingTaskService`, `PickingPortalService`. Пик идёт операцией очереди `picking_pick`
(`OperationsRepository.PickingPick`) - тем же путём, что пик с ТСД. Права и коды ответов уже
проверены HTTP-тестами задач, здесь - бизнес-итог: остатки ячеек, `ОТГРУЗКА`, статусы, журнал,
сверка.

Реестр - настоящий `.xlsx` (`registryFile`), загрузка идёт через разбор файла, сопоставление
кода `00000016147` с номенклатурой `16147` и подбор.

### Сценарии

- **`TestPickingScenario_full`.** Остаток двумя партиями в двух ячейках. Подбор FEFO: 4 из B-1
  (01.09), затем 2 из A-1. До «Завершить сборку» остатки ячеек не меняются, после - товар в
  `ОТГРУЗКЕ`, после отгрузки `ОТГРУЗКА` пуста. Портал: отгружен, сходится с 1С, собрала Анна,
  факт 6. Журнал: `taken:Анна, completed:Анна, shipped:Борис`. Повтор того же файла - без правок.
- **`TestPickingScenario_shortage`.** Менеджер уменьшил заказ 6 → 5 до сборки. На складе 3:
  подбор показывает нехватку 2, «Завершить» без «не хватает» - отказ с перечнем строк, с
  отметкой - пересчёт позиции. Отгружен частично и расходится с 1С. Реестр с планом 3 -
  «Сверен с 1С», причины правок: «изменение заказа», «приведено к факту». Заданий возврата нет.
- **`TestPickingScenario_competition`.** Два заказа по 5 на остаток 5. Анна собрала всё в свой
  заказ. Борису подбор показывает нехватку 5 без источников, пик из той же ячейки -
  `ErrPickingStockShort`. Анна отгрузила, Борис отметил «не хватает» и закрыл заказ пустой
  отгрузкой - заказ расходится с 1С.
