# Развёртывание Craft WMS

Два контура, две инструкции: на своей машине разработчик поднимает стек и собирает клиентов,
на боевом сервере — ставит, обновляет и восстанавливает из бэкапа. Команды у них разные,
поэтому и документы разные.

| Документ                         | О чём                                                                  |
|----------------------------------|------------------------------------------------------------------------|
| [dev-deploy.md](dev-deploy.md)   | Локальная машина: стек, `.env`, миграции, сборка APK и портала         |
| [prod-deploy.md](prod-deploy.md) | Боевой сервер: установка, TLS, авто-обновление, бэкапы, восстановление |
| [tsd-setup.md](tsd-setup.md)     | Ввод нового ТСД: установка приложения, первый вход, принтер           |

## Единая точка входа на сервере

```bash
sudo bash deploy/craft.sh
```

Панель управления: установка на чистой машине, обновление, состояние, логи, бэкапы
и восстановление — всё из одного меню. Подробности — в [prod-deploy.md](prod-deploy.md).

## Разница dev / prod

Локальный стек ([dev-deploy.md](dev-deploy.md)) поднимает и **контейнерный** nginx (`make up`).
На проде reverse-proxy и TLS делает **хостовый** nginx сервера, а `docker-compose.prod.yml`
содержит только `postgres` и `backend`, причём backend слушает loopback. Это осознанная разница —
см. [ADR-0011](../adr/0011-pilot-deploy-host-nginx-ghcr.md).

⚠ **Никогда на проде:** `migrate down` и `docker compose down -v` — сотрут данные.
Схема двигается только вперёд.
