# P1-07 · Flutter ТСД: главное меню + просмотр остатков

**Статус:** ✅ код готов, контур зелёный (`flutter analyze` 0 issues, кодогенерация ок, 28 тестов, debug-APK собран). Визуальная проверка на устройстве (DT50/Zebra) — за пользователем.
**Задача:** заменить экран-заглушку главным меню ТСД (по макету) и сделать рабочий раздел «Остатки»: список товаров с поиском/фильтрами → карточка остатков товара.
**Критерий готовности:** сотрудник видит меню; из «Остатков» ищет товар (поиск + фильтры) и открывает карточку с размещением, количеством по местам, партиями и общим итогом.

---

## Объём (по уточнению заказчика + макету)

Главное меню — 6 плиток (2×N): **приход, перемещение, задания, найти, история** — неактивные **заглушки** (тап → уведомление «Раздел в разработке»); **остатки** — рабочая.

- **«Справочники»/«Номенклатура» как отдельных пунктов нет** — список товаров вложен в «Остатки».
- **«Найти»** (скан ШК → карточка товара) — заглушка: штрихкоды ещё не привязаны к товарам.
- **Разбивка по ГЕ (грузовым единицам)** — позже (P4/P5); сейчас остаток показывается «россыпью».

## Экраны

- **Главное меню** (`features/home`): шапка (ФИО + логин слева, склад справа, меню логи/выход) + сетка плиток. Склад — из `AppConfig.warehouseName` (dart-define `WAREHOUSE_NAME`, дефолт «Шабулина»). Рабочая плитка «Остатки» → список товаров.
- **Остатки — список товаров** (`features/stock/.../goods_list_screen`): поиск по имени/коду (дебаунс 350 мс) + фильтры **группа** и **поставщик** (выпадающие, из `GET /nomenclature-groups` и `GET /suppliers`); список → `GET /goods` (пагинация). Тап по товару → карточка.
- **Карточка остатков** (`stock_detail_screen`): шапка товара (наименование/код/ед./группа/поставщик) + строки «ячейка · партия · кол-во» (`GET /stock?good_id=`) + **общий итог**.

## Что сделано

- **`features/stock/data/catalog_models.dart`** — freezed-модели `Good`/`NomenclatureGroup`/`Supplier`/`StockItem` (маппинг snake_case) + обобщённая `Paged<T>` (ручной разбор `{items,total,limit,offset}`, т.к. freezed/json не дружит с дженериком). `qty` — строка (точный decimal с бэкенда, без потери знаков).
- **`features/stock/data/catalog_repository.dart`** — `@lazySingleton`, dio → `/goods`, `/nomenclature-groups`, `/suppliers`, `/stock`; пустые фильтры не уходят в URL; ошибки → `Either<Failure,T>` (401→auth, код→server, иначе network).
- **`features/stock/presentation/`** — `GoodsListCubit` (`@injectable`, держит справочники фильтров + перезагружает список; одноклассовый стейт со статусом) и `StockDetailCubit` (грузит остатки товара + считает итог); экраны `GoodsListScreen`/`StockDetailScreen` (поиск с дебаунсом, фильтры-дропдауны, состояния загрузка/ошибка-повтор/пусто).
- **`features/home/presentation/home_screen.dart`** — переписан из заглушки в главное меню; виджет плитки `widgets/menu_tile.dart`.
- **Маршруты** (`core/router/app_router.dart`): `GoodsListRoute`, `StockDetailRoute(good)` под `AuthGuard`. **`ApiConst`** +маршруты чтения. **`AppConfig.warehouseName`** (dart-define). i18n-ключи (slang) для меню и экранов остатков. Цвета плиток и размеры — в `AppColors`/`AppSizes` (без магических чисел).

### Ключевые решения

- **Список товаров вложен в «Остатки»** (нет отдельного раздела «Номенклатура») — по уточнению заказчика.
- **Склад в шапке — из константы/`.env`** (`WAREHOUSE_NAME`, дефолт «Шабулина»). ⚠ Плейсхолдер: при мультискладе/привязке устройства склад должен приходить из профиля, а не из клиента.
- **`qty` — строка** (не double): бэкенд отдаёт decimal строкой, храним точно; общий итог для показа считаем в double (кол-ва ≤ numeric(20,3), точности хватает), формат без хвостовых нулей.
- **Поиск с дебаунсом 350 мс** — не дёргаем API на каждый символ.
- **Заглушки — активные на вид плитки** (тап → SnackBar), а не скрытые/выключенные: по требованию «именно неактивные заглушки, а не убрать».

### Запуск (полный цикл)

Экранам нужен живой бэкенд с наполненными справочниками. Из корня репозитория:

```bash
# 1. Поднять зависимости и наполнить данные
colima start
make up && make migrate-up && make seed          # стек + схема + админ (бейдж из .env)
source .env                                       # ADMIN_BADGE и т.п.
TOKEN=$(curl -s -X POST -H 'Content-Type: application/json' \
  -d "{\"badge\":\"$ADMIN_BADGE\"}" http://localhost:8080/api/v1/auth/login | \
  python3 -c 'import sys,json;print(json.load(sys.stdin)["access"])')
curl -s -F "file=@apps/backend/internal/importer/testdata/nomenclature_sample.xls" \
  -H "Authorization: Bearer $TOKEN" http://localhost:8080/api/v1/import/goods   # товары
curl -s -F "file=@/путь/к/cells.xlsx" \
  -H "Authorization: Bearer $TOKEN" http://localhost:8080/api/v1/import/cells   # ячейки

# 2. Запустить приложение (эмулятор Pixel_8_Pro: 10.0.2.2 = localhost хоста — это дефолт .env)
cd apps/craft_wms
flutter emulators --launch Pixel_8_Pro           # или подключить реальный ТСД по adb
flutter run --dart-define-from-file=.env -t lib/main.dart
#   вход по тест-бейджу 1000000012345678 → «Остатки» → поиск/фильтры → карточка товара

# 3. Остановить и вернуть к исходному
#   в сессии flutter run — 'q' для выхода
cd ../.. && make down && colima stop
```

На **реальном ТСД** (DT50/Zebra) адрес API — в `apps/craft_wms/.env` (`BASE_URL`): для прода
`https://craft.skogi.ru/api/v1/`, для локального стека по LAN — `http://<IP-хоста>:8080/api/v1/`.
Сборка релиза: `flutter build apk --dart-define-from-file=.env --release -t lib/main.dart` → установка на устройство.
