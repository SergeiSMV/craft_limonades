# ADHOC-02 (ops) · Публикация веб-портала одной командой

**Статус:** ✅ завершена (собранный бандл проверен, образ и раскладка прогнаны локально).
На прод-сервере ещё не применял и видимость пакета в GHCR не переключал — см. «Границы задачи».
**Категория:** внеплановая, `adhoc-ops` — эксплуатация прода. Строки в `plan_v3.docx` нет.

## Задача

Публикация портала оставалась единственной ручной операцией деплоя: локальная сборка
`flutter build web`, затем заливка каталога по SFTP. Задача «воспроизводимый деплой портала»
была снята с разработки как «приемлемо вручную» — но цена этого решения предъявилась:
ручная правка nginx, которой портал отдавался с диска, жила вне репозитория, и переустановка
затёрла её шаблоном. Портал лёг, при том что API отвечал нормально и по пробам сервер выглядел
исправным.

Пока публикация ручная, состояние портала на сервере не выводится из содержимого репозитория,
и любая автоматика способна его молча испортить.

## Критерий готовности

Портал обновляется без ручной сборки и без SFTP; обновление переживает переустановку сервера;
на бесплатном тарифе не упирается в квоты.

## Ключевые решения

### Бандл не зависит от домена — это и сделало остальное возможным

Раньше адрес API зашивался в бандл при сборке (`--dart-define-from-file=.env`), поэтому портал
был привязан к домену и собирать его в CI не имело смысла: пришлось бы держать домен в CI
и пересобирать под каждое окружение.

Портал живёт на одном origin с API ([ADR-0015](../adr/0015-url-scheme-api-v1-portal-root.md)),
а `dio` **явно поддерживает относительный `baseUrl` на Web** — это записано в его исходнике:

```dart
///  - Relative path on Web, e.g. `api/`.
set baseUrl(String value) {
  if (value.isNotEmpty && !kIsWeb && Uri.parse(value).host.isEmpty) {
    throw ArgumentError.value(value, 'baseUrl',
      'Must be a valid URL on platforms other than Web.');
  }
}
```

Поэтому портал собирается с `--dart-define=BASE_URL=/api/v1/` и годится для любого домена.
Проверено на собранном бандле: `"/api/v1/"` внутри, а `craft.skogi.ru`, LAN-адреса и даже
подстроки `http://` не встречаются ни разу.

У приложения ТСД так нельзя — там нативная сборка, адрес сервера зашивается в приложение
и относительным быть не может: на устройстве нет origin, относительно которого его разрешать.

**Что порталу нужно из окружения сборки — ничего, кроме адреса API.** В клиенте всего два
чтения `String.fromEnvironment`: `BASE_URL` (используется dio) и `WAREHOUSE_NAME`, который
читает только главный экран ТСД. Совпадение имён обманчиво — в портале `warehouseName`
встречается в `inventory_repository.dart`, но это поле модели документа, приходящее из JSON
API, а не из окружения сборки.

⚠ **Попутно вскрылось в CI.** Шаг «подставить `.env` из шаблона» существовал ради сборки
портала — единственного, кто читал файл. Убрав из портальной сборки `--dart-define-from-file`,
я оставил шаг мёртвым, а сборка APK, как выяснилось, `.env` не использовала **никогда**:
`flutter build apk --debug` шёл без флага и полагался на `defaultValue` в коде, то есть на
адрес эмулятора. Гейт «`.env.example` остаётся разбираемым» при этом не работал вовсе.
Исправлено: `.env` подставляется перед сборкой APK и передаётся ей флагом — тем самым,
которым APK собирается на самом деле.

### Образ в GHCR, а не артефакт CI и не Release-ассет

| Способ           | Почему не он                                                              |
|------------------|---------------------------------------------------------------------------|
| Артефакт Actions | Однажды уже упёрлись в квоту хранилища, из-за чего выгрузку и отключили   |
| Release-ассет    | Нужен токен со scope `repo`; ассеты приватного репозитория тоже считаются |
| **Образ в GHCR** | GHCR с прод-сервера доступен и уже используется, авторизация настроена    |

Решающий довод практический: **Docker Hub из России отваливается по TLS**, а GHCR работает —
это выяснилось на бою, когда `compose pull` не смог скачать `postgres:16-alpine`, притом что
образ backend из GHCR тянулся нормально.

Бандл весит ~50 МБ, поэтому пакет делается **публичным**: публичные пакеты в GHCR не
тарифицируются, и квота перестаёт участвовать в схеме. Раскрытия при этом нет — бандл и так
публично скачивается с сайта, портал по определению отдаётся браузеру. Репозиторий остаётся
приватным: видимость пакета задаётся отдельно от видимости репозитория.

Тег только `:main`, без тега по sha: иначе каждая сборка оставляла бы полсотни мегабайт
навсегда. Прошлые версии остаются без тега и подчищаются шагом `delete-package-versions`,
одна сохраняется для отката.

⚠ **Имя образа приводится к нижнему регистру.** Логин владельца — `SergeiSMV`, а docker
принимает только строчные имена репозиториев образа. `ci-backend.yml` это уже учитывал
(`${GITHUB_REPOSITORY_OWNER,,}`), моя первая версия — нет, и публикация упала бы при первом
же мерже в `main`.

### Образ на `scratch` с командой-заглушкой

Базовый образ не нужен: контейнер не запускается, сервер делает `docker create` и сразу
`docker cp`. Но **`docker create` отказывается создавать контейнер без команды**
(`no command specified`) — выяснилось прогоном, первая версия образа была нерабочей.
Поэтому в образе есть `CMD`, который никогда не выполняется.

### Конфигурации rclone нет — и она не должна о себе напоминать

Подключение задаётся переменными, файла конфигурации нет намеренно. Но rclone на каждый вызов
печатает `Config file "/root/.config/rclone/rclone.conf" not found - using defaults`, и ночной
таймер капал бы этим в journal, маскируя настоящие ошибки. Глушится через `RCLONE_CONFIG=/dev/null`,
что заодно честно описывает положение дел: конфигурации нет.

Уровень логирования при этом **не понижается**. Соблазн добавить `--log-level ERROR` был, но он
прячет и сводку об ошибках. Проверено на неверном пароле: `ERROR: 401 Unauthorized` виден,
код возврата 1, `yandex_check` по-прежнему отличает успех от отказа.

### Подмена бандла атомарная

Файлы извлекаются во временный каталог рядом, проверяется наличие `index.html` (признак,
что извлеклось осмысленное, а не пустота), и только потом каталог подменяется через `mv`.
Иначе nginx успел бы отдать пользователю наполовину скопированный бандл.

Неудача обновления портала не роняет обновление сервера: API на ТСД важнее вёрстки,
поэтому ошибка пишется в journal, а прежний бандл остаётся на месте.

## Что сделано

- **`infra/portal/Dockerfile`** — образ с бандлом на `scratch`.
- **`.github/workflows/ci-flutter.yml`** — портал собирается с относительным `BASE_URL`;
  на push в `main` образ публикуется в GHCR, устаревшие версии подчищаются. Добавлено
  разрешение `packages: write`.
- **`deploy/_lib.sh`** — `portal_root`, `portal_image`, `portal_deploy` (извлечение и
  атомарная подмена).
- **`deploy/update.sh`** — раскладка портала в обычном цикле обновления.
- **`deploy/craft.sh`** — пункт «Обновить веб-портал» для обновления без полного цикла.
- **`infra/.env.prod.example`** — `PORTAL_IMAGE`.

| Шаг                                   | Результат                                                                    |
|---------------------------------------|------------------------------------------------------------------------------|
| Сборка портала с `BASE_URL=/api/v1/`  | успешно, 53 МБ                                                               |

`actionlint` по `ci-flutter.yml` — чисто. `shellcheck -S warning -x deploy/*.sh` — 0 issues.

## Границы задачи

Осталось сделать:

- **Переключить пакет `craft-wms-portal` в GHCR на публичный.** Первая публикация создаст его
  приватным по видимости репозитория; переключается один раз в настройках пакета. Пока пакет
  приватный, он расходует квоту.
- **Прописать `PORTAL_IMAGE` в `.env.prod`** на сервере.
- **Проверить полный цикл на бою:** мерж → сборка образа → обновление → портал отдаётся.

Сознательно вне объёма:

- Размер бандла не оптимизировался: 31 МБ из 53 — движок отрисовки, браузер скачивает лишь
  нужный вариант. Урезание влияет на отрисовку, а портал верстался по макету — трогать без
  проверки вживую не стоит.
- APK для ТСД по-прежнему собирается вручную: он привязан к адресу сервера и подписи,
  автоматическая публикация ему не нужна.
