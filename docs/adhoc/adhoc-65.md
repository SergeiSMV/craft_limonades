## Задача

На ТСД в меню «три точки» главного экрана (рядом с «Номенклатурой», «Сканером», «Принтером») -
раздел печати бейджей сотрудников на мобильный принтер. Доступ задаётся правами должности, три
уровня: только свой бейдж; бейджи всех, кроме администратора; бейджи всех.

## Критерий готовности

- Пункт «Бейджи» в меню виден при любом из трёх прав.
- Список сотрудников - ровно те, чьи бейджи пользователь вправе печатать; решает сервер.
- Касание сотрудника печатает бейдж тем же номером, что выдан: ФИО, должность, Code128 из 16 цифр.
- Права - в дереве должностей портала, миграция с ограничением `positions.rights`.
- Номер раскрывается только сервером и только на печать, каждое раскрытие - в `audit_log`.

## Ключевые решения

### Бейдж печатается тем же номером - номер хранится зашифрованным

Секрет бейджа (последние 8 цифр) проверяется argon2-хешем, а хеш номер не возвращает. Поэтому
для печати секрет лежит отдельно - `users.badge_secret_enc`, AES-256-GCM ключом `BADGE_KEY` из
окружения бэкенда, nonce в начале. Связанные данные - логин (первые 8 цифр): шифртекст,
подложенный от другой строки, не расшифруется. Ключа в базе нет, дамп без `.env.prod` номеров
не раскрывает. Проверка входа не меняется - только хеш.

### Номер запоминается, когда сервер его видит

Два места: вход по бейджу (номер пишется, если сохранённого нет или он другой) и выдача бейджа в
портале (новый бейдж заменяет номер; без ключа - стирает прежний). У сотрудников, заведённых
раньше, номера нет, пока они не войдут один раз: в списке строка помечена «Номер не сохранён»,
печать отвечает 409. Неудача записи номера вход не роняет - только предупреждение в журнале.

### Ключ сменился - номера восстанавливаются входом

Сменился `BADGE_KEY` или база - снимок прода на стенде со своим ключом: номер не
расшифровывается, считается несохранённым и перезаписывается при следующем входе. Ключа нет -
вход работает как прежде, печать отвечает 503 «не задан ключ BADGE_KEY».

### Три права, действует самый широкий

`tsd.badges.own` - свой; `tsd.badges.staff` - всех, кроме администратора; `tsd.badges.all` -
всех. Администратор - системная должность «Администратор»; она получает все права сама.
Галочки, а не переключатель: дерево прав портала - только галочки. Отмечено несколько - уровень
самый широкий (`model.BadgeScopeOf`). Маршрут пускает любое из трёх, чей бейдж - решает сервис.

### Номер - только на печать и в журнал

`GET /badges` отдаёт список без номеров (`stored` - можно ли печатать). `GET /badges/{id}`
отдаёт 16 цифр с `Cache-Control: no-store` и пишет `badge.print` в `audit_log`: бейдж - вход в
систему от имени сотрудника. Терминал номер не кэширует и в состоянии экрана не держит:
не напечаталось - касание ещё раз берёт номер заново. Раздел работает только со связью.

### Ярлык

ФИО (до двух строк) и «Должность: …», ниже Code128 из 16 цифр с цифрами под полосами; модуль 2
точки, высота 12 мм. Code128 - потому что EAN 16 цифр не вмещает; цифры подряд принтер кодирует
набором C. Полосы по левому краю, как у товарного ярлыка с Code128. ФИО и должность проходят
`sanitizeTsplText`. Раскладка - рулон 58×40 мм.

### Попутно: плитка «История» убрана

С главного экрана ТСД убрана плитка-заглушка «ИСТОРИЯ» вместе с `showStub`, строками
`history_title`/`history_subtitle`/`stub_snack` и цветом `kTileHistory`. Заглушек в меню больше нет.

## API

- `GET /api/v1/badges` → `[{id, full_name, position_name, is_admin, stored}]` по ФИО. Право - любое
  из `tsd.badges.*`.
- `GET /api/v1/badges/{id}` → `{user_id, full_name, badge}`; 403 - не вправе, 404 - нет,
  заблокирован или входит по паролю, 409 - номер не сохранён, 503 - ключ не задан.

## Выкатка

`BADGE_KEY` в `.env.prod` - 64 шестнадцатеричных знака (`openssl rand -hex 32`), заводится один
раз и не меняется; в `infra/docker-compose.prod.yml` - переменная `BADGE_KEY: ${BADGE_KEY:-}` у
бэкенда. После выкатки каждый сотрудник один раз входит по бейджу - номер запоминается.
