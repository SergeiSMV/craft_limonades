# ADHOC-66 (ops) · Выпуск приложения ТСД в RuStore

**Статус:** ✅ завершена (`flutter analyze` чист, весь набор Flutter зелёный; релизный APK собран
`scripts/build_tsd_rustore.sh` и подписан ключом приложения). Бэкенд и миграции не менялись.
**Категория:** внеплановая, `adhoc-ops`. Строки в `plan_v3.docx` нет.
**Порядок выпуска версии и тексты карточки:** [`deploy/rustore.md`](../deploy/rustore.md).

## Задача

APK для ТСД нигде не распространялся: его собирали и ставили на терминалы вручную по `adb`.
Приложение «КЛ: Склад» публикуется в RuStore, чтобы терминалы ставили и обновляли его из магазина.

Что мешало публикации:

- релиз подписывался отладочным ключом (`signingConfig = debug`, сертификат `CN=Android Debug`).
  RuStore принимает обновление только с подписью первой версии, а отладочный ключ у каждой машины
  свой - им публиковать нельзя;
- версия `1.0.0+1` не росла, а RuStore требует рост `versionCode` с каждой загрузкой;
- приложение обрабатывает персональные данные сотрудников (ФИО, логин, журнал операций), и по
  правилам RuStore политика конфиденциальности нужна по ссылке в карточке и внутри приложения;
- в APK лежала сборка под x86_64, нужная только эмулятору.

## Критерий готовности

- Релиз боевого приложения подписан ключом приложения; без ключа (CI) - отладочным, как раньше.
- Стенд всегда на отладочном ключе и не требует ключа приложения.
- Версия `1.1.0+2`.
- Одна команда собирает APK для RuStore и отказывает, если подпись отладочная.
- Политика конфиденциальности открывается по `<сервер>/privacy.html` и с экрана входа.
- Есть иконка карточки, тексты, декларация данных, обоснование геолокации и порядок действий в
  RuStore Консоли.

## Ключевые решения

- **APK, а не AAB.** APK подписан своим ключом (так RuStore и рекомендует), и тот же файл ставится
  по `adb` до публикации: RuStore потом обновляет его поверх. AAB потребовал бы загрузки ключа в
  Консоль.
- **Ключ приложения - вне репозитория.** RSA 4096, срок 30 лет, путь и пароли - в
  `android/key.properties` (в `.gitignore`). Gradle берёт ключ, только если файл есть: CI и другие
  машины собирают релиз отладочным ключом, как раньше, и гейту ключ не нужен. Отпечаток SHA-256
  записан в `deploy/rustore.md`.
- **Стенд - отладочным ключом всегда.** Приложение стенда (`…sklad.stand`) в RuStore не идёт.
- **Флейворов по-прежнему нет.** Стенд выбирается `--dart-define=STAND=true` (ADHOC-39).
- **Только ARM.** `--target-platform android-arm,android-arm64`: APK 70 МБ вместо 93 МБ.
- **Политика - статическая страница портала.** `web/privacy.html` уезжает с порталом, nginx отдаёт
  файл раньше `index.html` (`try_files $uri …`), правок сервера нет. Адрес в приложении выводится из
  `BASE_URL`: боевая сборка открывает прод, сборка стенда - стенд.
- **Ссылка - только на экране входа**, внизу обеих форм; открывается внешним браузером.
  Не открылась - адрес показывается подсказкой.
- **Публикация - публичная**, издатель - физическое лицо. Закрытой публикации у RuStore нет, есть
  только альфа-тест по VK ID, где каждая версия всё равно проходит модерацию. Без учётной записи
  приложение бесполезно, учётные записи заводит администратор.
- **Модератору - тестовый работник** с правами только на просмотр: правила RuStore требуют
  тестовый аккаунт для приложений ограниченного круга.

## Проверка

```bash
cd apps/craft_wms
dart run build_runner build --delete-conflicting-outputs
flutter analyze        # No issues found!
flutter test           # All tests passed!
cd ../..
bash scripts/build_tsd_rustore.sh
# == Подпись: CN=Semenov Sergei, O=Craft WMS, L=Ryazan, C=RU, SHA-256 337979c8…5dd799
# package: name='com.craftlimonades.sklad' versionCode='2' versionName='1.1.0'
# разрешения: INTERNET, BLUETOOTH*, ACCESS_FINE_LOCATION (maxSdk 30), BLUETOOTH_SCAN, BLUETOOTH_CONNECT
```

Без `android/key.properties` скрипт останавливается до сборки, а `flutter build apk --release`
подписывает отладочным ключом, как раньше.

## Границы

- Страница `privacy.html` появляется на проде с выкаткой портала из `main`. До выкатки по адресу
  открывается портал - ссылку в карточку RuStore вставлять после выкатки.
- Терминалы с прежней установкой (отладочная подпись) один раз переустанавливаются с удалением
  приложения - порядок в `deploy/tsd-setup.md`. Неотправленная очередь при удалении пропадает.
- Встроенное обновление через SDK RuStore (окно «есть новая версия» в приложении) не делал:
  обновляет само приложение RuStore, если в нём включено автообновление.
- Осталось сделать: публикация в RuStore Консоли (загрузка APK, карточка, тестовый работник,
  модерация), установка RuStore с VK ID склада на терминалы.
