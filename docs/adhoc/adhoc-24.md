# ADHOC-24 (fe) · Бейдж «Заданий» после приёмки и имя файла документа в портале

**Статус:** ✅ завершена (`flutter analyze` 0 issues, полный прогон Flutter-тестов зелёный,
релизная APK собирается).
**Категория:** внеплановая, `adhoc-fe`. Строки в `plan_v3.docx` нет.

## Задача

Два дефекта, найденные на проде после выкатки P5-04:

1. **ТСД.** После завершения приёмки и «На главную» на плитке «ЗАДАНИЯ» не появлялся бейдж
   нового задания на размещение.
2. **Портал.** Любой документ — «Поступление», «Движение» — скачивался под именем
   `vvod-ostatkov-<склад>.xlsx`.

## Критерий готовности

Бейдж «Заданий» обновляется сам, как только сервер подтвердил приёмку или размещение. Файл
документа скачивается под именем, которое прислал сервер: `postuplenie-…`, `dvizhenie-…`,
`vvod-ostatkov-…`.

## Причины

**Бейдж.** Плитка подписана на число заданий в снимке на терминале, а снимок с сервера
обновлялся только при построении главного экрана. Главный экран остаётся в стеке под приёмкой,
и «На главную» возвращает на него без повторного запроса. Задание при этом рождается на сервере
только при проведении приёмки, то есть когда очередь отправила `receipt_submit` — и
обновлять снимок в момент возврата было бы мало даже при перестроении экрана.

**Имя файла.** Сервер собирает имя по форме документа и отдаёт его в `Content-Disposition`,
но портал заголовок не читал: имя было зашито в вкладке документов ещё со времён ввода
остатков, когда форма была одна.

## Ключевые решения

**Обновление заданий — следствие подтверждения операции, рядом со снимком содержимого.**
Подтверждение `receipt_submit` и `putaway_submit` уже обновляет снимок содержимого склада
(P5-05); теперь оно же просит обновить снимок заданий. Приёмка рождает задание, размещение
меняет его остаток — оба события терминал узнаёт только по подтверждению. Путь общий для
немедленной отправки и отправки движком синхронизации, так что бейдж обновится и тогда,
когда приёмка ушла позже, при появлении связи. Плитка подписана на число в снимке и
перерисовывается сама.

**Пауза две секунды**, как у снимка содержимого: очередь подтверждает операции пачкой,
и задания достаточно подтянуть один раз после неё. Без связи загрузка не удастся, снимок
останется прежним.

**Слой domain у заданий начат с узкого интерфейса.** Очередь (`core`) зависит от абстракции
`TasksSnapshotSync`, а не от репозитория фичи — по `dev.md`, как у `ContentsSnapshotSync`.
Остальная фича заданий без domain — это долг 21, отдельной задачей.

**Имя файла знает сервер, портал его не придумывает.** Скачивание возвращает байты вместе
с именем из `Content-Disposition`; новая форма документа больше не требует правки портала.
Сервер шлёт имя латиницей в простой форме `filename=`; нет заголовка — `document.xlsx`.
Портал и API на одном origin, поэтому заголовок читается в браузере без CORS.
