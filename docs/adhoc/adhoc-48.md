## Задача

Пересчёт (P10) блокирует ячейку мягко: движение через ячейку на подсчёте сервер принимает, а
подсчёт помечает сбитым, и считающий узнаёт об этом только при отправке факта — отказом
«пока ячейку считали, через неё прошло движение». Кладовщик, который двигает товар, не знает,
что сбивает чужую работу. Нужно предупредить его до движения.

## Критерий готовности

- Скан ячейки (или короба в ней) в перемещении, размещении, пометке проблемы и возврате
  поставщику на ячейке, где идёт подсчёт, показывает окно: какая ячейка, кто считает, какой
  пересчёт, «Движение собьёт подсчёт — ячейку посчитают заново».
- Кладовщик выбирает: «Отмена» — ячейка не берётся; «Всё равно» — поток идёт дальше, как
  раньше.
- Без связи предупреждения нет, движение не задерживается — сервер сбивает подсчёт сам.

## API

`GET /api/v1/cells/{id}/stocktake-count` (сотрудник) — идёт ли в ячейке склада подсчёт:

```json
{"counting": {"stocktake_number": 12, "address": "M1-1-1-1", "counted_by": "Иванов И.",
              "started_at": "2026-10-26T10:00:00Z"}}
```

или `{"counting": null}`. Подсчёт — ячейка `counting` открытого пересчёта; взятая и не начатая —
нет: снимка у неё ещё нет, сбивать нечего. Неверный id — `null`.

## Ключевые решения

- **Предупреждение, а не запрет.** Решение 2026-10-12 говорило «ТСД на связи не дают начать
  движение»; заменил его выбором «Отмена» / «Всё равно». Начатую и брошенную ячейку иначе нельзя
  было бы тронуть до закрытия пересчёта — склад встал бы из-за одной забытой ячейки.
- **Спрашиваю сервер в момент скана, а не по снимку склада.** Снимок на терминале обновляется
  при входе, по «Обновить» и после подтверждений, а подсчёт ячейки идёт минуты — снимок о нём
  не узнал бы вовремя.
- **Ожидание — 3 с на всё**, и соединение, и ответ. Без связи, при таймауте, ошибке или старом
  сервере без ручки — как будто подсчёта нет: кладовщик со сканером у ячейки важнее
  предупреждения, а сервер сам пометит подсчёт сбитым.
- **«Всё равно» помнится** по ячейке и началу подсчёта до перезапуска приложения: повторные сканы
  той же ячейки в сеансе не спрашивают снова, новый подсчёт той же ячейки — спрашивает.
- **Проверка — на странице потока, до кубита.** Окно — это UI, кубиты остаются синхронными.
  Одна функция `allowMoveThroughCell` в фиче пересчёта, страницы потоков её вызывают.
- **Ячейку приёмки не проверяю** — пересчёт её не считает, лишний запрос ни к чему.
- **Возврат поставщику тоже предупреждает**: товар возврата лежит на системном складе, который
  пересчёт не считает, но триггеры P10-02 сбивают подсчёт при любом изменении остатка ячейки.

## Границы задачи

- Без связи предупреждения нет — так задумано: сервер принимает движение и сбивает подсчёт.
- Скан короба во «Возврате поставщику» не проверяется — только скан ячейки; короб возврата
  забирают из ячейки, которую сканируют до него.
- «Ввод остатков» не проверяет ячейки: он заводит стартовые остатки до пересчётов, при паузе
  движений.
- Новая APK со старым сервером работает: ручки нет — 404 — предупреждения нет.
