# ADHOC-64 (fe) · Признак «маркируемый» после возврата из карточки товара

**Статус:** ✅ завершена (`flutter analyze` чист, весь набор Flutter зелёный). Бэкенд, миграции и
локальная база терминала не менялись.
**Категория:** внеплановая, `adhoc-fe`. Строки в `plan_v3.docx` нет.
**Раздел:** «Номенклатура» на ТСД, признак «маркируемый» - [`cz/cz-05.md`](../cz/cz-05.md).

## Задача

В «Номенклатуре» в карточке товара с признаком «Маркируемый» выбрали «Без марки» и вернулись к
списку. При повторном входе в карточку этого товара она снова показывала «Маркируемый».

Сервер правку принимает (`PATCH goods/{id}/cz-marked` → 200), справочник терминала тоже
обновляется (`CatalogCache.setGoodCzMarked`). Но карточка открывается из объекта товара в списке
номенклатуры, а список при возврате из карточки ничего не перечитывал
(`GoodsListCubit.returnedFromCard` был пустым). Поэтому карточка снова строилась из объекта,
загруженного до правки. Со старым признаком открывалась и секция «Штрихкоды».

## Критерий готовности

- После правки признака в карточке и возврата к списку повторный вход показывает новый признак.
- Список при этом заново не запрашивается: прокрутка, подгруженные страницы и фильтры остаются.
- «Остатки» по-прежнему перечитывают снимок при возврате из карточки.

| `features/stock/presentation/bloc/goods_list_cubit.dart`          | `returnedFromCard(goodId)` подменяет товар в списке |

| `features/stock/presentation/widgets/goods_list/goods_result.dart` | передаёт товар карточки                          |

| `test/features/stock/goods_list_cubit_test.dart`                  | подмена товара, товара нет в справочнике          |

## Ключевые решения

`GoodsListCubit.returnedFromCard(goodId)` читает открытый товар из справочника терминала
(`CatalogRepository.goodById`, без сети) и подменяет его в списке, если он изменился. Перечитывать
весь список не нужно: карточка меняет только свой товар, а полная загрузка сбросила бы
подгруженные страницы и прокрутку. Товара в справочнике нет (заведён после загрузки) - список
остаётся прежним.

«Остатки» (`StockGoodsCubit`) при возврате, как и раньше, перечитывают снимок. Товары в нём уже
берутся из справочника заново (`goodsByIds`), поэтому там этой ошибки не было.
