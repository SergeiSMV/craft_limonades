# ADHOC-59 (fe+be) · ТСД: карточка из «Остатков» теряла признак «маркируемый»

**Статус:** ✅ завершена (`go test ./...` и весь набор Flutter зелёные, линтеры чисты).
**Категория:** внеплановая, `adhoc-fe` с правкой сервера (`adhoc-be`). Строки в `plan_v3.docx` нет.

## Задача

Маркируемый товар с маркой на складе в карточке, открытой из «Остатков», показывался
«Маркировка ЧЗ: нет» / «Без марки». Обновление справочников не помогало, хотя на сервере признак
стоял. Скан марки открывал ту же карточку с «да».

Причина — на ТСД. «Остатки» (ADHOC-33) строят список из снимка склада, и товар для карточки
собирался из строки снимка: id, код, наименование, группа, поставщик. Признака «маркируемый» в
строке нет — он вставал по умолчанию `false`. Терялись и полное наименование, имя поставщика и
«активен». По тому же признаку блок «Штрихкоды» решает, проверять ли марки на складе перед
отвязкой ШК (ADHOC-53), поэтому из «Остатков» проверка на ТСД пропускалась (сервер отвязку всё
равно отклонял, но перепривязку с «Пересортом» ТСД не предлагал).

Попутно: снять признак мог admin при марках на складе — сервер это принимал, и товар с марками
начинал двигаться количеством, мимо правила CZ-06.

## Критерий готовности

- Карточка из «Остатков» открывается с товаром из справочника терминала целиком — признак, полное
  наименование, поставщик те же, что из «Номенклатуры».
- Товара нет в справочнике терминала — карточка открывается с данными строки снимка, как раньше.
- Снять «маркируемый», пока марки товара на складе, нельзя: 409 с причиной по-русски, ТСД
  показывает её; ставить признак можно всегда.

## Что сделано

| Файл                                                  | Правка                                          |
|-------------------------------------------------------|-------------------------------------------------|
| `stock/data/catalog_repository.dart`                  | `goodsByIds` — товары справочника одним запросом |
| `stock/presentation/bloc/stock_goods_cubit.dart`      | товар строки — из справочника, снимок — запасной |
| `internal/model/cz.go`                                | `ErrCZGoodHasMarks`                             |
| `internal/repository/cz_marks.go`                     | проверка марок в том же `UPDATE`                |
| `internal/handler/cz.go`                              | 409 с причиной                                  |
| тесты                                                 | признак из справочника в «Остатках», запрет снятия |

## Ключевые решения

- **Источник товара карточки — справочник терминала, а не строка снимка.** Снимок отвечает за
  количество и места, справочник — за сам товар; «Остатки» читают товары справочника одним
  запросом на весь список при каждом перечитывании снимка.
- **Проверка марок — в самом `UPDATE`**, а не отдельным запросом перед ним: марку могут принять
  между проверкой и правкой. Не изменилось ни одной строки — второй запрос различает «нет
  товара» (404) и «марки на складе» (409).
- «На складе» — марки в статусе `in_stock`; отгруженные и возвращённые снятию признака не мешают.
