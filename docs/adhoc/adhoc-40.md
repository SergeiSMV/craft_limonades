# ADHOC-40 (be) · Отказ документа называет все плохие строки, по-русски и по содержимому

**Статус:** ✅ завершена (gofmt/build/vet чисты, golangci-lint 0 issues, полный `go test ./...`
зелёный; новые тесты без отката строки и без восстановления остатка задания падают).
**Категория:** внеплановая, `adhoc-be`. Строки в `plan_v3.docx` нет; первая часть долга 26.

## Задача

Документ движения и сеанс размещения проводятся одной транзакцией, и проверка строк
обрывалась на первой плохой. В отказ уходил английский код (`not enough goods at the source`)
без указания строки, и терминал показывал его на экране «Несинхронизированное» как есть.
Кладовщик с тремя неисполнимыми строками узнавал о них по одной за попытку и не понимал,
о какой строке речь. Живой сценарий — два терминала, работающие по устаревшему снимку склада.

## Критерий готовности

Отклонённый `movement_submit` и `putaway_submit` называет все плохие строки сразу; каждая —
по-русски, товаром, партией, количеством и местами «откуда → куда». Документ по-прежнему
проводится целиком или не проводится вовсе.

## Ключевые решения

### Точка отката на строку

Каждая строка выполняется под `SAVEPOINT`. Отказ строки по существу (не хватает товара, короб
не найден или не размещён, ячейка приёмки, чужой склад, нет в задании …) откатывает только
её, и следующие строки проверяются так, будто её не было. После последней строки: есть плохие —
отказ документа со списком всех, транзакция откатывается целиком, как и раньше. Временный сбой
и отказ всего документа (уже проведён, неизвестный вид, задание не то) обрывают проверку сразу.

Откат к точке нужен не только ради чистого состояния: ошибка SQL внутри строки (ссылка на
несуществующее) переводит транзакцию Postgres в «прерванную», и без отката следующая строка
упала бы уже на этом.

### Остаток задания в памяти

Размещение списывает строку с остатка задания в памяти до переноса товара. Отклонённая строка
этот остаток восстанавливает: иначе следующая строка упёрлась бы в «больше, чем осталось по
заданию» из-за строки, которой нет.

### Текст — по-русски и по содержимому строки

Номер строки кладовщику ничего не говорит: документ он собирал сканами, а не по списку. Сервер
знает справочники и называет строку так, как её видит человек:

```
Отклонено строк: 2 из 3
• Кальмар · партия 01.09.2026 · 50 шт: M1-1-1-1 → M1-1-1-2: в источнике не хватает товара этой партии
• Кальмар · партия 01.09.2026 · 20 шт: короб 1A2B 3C4D → M1-1-1-3: в источнике не хватает товара этой партии
```

Короб — коротким кодом, как на ярлыке. Терминал показывает текст без правок: экран
«Несинхронизированное» и так выводит причину отказа. Русские причины заведены только для
отказов строк документа; прочие коды не менялись.

### Ошибка с причинами строк

`DocumentLinesError` отдаёт причины строк через `Unwrap() []error`: `errors.Is` по ним работает,
как прежде, поэтому прежние проверки отказа в тестах и сервисе не менялись. Сервис дополнительно
узнаёт список строк явно — отказ по существу целиком.
