# ADHOC-44 (ops) · Секреты сервера: `.env.prod` только для root

**Статус:** ✅ завершена (`bash -n` и `shellcheck -S warning` по `deploy/` чисты; на сервере права
выставлены и проверены: обычный пользователь файл не читает, root читает, `/ready` — 200).
**Категория:** внеплановая, `adhoc-ops`. Строки в `plan_v3.docx` нет. Закрывает долг 32.

## Задача

`/opt/craft-wms/.env.prod` лежал с правами `644`: любой пользователь сервера читал пароль базы,
JWT-секрет, фразу шифрования бэкапов, токен GHCR, пароли Bugsink и SMTP. Скрипты деплоя и
таймеры работают от root, но панель `craft.sh` пункты бэкапа и восстановления запускает без
повышения прав — простой `chmod 600` молча оставил бы их без пароля базы и фразы шифрования.

## Критерий готовности

`.env.prod` — `root 600` на сервере и при любой установке; права возвращаются сами, если файл
пересоздали; скрипт без прав на чтение отказывает с подсказкой, а не работает с пустыми
значениями; панель, открытая без `sudo`, поднимает права сама.

## Что сделано

| Файл                         | Правка                                                   |
|------------------------------|----------------------------------------------------------|
| `deploy/_lib.sh`             | `secure_env_file`; `require_env_file` проверяет чтение   |
| `deploy/install.sh`          | права на `.env.prod` при установке                       |
| `deploy/update.sh`           | права на `.env.prod` при каждом прогоне таймера          |
| `deploy/craft.sh`            | без root и без прав на файл — перезапуск через `sudo`    |
| `docs/deploy/prod-deploy.md` | права файла, `chmod 600` в установке, `sudo` у compose   |

На сервере: `chown root:root` и `chmod 600` на `/opt/craft-wms/.env.prod`.

## Ключевые решения

### Права чинит каждый прогон обновления

`update.sh` работает от root по таймеру каждые 5 минут и при старте ставит `root 600`. Файл,
пересозданный руками с умолчательными `644`, через несколько минут снова закрыт — держится не
на памяти администратора. `install.sh` делает то же при установке.

### Нет прав — отказ, а не пустые значения

`get_env` читает файл `grep`-ом с подавлением ошибок: без прав он вернул бы пустую строку, и
бэкап ушёл бы с пустой фразой шифрования. Поэтому `require_env_file` проверяет и чтение:
нет прав — «запускайте через sudo».

### Панель поднимает права сама

`craft.sh` и так запускается через `sudo` по инструкции, а пункты, которым root не нужен,
шли без него ради лишнего запроса пароля. С закрытым файлом без root панель не прочтёт даже
домен, поэтому, открытая без `sudo`, она перезапускается через него.

### Что не трогали

`cz-signer.env` (пароль ключа подписанта) уже был `root 600`; служба подписанта читает его
через systemd. Остальные юниты `.env.prod` не читают.

## Границы

Шифрования секретов на диске нет: root сервера читает их, как и прежде. Защита — от прочих
пользователей и процессов сервера.
