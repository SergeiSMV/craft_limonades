## Задача

`deploy/update.sh` накатывал миграции (`migrate up`) без дампа. Откат схемы на проде запрещён,
неудачная миграция чинится следующей, но если миграция испортила данные, ближайшей точкой
восстановления был ночной бэкап (06:30 МСК): всё внесённое с утра до обновления терялось.

## Критерий готовности

Перед применением новых миграций обновление снимает дамп базы; без новых миграций дампа нет.
Не снялся дамп — миграции не применяются, работает прежняя версия.

## Ключевые решения

### Дамп только при новых миграциях

Таймер гоняет `update.sh` каждые 5 минут, дамп на каждом запуске забил бы диск. Раннер
получил команду `migrate pending`: она сравнивает версию базы с последней миграцией,
встроенной в образ, и отвечает кодом выхода — `0` есть что применять, `3` схема актуальна,
`1` ошибка. Пустая база и «грязная» версия (миграция упала на середине) считаются «есть».
Тройка, а не единица, потому что единицу отдаёт `log.Fatal`.

`update.sh` спрашивает свежий образ (после `pull`) до `migrate up`: `3` — дампа нет, `0` —
дамп, иначе — дамп «на всякий случай». Последнее покрывает и первую выкатку, когда новый
`update.sh` приезжает раньше образа, где `pending` уже есть: несколько лишних дампов дешевле
миграции без точки восстановления.

### Не снялся дамп — обновление стоит

Отказ дампа останавливает обновление до миграций: прежний контейнер работает на прежней схеме,
в journal — запись с приоритетом error. Отказ `pg_dump` проверяется явно, а не только через
`set -e`: функцию зовут в контексте `||`, где errexit выключен, а `gzip` от пустого входа даёт
непустой файл — проверка размера такой отказ не видит.

### Свой каталог, без шифрования, наружу не уходит

Дампы ложатся в `/opt/craft-wms/premigrate/` (права 700), хранятся последние 5. Каталог
отдельный от `backups/`: ночная ротация (`find` по `backups/` рекурсивный) и внешняя копия его
не видят. Не шифрую: на сервере ночной `.sql.gz` тоже лежит открытым (на нём работает проверка
восстановимости), шифрование на том же диске ничего не защищает, а открытый дамп сразу
восстанавливается `pg-restore.sh <файл>`.

### Общий дамп

`pg_dump | gzip` с проверками вынесен в `dump_db` — им пользуются и ночной бэкап, и дамп перед
миграциями.

## Проверка

```bash
colima start
cd apps/backend
gofmt -l . && go build ./... && go vet ./... && golangci-lint run ./...
DOCKER_HOST="unix://$HOME/.colima/default/docker.sock" TESTCONTAINERS_RYUK_DISABLED=true \
  go test ./cmd/migrate/ -count=1 -v
cd ../..
for f in deploy/*.sh; do bash -n "$f"; done
docker run --rm -v "$PWD:/mnt" -w /mnt koalaman/shellcheck:stable \
  -S warning -x deploy/*.sh deploy/test_stand/*.sh
colima stop
```

Ожидаемо: `TestPendingMigrations` — PASS, shellcheck без замечаний. На сервере после выкатки
первой новой миграции: в `journalctl -u craft-wms-update` — «Дамп перед миграциями → …», файл
в `/opt/craft-wms/premigrate/`; на запусках без миграций — «Новых миграций нет — дамп не нужен».
