# ADHOC-69 (fe) · Обновление приложения ТСД из RuStore

**Статус:** ✅ завершена (`flutter analyze` чист, весь набор Flutter зелёный; релизный APK собран
`scripts/build_tsd_rustore.sh` и поставлен на DT50S). Само обновление на терминале не проверено:
приложения ещё нет в RuStore, SDK отвечает 404 (см. «Проверка»). Бэкенд и миграции не менялись.
**Категория:** внеплановая, `adhoc-fe`. Строки в `plan_v3.docx` нет.

## Задача

После ADHOC-66 новую версию на терминал ставит только приложение RuStore, если в нём включено
автообновление и выполнен вход под VK ID. Учётную запись VK склада на терминалах не заводим
(решение 2026-11-09). Приложение должно находить и ставить новую версию само, через SDK RuStore.
При этом нельзя терять очередь неотправленных операций и перезапускать приложение посреди работы.

## Критерий готовности

- Проверка новой версии - на экране входа и в главном меню, где никто не стоит посреди операции:
  при показе экрана, при возврате в меню из раздела, при пробуждении терминала; не чаще раза в 3 часа.
- Новая версия скачивается в фоне без окон RuStore; когда скачана - кнопка «Обновить приложение» на
  экране входа и в главном меню.
- Установка - только при пустой очереди операций, иначе подсказка отправить очередь.
- Отказ RuStore (нет RuStore, нет входа в RuStore, обновления нет, приложение не найдено) -
  только запись в журнал приложения, работнику ошибок нет.
- В приложении стенда (`STAND=true`) и в демо-режиме проверки нет.

## Ключевые решения

- **Тихое скачивание + установка с перезапуском.** `silent()` качает в фоне без окон RuStore.
  Установка - `completeUpdateFlexible()`: RuStore показывает окно установки, после неё приложение
  запускается заново. Отложенный сценарий (`download()`) не взят: он показывает окно RuStore
  «скачать?», и работнику пришлось бы разбираться с чужим экраном. Принудительный (`immediate()`)
  перекрывает приложение и при отказе требует его закрыть - посреди смены это недопустимо.
  `completeUpdateSilent()` не взят: он закрывает приложение без перезапуска.
- **Экран входа и главное меню.** Сеанс живёт до 30 дней (refresh-токен, `REFRESH_TTL`), и
  терминал, где никто не выходит из учётной записи, экран входа месяцами не видит - проверка только
  там новую версию не нашла бы. Главное меню тоже безопасно: приёмка, размещение, сборка,
  пересчёт открываются отдельными экранами поверх него, внутри них кнопки нет.
- **Поводы проверки - показ экрана, возврат в меню, пробуждение терминала.** Возврат из раздела
  ловит `didPopNext` через `AutoRouteObserver` в роутере; готовый `AutoRouteAwareStateMixin` не
  взят - он падает, когда экран нарисован без роутера (виджет-тесты). Пробуждение -
  `AppLifecycleState.resumed`.
- **Не чаще раза в 3 часа.** Версии выходят редко, а каждый запрос - сеть и батарея ТСД. Во время
  скачивания и при уже скачанной версии магазин не спрашивается вовсе; после ошибки скачивания
  следующая проверка качает заново.
- **Кубит один на приложение** (`@lazySingleton`): скачивание идёт дольше одного экрана, и
  «скачано» должно дожить до перехода между входом и меню.
- **Очередь проверяется при нажатии.** Обновление базу не стирает, но операции должны уйти на
  сервер со старой версией. В меню подсказка - дождаться отправки (значок очереди в шапке), на
  экране входа - войти и дождаться (без сеанса очередь не уходит). Отклонённые сервером операции
  установку не держат.
- **Отказ SDK - журнал, а не ошибка работнику.** Плагин отдаёт ошибку SDK как `PlatformException`
  с именем класса. Реализация переводит её в `AppUpdateUnavailable`, кубит пишет её в журнал
  (`talker.info`). Неудачная установка после нажатия - подсказка «не удалось обновить».
- **Имена ошибок SDK в релизе.** Правила самой SDK не защищают `ru.rustore.sdk.core.exception`, и
  R8 переименовывал их в «c» - по журналу нельзя было понять причину. `-keepnames` в
  `proguard-rules.pro` сохраняет только имена.
- **Без maven-правок.** Плагин сам добавляет репозиторий RuStore
  (`nexus-external.rustore.ru/…/maven-rustore-exposed`) и тянет `ru.rustore.sdk:appupdate:10.5.2`.
  minSdk плагина 24, у приложения 30.
- **Новое разрешение `RECEIVE_BOOT_COMPLETED`** приходит из SDK RuStore (обычное, не опасное) -
  видно в выводе `build_tsd_rustore.sh`.

## Условия работы SDK

Из документации RuStore: проект в RuStore Консоли («Push-уведомления → Проекты») для пакета и
подписи, пройденная модерация (публиковать необязательно), актуальное приложение RuStore, ему
разрешена установка приложений, **выполнен вход в RuStore**. Без входа `info()` должен отвечать
`RuStoreUserUnauthorizedException` - тогда приложение молча не обновляется, версия ставится по `adb`.

## Проверка

```bash
cd apps/craft_wms
dart run build_runner build --delete-conflicting-outputs
flutter analyze        # No issues found!
flutter test           # All tests passed!
cd ../..
bash scripts/build_tsd_rustore.sh
adb install -r apps/craft_wms/build/app/outputs/flutter-apk/app-release.apk
```

На DT50S (RuStore 1.113.2.0) экран входа и главное меню открываются без ошибок и без кнопки. Вход,
раздел, возврат в меню и пробуждение экрана - без повторных запросов к RuStore (интервал). В журнале
один раз за запуск:

```text
Обновление приложения недоступно: RuStoreException | ru.rustore.sdk.core.exception.RuStoreException:
404 Not Found on request: /applicationData/overallInfo/com.craftlimonades.sklad
```

RuStore пока не знает приложение: оно не прошло модерацию. Выполнен ли вход в RuStore, такой ответ не
говорит, поэтому работает ли SDK без входа под VK ID, на терминале пока не установлено.

## Границы

- Само обновление (скачивание, кнопка, установка) на устройстве не проверено - нужна опубликованная
  версия в RuStore и следующая версия с большим `versionCode`. Порядок проверки: опубликовать
  `1.1.0+2`, завести проект в «Push-уведомления → Проекты», загрузить `+3`, перезапустить
  приложение `+2` на терминале, смотреть журнал. Ответ `RuStoreUserUnauthorizedException` будет значить, что
  без входа в RuStore SDK не работает.
- Первая установка на терминал - по-прежнему по `adb` или из RuStore.
- Демо-режим и стенд обновление не проверяют. Из демо в рабочий режим - через «Вернуться к рабочему
  серверу», дальше проверка идёт как обычно.
