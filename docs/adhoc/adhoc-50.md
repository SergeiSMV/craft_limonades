## Задача

После ADHOC-49 портал пускал только администратора, а вести пользователей было негде. Первый
вариант экрана должностей показал, что девять прав по API непонятны: «Честный знак» в портале
не виден вовсе, а «документы для 1С» одной галочкой не дают разделить «смотреть» и «проводить».
Права должны совпадать с экранами: дерево «приложение → раздел → действия» с галочками.

Вторая из трёх задач должностей: сервер — ADHOC-49, ТСД — ADHOC-51; в `main` уходят вместе.

## Критерий готовности

- Права должности — действия по разделам портала и плиткам ТСД; в карточке должности — дерево
  с галочками: галочка раздела ставит и снимает все его действия, часть отмечена —
  «полугалочка»; повторное нажатие снимает.
- Сервер проверяет каждое действие: вид документа и действие с ним, вид операции очереди.
- Прежние права переходят в новые без потери доступа.
- В портал пускает любое действие портала; меню и кнопки внутри разделов — по действиям.
- «Настройки» → «Должности» и «Пользователи»: завести, изменить, удалить пустую должность;
  пользователь — бейдж или логин с паролем, новый бейдж или пароль, блокировка; себя
  заблокировать нельзя.

## Дерево прав

**Портал** (код `portal.<раздел>.<действие>`):

- Номенклатура — загружать из 1С.
- Приход, Перемещение — смотреть документы и историю, скачивать, проводить.
- Инвентаризация — пересчёты (смотреть ход; заводить и закрывать), документы «Инвентаризация»
  и «Ввод остатков» (смотреть, скачивать, проводить).
- Ячейки — загружать, печатать этикетки.
- Проблемы склада — смотреть (с фото), принимать решение и проводить.
- Настройки — внутренние склады; должности и пользователи.

**ТСД** (код `tsd.…`, по плиткам): Приход · Перемещение · Задания (размещение и возврат
поставщику; пересчёт — считать ячейки; пересчёт — заводить и закрывать) · Остатки (смотреть;
признак «маркируемый (ЧЗ)») · Ввод остатков · Проблемы (смотреть; помечать с фото).

Служебные проверки ЧЗ и мониторинга (их зовёт `craft.sh`) — только «Администратор». «Сборка» в
дереве появится вместе с P9; до тех пор раздел в портале не показывается.

## Ключевые решения

- **Код права — «приложение.раздел.действие»**; группы дерева в базе не хранятся, их рисует
  клиент по общему описанию дерева. Сервер знает только листья — 31 действие, тот же список в
  ограничении `positions.rights`.
- **Перенос прежних прав** (миграция 34): каждый прежний код — в свои действия, «работа на ТСД»
  — во всё на ТСД, кроме того, что раньше было отдельными правами (заводить пересчёт, признак
  ЧЗ). Откат возвращает прежний код каждому действию и «вход в портал» — у кого был раздел
  портала.
- **Отдельного «входа в портал» нет** — пускает любое действие портала.
- **Документы:** список вида — по любому праву на вид (скачивать и проводить без списка
  бессмысленны), история — «смотреть», файл — «скачивать», «Провести» — «проводить». Маршрут
  пускает с правом хоть на один вид, обработчик уточняет по виду документа.
- **Очередь ТСД:** операция без права отклоняется русским текстом «нет права на эту операцию —
  обратитесь к администратору», остальные в батче идут дальше. Привязка ШК — любое право ТСД.
- **Доступ читается один раз на запрос** и кладётся в контекст: обработчики документов и очереди
  проверяют вид, не обращаясь к базе повторно.
- **Галочки — Material `Checkbox` с тремя состояниями**: фильтр-чип портала для этого не годится
  — выбранный чип нажатий не принимает (поэтому в первом варианте право нельзя было снять).
- **Разделы в дереве свёрнуты**, приложения раскрыты: состояние раздела видно по его галочке.
- **Строка должности** — сводка по приложениям: «Портал: Приход, Проблемы склада».
- **Кнопки, на которые нет права, не показываются**, а не отключаются.
- **Вход нового пользователя — бейдж по умолчанию**; новый бейдж и новый пароль — того же вида,
  что прежний вход.

## Границы задачи

- ТСД: плитки и действия по правам вместо роли — ADHOC-51. До неё ТСД смотрит на производную
  роль (`admin` — у кого «Должности и пользователи»), сервер уже проверяет действия ТСД.
- Права в открытой сессии портала не обновляются на лету — после смены прав нужен новый вход;
  сервер отвечает по новым правам сразу.
- Операция очереди, принятая раньше и пришедшая повторно после того, как право сняли, получит
  отказ, а не «повтор»: право проверяется до разбора повтора.
