# ADHOC-54 (ops) · Честный знак на тестовом стенде

**Статус:** ✅ завершена: shellcheck и `bash -n` чисты, стенд без ЧЗ работает как прежде.
Включено на настоящем сервере (2026-10-29): `cz-setup` → токен стенда, чтение марки через True API
со стенда, токен прода жив.
**Категория:** внеплановая, `adhoc-ops`. Строки в `plan_v3.docx` нет.

## Задача

На стенде (ADHOC-27) не было ЧЗ: бэкенд получает токен True API подписью КЭП через службу
`craft-wms-cz-signer`, а она с КриптоПро и ключом стоит только на боевом сервере. Поэтому скан
марок, приёмку ЧЗ, пересорт (ADHOC-53) можно было проверить только после слива в прод.

## Критерий готовности

- ЧЗ на стенде включается одной командой и выключается настройкой; без ЧЗ стенд работает как
  раньше.
- КриптоПро и ключ остаются только на сервере, копий КЭП нет.
- Доступ стенда к серверу — отдельный пользователь, у которого есть только проброс, без оболочки.
- Есть проверка по звеньям, как пункт 19 на проде.

## Как устроено

- **Подписант остаётся на сервере.** Контейнер `cz-tunnel` держит SSH к серверу от пользователя
  `cz-tunnel` и пробрасывает `/run/cz-signer/sign.sock` в общий том. Бэкенд стенда видит сокет
  по тому же пути, что на проде, и получает токен тем же кодом.
- **Запросы к True API идут через тот же SSH** (SOCKS, `-D`, `HTTPS_PROXY` бэкенда), с адреса
  сервера, как у прода. С Mac напрямую они ненадёжны: VPN-клиент Happ (sing-box, `utun4`)
  вешал TLS к `markirovka.crpt.ru` из VM colima, хотя с самого Mac сайт открывался за полсекунды.
- **Туннель — контейнер, а не `ssh -L` на Mac**: сокет с macOS внутрь VM colima не пробрасывается.
- **Пользователь `cz-tunnel` на сервере:**
  - группа `cz-signer` (без docker и sudo), оболочка `nologin`;
  - ключ с `restrict,port-forwarding`;
  - правило `Match User cz-tunnel` в `/etc/ssh/sshd_config.d/craft-stand-cz.conf`: только
    локальный проброс, без TTY, агента, X11, обратных туннелей и пароля.

  sshd открывает проброс unix-сокетов только при `AllowTcpForwarding local`, а `PermitOpen`
  закрывает вместе с TCP и сокеты. Поэтому TCP-проброс у `cz-tunnel` открыт. Ключ лежит на
  машине разработчика, у которой и так есть полный SSH-доступ к серверу.
- **Ключ хоста сервера** берётся из `~/.ssh/known_hosts` этой машины (туда же ходит
  `stand.sh pull`), ssh туннеля проверяет его строго.
- **`STAND_CZ=on`** подключает `docker-compose.stand.cz.yml` поверх основного. При `off` туннель
  прежнего запуска убирается (`--remove-orphans`), бэкенд работает без ЧЗ.
- **nginx стенда** узнаёт адрес бэкенда через DNS Docker на каждый запрос. Раньше он
  запоминал адрес при старте и после пересоздания бэкенда (смена `STAND_CZ`) отвечал 502.
- **`cz-test`** проверяет по звеньям: сокет в туннеле → проверочный администратор (заводится
  сидером, если его нет после `reset`/`refresh`) → статус ЧЗ бэкенда (подписант, токен) → по
  желанию чтение марки.

## Включение

```bash
bash deploy/test_stand/stand.sh cz-setup
```

Команда:

1. создаёт ключ туннеля;
2. копирует `stand-cz-access.sh` на сервер и запускает через `sudo` (пароль спросит сервер);
3. спрашивает ИНН — как `CZ_OWNER_INN` на проде;
4. ставит `STAND_CZ=on`, поднимает стенд и запускает `cz-test`.

Выключить — `STAND_CZ=off` в `stand.env` и `stand.sh up`. Убрать доступ на сервере:
`sudo bash deploy/stand-cz-access.sh --revoke`.

## Проверка

```bash
docker run --rm -v "$PWD:/m" -w /m koalaman/shellcheck:v0.10.0 deploy/test_stand/stand.sh deploy/stand-cz-access.sh
bash deploy/test_stand/stand.sh up          # без ЧЗ — как прежде
bash deploy/test_stand/stand.sh cz-test     # после cz-setup
```

Без доступа к серверу цепочку проверили на поддельном сервере: контейнер с sshd по тем же
правилам `Match` и сокетом-заглушкой подписанта.

- Через туннель сокет отвечает, бэкенд видит подписанта, а запросы к True API выходят со
  стороны сервера.
- Пользователю `cz-tunnel` закрыты оболочка («This account is not available») и обратный
  проброс.

## Границы

- Стенд получает свой токен True API на ту же организацию, что и прод. Токены живут рядом:
  2026-10-29 после выдачи токена стенду прод по-прежнему читал марки своим (`craft.sh`, пункт 19).
- Каждый скан на стенде — настоящий запрос в True API от имени организации, только чтение.
- Пока туннель лежит (сервер недоступен, вне LAN), `stand.sh up` с `STAND_CZ=on` не поднимает
  стенд и говорит, как выключить ЧЗ.
