# ADHOC-12 (fe) · Отложенная привязка не попадала в карточку, а «Отмена» роняла диалог

**Статус:** ✅ готово (analyze 0, 277 тестов зелёные, релизная APK собрана).
Оба регресс-теста проверены на коде с дефектами.
Проверено на живом DT50S: привязка без связи появляется в карточке с пометкой, диалог
закрывается штатно. Отложенная отвязка без связи тоже проверена на устройстве — код исчезает
из карточки сразу.
**Категория:** внеплановая, `adhoc-fe`. Строки в `plan_v3.docx` нет.

## Задача

Два дефекта, найденные на устройстве сразу после выпуска P2-06. Оба — недоделки предыдущих
задач, а не новые обстоятельства.

### 1. Отложенная привязка не появлялась в карточке

Привязка ШК без связи ложится в кэш с пометкой «ожидает отправки» — это и есть смысл P2-06.
Но карточка её не показывала: `StockDetailCubit.bindBarcode` перезагружал карточку **только
при успехе**, а офлайн успеха нет. Кладовщик видел прежний список и делал единственно разумный
вывод — работа пропала.

Зеркально то же было с отвязкой: код убирался из кэша, а в карточке оставался.

### 2. «Отмена» роняла диалог вместо закрытия

```
type 'bool' is not a subtype of type 'BindOutcome?' of 'result'
  bind_barcode_dialog.dart:242  Navigator.pop
```

На кнопке «Отмена» остался `pop(false)` со времён, когда диалог возвращал `bool`. В ADHOC-11 я
поменял тип возврата у отправки и не поменял у отмены; `showDialog<BindOutcome>` получал `false`
и падал на приведении типа. Диалог при этом не закрывался.

## Критерий готовности

Отложенная привязка видна в карточке с пометкой. «Отмена» закрывает диалог без ошибки.

## Ключевые решения

### Список ШК перечитывается отдельно от остатков

Полная перезагрузка карточки тут не годится: остатки читаются **всегда из сети** (решение
P2-02 — устаревшее число хуже честного «нет связи»), и без связи она увела бы карточку в экран
ошибки при том, что привязка на самом деле принята. Поэтому появился `_reloadBarcodes`: читает
только список ШК, не трогая ни остатки, ни статус карточки.

Неудачу самого чтения он тоже не показывает: список берётся из локального кэша, а если и тот не
дался — прежний список вернее пустого.

### Отмена возвращает «ничего», а не значение

`pop()` без аргумента: отмена — это отсутствие исхода, а не третий его вид. Вызывающий уже
устроен так, что действует только на `deferred`, а `null` для него означает «кладовщик закрыл
диалог».

## Что сделано

- **`features/stock/presentation/bloc/stock_detail_cubit.dart`** — `_reloadBarcodes` и его вызов

- **`features/stock/presentation/widgets/stock_detail/bind_barcode_dialog.dart`** — «Отмена»

Правок бэкенда, миграций и изменений API нет.

```
cd apps/craft_wms

```

**Оба регресса проверены на коде с дефектами.** Тест отложенной привязки упал на отсутствии
пометки в карточке; тест отмены — ровно с тем сообщением, что пришло с устройства:

```
type 'bool' is not a subtype of type 'BindOutcome?' of 'result'
```

Тем же `pop(false)` ронялся и давно написанный тест про 409 — то есть дефект отмены задевал
не только отмену.

В моке репозитория офлайн-привязка теперь **кладёт запись в кэш с пометкой и возвращает отказ**,
как это делает настоящий репозиторий. Без этого тест проверял бы не тот договор.

## Границы задачи

- **Отложенная отвязка проверена на устройстве** — код исчезает из карточки сразу, не дожидаясь
  связи; раньше этот сценарий был закрыт только тестом на уровне cubit.
- **Остальные диалоги не пересматривались.** Возврат `bool` там законен: диалог отвязки и
  подтверждение отброса операции — вопросы «да/нет», у них нет исхода сложнее.
