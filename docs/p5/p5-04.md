# P5-04 · Excel «Движение»: документ размещения в портале

**Статус:** ✅ завершена (`go test ./...` и `golangci-lint` зелёные, `flutter analyze` 0 issues,
полный прогон Flutter-тестов зелёный; список и скачивание проверены в локальном стеке).
**Категория:** плановая, фаза P5.

## Задача

Проведённое размещение публикуется в портал документом «Движение» для 1С: исполнитель, товары
по партиям, ячейка-отправитель и ячейка-адресат. Шаблон один на размещение, перемещение
и пополнение (P6). Оператор скачивает .xlsx, заносит в 1С и отмечает выполненным — тот же
цикл, что у «Поступления».

## Критерий готовности

Размещение уходит на портал, содержимое формы верное.

## Ключевые решения

**Документ рождается в транзакции проведения сеанса.** Проведённого сеанса без документа нет,
как и документа без сеанса: `putaway_submit` сохраняет снимок формы `movement` с источником
`putaway` после записи строк, в той же транзакции. Очереди публикации нет — по той же причине,
что у «Поступления»: публикация — запись в ту же базу, идемпотентность дают `operation_id`
и уникальность источника. Каждый сеанс — свой документ: частичное размещение задания даёт
столько документов, сколько было сеансов, — ровно столько физических переносов и было.

**Одна форма на все движения, операция — поле снимка.** `kind = movement`, а размещение,
перемещение и пополнение различаются полем `operation` (сегодня одно значение — `putaway`).
P6 добавит значения, а не шаблоны и не вкладки.

**Строки — через общий разворот (`internal/movement`).** Короб раскладывается по составу,
россыпь проходит как есть, одинаковые товар · партия · откуда · куда складываются в одну строку:
1С коробов не знает. Состав читается в транзакции проведения — размещение меняет место короба,
но не его содержимое, поэтому разворот после записи строк видит ровно то, что переехало.
Порядок строк — откуда, куда, наименование, дата выпуска: оператор заносит перемещение в 1С
парой ячеек, и строки одной пары идут подряд.

**Основание — задание и приёмка, из которой оно родилось.** В шапке: операция, склад, номер
задания, поставщик и его накладная (ADHOC-23), исполнитель, дата по Москве. Поставщик
и накладная лежат в тех же полях снимка, что у «Поступления» (`supplier`, `doc_number`,
`doc_date`): список документов уже их отдаёт, и строка списка «Движения» получает основание
без новой выборки. Каждая строка основания выводится, только если есть: перемещению задание
не обязательно, приёмка бывает без поставщика.

**Обогащение строк справочниками — общее для форм с движением.** Адреса ячеек, код
и наименование товара, дата партии подставляются одной функцией одним запросом на все строки;
«Поступление» перешло на неё же и сортирует строки по-своему. Ячейка-отправитель
необязательна: у прихода её нет, у отгрузки (P9) не будет адресата.

**Миграции нет.** `report_documents.kind` и `source_type` без CHECK-списка — он пополняется
каждой фазой, а снимок — JSON с `omitempty`, прежние документы читаются как были.

**Портал — вкладка «Перемещение» вместо заглушки P6,** по образцу «Прихода»: общая
`DocumentsTab` с формой `movement`. Строка списка: «Движение · Размещение · Задание № … ·
поставщик · № … от … · склад».

## Что сделано

**Сервер (Go)**

| Слой         | Правка                                                                          |
|--------------|---------------------------------------------------------------------------------|
| `model`      | форма `movement`, источник `putaway`, операция; поля снимка и строки списка     |
| `repository` | снимок «Движения» в транзакции `putaway_submit`; общее обогащение строк         |
| `report`     | шаблон `movement_xlsx.go`, ветка в `BuildDocumentXLSX`, имя `dvizhenie-…`       |
| `handler`    | `GET /documents` отдаёт `operation` и `task_number`                             |

**Портал (Flutter)**

| Слой                      | Правка                                                |
|---------------------------|-------------------------------------------------------|
| `portal/data`             | `PortalDoc`: операция и номер задания                 |
| `portal/presentation`     | вкладка документов `movement`, заголовок строки       |
| `assets/i18n`             | строки вкладки                                        |

**Тесты:** шаблон — шапка с основанием и без, таблица, имя файла; репозиторий (testcontainers) —
документ по сеансу (основание, разворот двух коробов с россыпью в одну строку, список, журнал),
документ на каждый сеанс, отклонённый сеанс документа не оставляет; без публикации документа
оба интеграционных теста падают; портал — разбор операции и номера задания.

и накладную; `GET /api/v1/documents/{id}/file.xlsx` → `200`, файл `dvizhenie-<склад>-<дата>.xlsx`
с шапкой и строками «откуда → куда». Затем `make down`, `colima stop`.

## Границы задачи

Перемещение и пополнение (P6) пользуются этой же формой и добавят только значения `operation`.
Отбрасывание «нулевых» строк (откуда = куда) — правило P6-07: у размещения такой строки быть
не может, сервер её отклоняет.
