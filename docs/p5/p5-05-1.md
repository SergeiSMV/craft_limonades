# P5-05-1 · «Остатки» на ТСД: вкладка «Короба», перепечатка ярлыка, история

**Статус:** 🔧 код готов, ждёт проверки на DT50S (`go test ./...` и `golangci-lint` зелёные,
`flutter analyze` 0 issues, полный прогон Flutter-тестов зелёный, релизная APK собирается).
**Категория:** плановая, фаза P5. Закрывает долг 20.

## Задача

В «Остатках» два переключателя, как в «Заданиях», — «Товары» и «Короба». Во вкладке «Короба» —
список коробов на складе, поиск по короткому коду с ярлыка и сканом QR. Карточка короба (общая
с P5-05) получает кнопку «Перепечатать ярлык» и историю: когда и кем короб принят, куда и кем
переносился. Так закрывается контур приёмки: короб с потерянным или испорченным ярлыком можно
найти и снова пометить.

## Критерий готовности

Короб на складе находится по короткому коду или скану, ярлык перепечатывается, история видна.

## Ключевые решения

**Переключатель — тот же, что в «Заданиях».** Неоморфный тумблер «Текущие / Завершённые»
переезжает в `core/widgets` общим переключателем с подписями снаружи; «Задания» и «Остатки»
пользуются одним виджетом. Вкладка «Товары» — нынешний список без изменений.

**Список коробов — из снимка P5-05, работает без связи.** Короб живой — значит виден и офлайн,
и онлайн. Отдельной ручки списка нет: при открытии вкладки и по жесту «потянуть вниз» снимок
обновляется с сервера, затем список читается из него. Без связи — снимок как есть, с подписью
«данные на ЧЧ:ММ». Поверх — короба своих неотправленных приёмок и переносы своих размещений
(наложение P5-05), с пометкой «ожидает отправки». Порядок — по адресу ячейки, внутри ячейки —
по времени создания. Строка: короткий код, ячейка, число позиций. Страниц нет: на масштабе
пилота сотни коробов, список строится лениво.

**Поиск по короткому коду — по вхождению в последние восемь знаков идентификатора.** Ввод
приводится `LoadUnitLabel.normalizeShortCode` (без пробела и дефиса, заглавными) — ярлык
разбит пробелом, и человек набирает так, как видит. Частичный ввод допустим: на мятой наклейке
читается не всё, а восемь знаков не гарантируют уникальности — совпадений бывает несколько,
и выбирает человек.

**Онлайн поиск идёт по всем коробам склада, офлайн — по снимку.** Ярлык перепечатывают как раз
тогда, когда короб «пропал»: он мог появиться после загрузки снимка или выйти из обращения
(пустой, не размещённый). Поэтому со связью поиск спрашивает сервер — новая ручка
`GET /load-units?code=…` по всем коробам, живым и нет; без связи — снимок и своя очередь.
Неживой короб в выдаче помечен. Поиск уходит в снимок не только без связи, а при любом
отказе сервера, кроме истёкшей сессии: старая версия сервера без этой ручки или его сбой не
должны отнимать поиск, когда короба на терминале уже есть (найдено на DT50S против прода,
где ручки ещё не было).

**Скан QR во вкладке открывает карточку**, как в P5-05; скан ячейки — её содержимое.

**Перепечатка — тот же ярлык, что в приёмке, и работает без связи.** Ярлык определяется
идентификатором короба целиком, печать идёт по Bluetooth — сеть не нужна. Пометки «ПРОБНАЯ» нет:
это рабочая наклейка. Перепечатать можно и неживой короб — учёт это не меняет. Принтер не
выбран или недоступен — понятное сообщение, как в приёмке. В журнал печать не пишется: она не
меняет ни остаток, ни место короба.

**История — только со связью.** Журнал `placements` растёт без конца, тащить его на терминал
незачем. Новая ручка `GET /load-units/{id}/history`: создание (когда, кто принял, поставщик
приёмки) и переносы по порядку (откуда → куда, кто, когда, приёмка или размещение) —
с адресами ячеек и ФИО, а не идентификаторами. Без связи блок истории говорит «только со
связью», остальная карточка — из снимка.

**Слои — по `dev.md §2`, в фиче `contents`.** `domain`: сущности истории и строки поиска,
методы репозитория (список, поиск по коду, история), абстракция печати ярлыка — кубит не знает
о принтере. `data`: реализации поверх сети, снимка и `PrinterService`. Вкладка «Короба» —
виджет фичи `contents`; «Остатки» только размещают его рядом со списком товаров.

**Невидимая вкладка ничего не рисует до первого открытия.** Вкладки живут в `IndexedStack`,
и «Короба» строились бы с самого входа в «Остатки» — с крутилкой, которой нечего ждать.
Короба грузятся при первом заходе на вкладку.

**Скан на вкладке «Короба».** QR короба — карточка, этикетка ячейки — её содержимое; прочее
(например, штрихкод товара) — «это не ячейка и не короб». На вкладке «Товары» скан работает как
раньше.

**Списки содержимого — в стиле списка товаров.** Короба (вкладка «Короба», экран «Ячейка»),
россыпь в ячейке и товары в коробе — выпуклые неоморфные плашки со шрифтами вкладки «Товары»
(решение пользователя после проверки на DT50S); у коробов — иконка короба, она отличает их
от товаров в одном списке. Товар — в коробе и россыпью в ячейке — нажимается и открывает
карточку остатков этого товара:
товар целиком берётся из справочника терминала, нет его там — карточка открывается по
идентификатору и наименованию из строки.

**Шапка «Остатков» вынесена в виджет** (`StockHeader`): у вкладок своя строка поиска, и вёрстка
шапки вытесняла из страницы её логику. Поле поиска и переключатель вкладок — общие
(`core/widgets/search_field.dart`, `tab_switch.dart`), подсказка и подписи приходят снаружи.

## Что сделано

**Сервер (Go)**

| Слой | Правка |
|---|---|
| `repository` | поиск коробов по хвосту идентификатора (все, с признаком живого); история короба: создание из приёмки и переносы с адресами и ФИО |
| `model` | строка поиска, история короба |
| `service` | `ContentsService`: поиск (проверка кода — 1…8 шестнадцатеричных знаков), история |
| `handler` | `GET /load-units?code=…`, `GET /load-units/{id}/history` |

**ТСД (Flutter)**

| Слой | Правка |
|---|---|
| `core/widgets` | общий переключатель вкладок (из «Заданий») |
| `features/contents/domain` | история, результат поиска, `ContentsRepository` — список/поиск/история; `LoadUnitLabelPrinter` |
| `features/contents/data` | поиск: сервер → снимок; список из снимка с наложением; история по сети; печать через `PrinterService` |
| `features/contents/presentation` | вкладка «Короба» (поиск, список, скан), кнопка перепечатки и блок истории в карточке |
| `features/stock` | переключатель «Товары / Короба» в «Остатках» |
| `assets/i18n` | строки |

**Тесты:** репозиторий (testcontainers) — поиск живого и неживого короба по хвосту, частичный
код, история с ФИО и адресами; HTTP — ручки и коды ошибок; ТСД — поиск в снимке (частичный ввод,
пробел), выбор источника поиска, список с наложением, перепечатка (успех, принтер не выбран),
история без связи, экраны.

**Проверка на живом DT50S:**

1. «Остатки» → «Короба»: список коробов с ячейками.
2. Набрать 4 знака короткого кода с ярлыка (с пробелом и без) → короб в выдаче.
3. Скан QR короба во вкладке → карточка; «Перепечатать ярлык» → наклейка совпадает с исходной.
4. В карточке — история: приёмка (кто, когда, поставщик) и размещение (откуда → куда, кто).
5. Без Wi-Fi: список и поиск из снимка с подписью «данные на ЧЧ:ММ», перепечатка работает,
   история — «только со связью».
