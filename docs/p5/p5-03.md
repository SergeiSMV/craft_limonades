# P5-03 · ТСД: выполнение задания на размещение, офлайн

**Статус:** ✅ готово (`flutter analyze` 0 issues, полный прогон 493 теста зелёный, релизная APK
собирается; **проверено на живом DT50S против прода**: короб и россыпь размещаются по заданию,
частично и целиком, без связи и со связью; отброшенный чужой сеанс возвращает своё задание в пул).
**Категория:** плановая, фаза P5.

## Задача

Кладовщик берёт задание, сканирует короб или товар из задания и ячейку назначения; партия
и количество россыпи — из задания, без ручного ввода. «Завершить» доступно и при частичном
размещении (остаток возвращается в пул). Сеанс уходит одной операцией через очередь и работает
без связи.

## Критерий готовности

Задание на размещение выполняется на ТСД без связи, в том числе частично.

## Ключевые решения

**Порядок «товар → ячейка».** Каждый перенос заканчивается сканом ячейки: короб — QR, затем
ячейка; россыпь — штрихкод товара, количество, затем ячейка. Положить в «прошлую» ячейку по
забывчивости нельзя — в отличие от порядка «ячейка → товары», где ячейка запоминалась бы.

**Партия и количество — из задания.** Скан товара ищет его среди позиций задания; несколько
партий — кладовщик выбирает из них, одна — сразу количество. По умолчанию предлагается весь
остаток, больше остатка взять нельзя. Ручного ввода даты нет: ошибка в ней отклонила бы на
сервере весь сеанс.

**Что не годится, видно сразу, а не на сервере.** Короб не из задания или уже размещённый,
товар не из задания, скан ячейки без взятого, ячейка приёмки, ячейка другого склада — подсказка
на экране, строка не появляется. Всё это сервер всё равно отклонил бы, но вместе со всем
сеансом.

**Позицию можно взять касанием.** Ярлык короба бывает затёрт, у товара может не оказаться
штрихкода — для этого позиции «Осталось разместить» нажимаются, а ячейку можно выбрать из
справочника. Скан остаётся основным путём.

**Сеанс копится на терминале и уходит одной операцией** `putaway_submit` — как приёмка.
Незавершённый сеанс лежит черновиком и переживает выход с экрана и перезапуск. Черновик один
на терминал: если открыт сеанс по другому заданию, новый не начинается, пока кладовщик не
решит — вернуться или отбросить ту работу.

**Отброшенный сеанс отдаёт своё задание в пул.** Иначе задание оставалось бы «в работе» за
этим кладовщиком и было бы спрятано от остальных до авто-возврата через 8 часов (найдено на
проверке). Отдать задание можно только со связью; без неё кладовщик узнаёт, что оно вернётся
само.

**Без связи размещённое отмечается в снимке заданий.** Сеанс ушёл в очередь, а снимок текущих
прежний — задание показывало бы перенесённое как неразмещённое, и его разместили бы второй раз
(сервер отклонил бы такой сеанс целиком). Поэтому короба отмечаются размещёнными, остаток
россыпи уменьшается, задание возвращается «новым» или уходит из текущих — так же, как сделает
сервер. Следующий удачный запрос заменяет снимок целиком.

**Пустая карточка «в руках» не рисуется.** Подсказку «отсканируйте короб или товар» показывает
поле скана; карточка с той же подсказкой выглядела вторым полем (найдено на проверке).

**Клиентская половина эталона формата.** Тест проходит путь кладовщика — короб → ячейка,
россыпь → количество → ячейка — и сверяет тело операции с `testdata/putaway_submit.json`,
который применяет настоящий роутер сервера.

## Команды проверки критериев готовности

```
cd apps/craft_wms
dart run build_runner build
flutter analyze
flutter test
flutter build apk --release -t lib/main.dart --dart-define-from-file=.env
```

Ожидаемо: `No issues found!`, `All tests passed!`, собранная APK.

**Проверка на живом DT50S:**

1. «Задания» → задание → «Взять в работу» → «Начать».
2. QR короба → этикетка ячейки хранения: короб в «Размещено в этом заходе».
3. Штрихкод товара россыпи → количество меньше остатка → ячейка.
4. «Завершить», подтвердить частичное: «Размещение проведено», задание «новое» в «Текущих».
5. Без Wi-Fi — по остатку: «размещение уйдёт само»; в «Текущих» размещённое отмечено; после
   включения Wi-Fi очередь отправилась.
6. Всё размещено — задание в «Завершённых», в карточке «История выполнения» с заходами.
7. Начатый сеанс по одному заданию, «Начать» по другому → «Отбросить и начать»: первое задание
   стало «новым».

Пройдено.
