# P-FastStart-1 · Быстрый старт: ввод стартовых остатков на реальном складе

**Статус:** ТЗ (планируется; реализация не начата).
**Цель:** за один проход склада с ТСД наполнить стартовые остатки в WMS **и** проверить всю
цепочку на реальном железе (бейдж → скан → API → атомарный остаток → «Остатки»), а также выдать
Excel-документ для ручной сверки с 1С. Фаза `P-FastStart` — в [`plan_v3.docx`](../plan_v3.docx).

> Это рабочее ТЗ, а не производный файл. Первоисточник плана — [`plan_v3.docx`](../plan_v3.docx),
> схема БД — [`data-model.md`](../data-model.md), критерии готовности каждой задачи продублированы
> в её task-doc `docs/p-fs-NN.md`.

## 2. Согласованные решения (A–G + Undo)

| Ключ                    | Решение                                     |
|-------------------------|---------------------------------------------|
| A · Символика ШК ячейки | **Code128**, адрес `M1-1-2-1` как есть      |
| B · Семантика остатка   | **SET по строке** `(ячейка, товар, партия)` |
| C · Дата выпуска        | **обязательный ввод** (партия)              |
| D · Товар без ШК        | ручное добавление из номенклатуры           |
| E · Раскладка PDF       | **A4, 1 колонка × 8 этикеток**              |
| F · Этикетки            | клеятся **впервые** из этого PDF            |
| G · Транспорт           | **online-only** (офлайн — отдельно, P2)     |
| Undo                    | локальный стек **до 10**                    |

Пояснения к неочевидному:

- **B — «плюсование» набирается на ТСД**, в API уходит уже итог по строке.
- **D — товар без ШК** добавляется с количеством и партией, без привязки штрихкода.
- **E — на этикетке** Code128 и адрес, плюс стрелка вниз при `is_floor`; по согласованному образцу.
- **Undo отменяет строку целиком, включая привязку ШК:** поэтому привязка откладывается в буфер
  и коммитится на checkpoint ячейки, а не сразу.

## 3. Модель данных

### 3.1 Новое — слим-схема сессии (одна миграция)

Сессия = один документ «ввод остатков». Строки копятся на ТСД локально, на checkpoint'е ячейки
уходят в сессию (durable), в `stock` пишутся только в финале.

**`stock_entry_sessions`** — шапка документа:
- `id uuid PK`
- `warehouse_id uuid` → `warehouses(id)` — склад прохода
- `created_by uuid` → `users(id)` — кто вводил
- `status text` — `draft` (в работе) / `closed` (финализирована); дефолт `draft`
- `created_at` / `updated_at` / `closed_at`

**`stock_entry_lines`** — строки документа:
- `id uuid PK`
- `session_id uuid` → `stock_entry_sessions(id)` ON DELETE CASCADE
- `cell_id uuid` → `cells(id)`
- `good_id uuid` → `goods(id)`
- `production_date date NOT NULL` — партия
- `qty numeric(20,3) NOT NULL CHECK (qty >= 0)`
- `UNIQUE (session_id, cell_id, good_id, production_date)` — в рамках сессии строка на грань уникальна;
  повторный checkpoint той же грани **перезаписывает** строку (upsert-SET внутри сессии)

Триггер `updated_at` — общий `set_updated_at()`.

### 3.2 Переиспользуемое (без изменений)

- `batches` (`good_id`, `production_date`; `UNIQUE(good_id, production_date)`) — GetOrCreate по грани.
- `stock` (грань `UNIQUE(cell_id, good_id, batch_id)`, `qty`) — финал пишет сюда SET.
- `barcodes` (`good_id`, `barcode UNIQUE`, `symbology`) — привязка ШК.
- `cells` (`address`, `is_floor`) — резолв ячейки + генерация PDF-этикеток.

> ⚠ Измерение «внутренний склад» на `stock` (ADR-0016) в FastStart **не трогаем** — грань остаётся
> `(cell, good, batch)`. Расширение — в приёмке P4.

## 4. Бизнес-процесс ввода остатков

1. Кладовщик входит по бейджу → пункт меню **«Ввод остатков»** → открывается **сессия** (`draft`).
2. **Скан ячейки** (Code128 с наклеенной этикетки) → резолв по `cells.address`. Не распознана →
   выбор из списка (fallback). Ячейка фиксируется в шапке экрана.
3. Определение товара:
   - **скан ШК → найден** (`GET /barcodes/{code}` 200) → товар определён;
   - **скан ШК → не найден** (404) → экран привязки: поиск в номенклатуре → выбор товара →
     **привязка ШК откладывается в локальный буфер** (в `barcodes` попадёт на checkpoint'е);
   - **товар без физического ШК (D)** → ручное добавление из номенклатуры, без привязки.
4. **Дата выпуска — обязательно** (→ партия). Разная дата = **разная строка**.
5. **Количество:** скан-за-сканом (+1) **или** ввод фактического числа. Внутри буфера ячейки строка
   на грань `(товар, партия)` одна — повторные сканы копятся в неё.
6. **Undo** (до 10) — откатывает последнюю операцию буфера **целиком**: и количество, и, если строка
   создала привязку ШК, — привязку. Область Undo — **текущий буфер ячейки до checkpoint'а**.
7. **«Завершить ячейку»** (checkpoint) → буфер (строки + новые привязки ШК) уходит на бэкенд в
   сессию одной транзакцией. После этого строки ячейки «зафиксированы» (Undo их уже не трогает).
8. Переход к следующей ячейке (шаг 2).
9. **«Завершить ввод остатков»** (финал) → бэкенд одной транзакцией пишет все строки сессии в `stock`
   (SET), ставит сессию `closed`. Остатки становятся видны в «Остатках» (P1-07). **(1b)** тут же
   формируется Excel и публикуется документ в портал.

**Разрешение сканов в буфере:** клиент резолвит ШК против **локальных отложенных привязок ∪ сервера**
— чтобы повторный скан свежепривязанного (ещё не закоммиченного) ШК в той же ячейке узнавался.

## 5. Контракты API (под `/api/v1`, ADR-0015)

**Доступ:** поток ввода (сессия, привязка ШК, резолв) — **любой аутентифицированный сотрудник**
(кладовщик проходит склад и привязывает ШК на месте), как read-API P1-06 — **решено**.
Портал/PDF/список документов — **admin-only**.

### Привязка ШК (P-FS-03)
- `GET /barcodes/{code}` → `200 {good}` | `404` (ШК не привязан).
- `POST /barcodes` `{good_id, barcode, symbology}` → привязка; повтор того же ШК идемпотентен;
  привязка занятого ШК к другому товару → `409`.

### Сессия ввода остатков (P-FS-04)
- `POST /stock-entry/sessions` `{warehouse_id}` → `201 {session_id}` (старт, `draft`).
- `POST /stock-entry/sessions/{id}/cells` — **checkpoint ячейки**:
  `{cell_id, lines:[{good_id, production_date, qty}], new_barcodes:[{good_id, barcode, symbology}]}`
  → строки upsert-SET в `stock_entry_lines` (грань `session+cell+good+date`) + новые привязки в
  `barcodes`, **одной транзакцией**. Идемпотентно по грани.
- `POST /stock-entry/sessions/{id}/finalize` → все строки сессии → `stock` (SET через P-FS-02),
  сессия `closed`. Повторный finalize/checkpoint по `closed` → `409`. **(1b)** формирует Excel-документ.

### Остаток (P-FS-02, внутренний слой)
- `batch` GetOrCreate(`good_id`, `production_date`).
- Атомарный **SET** остатка грани `(cell, good, batch)` — приводит к заданному `qty` (не прибавляет);
  на атомарном SQL в стиле P1-03; `qty ≥ 0`.

### PDF-этикетки (P-FS-05/06)
- `GET /cells/labels.pdf?warehouse=SHB` (admin) → A4-PDF (см. §6).

### 1b — документы
- `GET /stock-entry/documents` (admin) → список `{id, warehouse, created_at, mark:"ввод остатков", lines_count}`.
- `GET /stock-entry/documents/{id}.xlsx` (admin) → скачивание Excel.

## 6. PDF-этикетки ячеек (P-FS-05)

- **Формат:** A4, портрет, **1 колонка × 8 этикеток на лист**, полосы во всю ширину, пунктирные
  линии реза между этикетками.
- **Этикетка:** слева **Code128** (кодирует `address`), справа крупный жирный адрес; при
  `is_floor=true` — **стрелка вниз** справа от адреса. Больше на этикетке ничего.
- **Состав/порядок:** все активные ячейки склада, **натуральная сортировка** по числовым сегментам
  адреса (`M1-1-2-1` раньше `M1-1-10-1`). Пропуски адресов — норма (генерим по факту `cells`).
- **Реализация:** Go — `go-pdf/fpdf` + `boombuler/barcode` (Code128 → image). Стрелку рисуем
  **вектором** (fpdf-примитивы), не глифом шрифта.
- **Гейт:** образец согласован (1×8, только адрес+ШК+стрелка). Соответствие образцу — критерий.

## 9. Границы (решено)

- **Не заменяет полный P10** — FastStart бутстрапит стартовые остатки и валидирует железо;
  циклический пересчёт со сверкой «ожидалось/факт» — остальной P10.
- **Корректировка уже закоммиченной ячейки** (после checkpoint'а) в MVP **не предусмотрена** — Undo
  покрывает только текущий буфер. При необходимости — отдельным улучшением.
- **Привязка ШК доступна кладовщику (employee)** на проходе — **решено**.
- **Товары без ШК** заносятся вручную; генерация внутренних EAN-13 (вопрос №4) — вне FastStart.
