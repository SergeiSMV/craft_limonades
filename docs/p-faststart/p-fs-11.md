# P-FS-11 · Модель привязки ШК при вводе остатков: несколько ШК на товар

**Статус:** готово (ветка `p-fs-11-barcode-binding-model`); ⚠ вживую на DT50 ещё не проверял.
**Фаза:** P-FastStart (доработка потока ввода остатков P-FS-07). ТЗ — [`p-faststart-1.md`](p-faststart-1.md).

## Задача

Поток ввода остатков терял часть штрихкодов: у товара может быть несколько разных ШК (на штуке и на
коробе — они не совпадают), а старая модель хранила ШК **на строке буфера** с гранью `(товар, дата)`.
Второй ШК того же товара с той же датой в одну строку не помещался — молча терялся при слиянии, не
узнавался на повторном скане (снова спрашивал привязку) и не попадал в БД на финале.

Требование пользователя: разные ШК на одной позиции — обязательны (короб не вскрываем — сканируем ШК
короба и вводим количество в штуках руками); ШК должны узнаваться независимо от их числа на товар;
после финала **все** отсканированные ШК попадают в БД и привязываются к товарам.

## Критерий готовности

Сколько бы разных ШК ни привязали к одному товару за проход — каждый узнаётся при повторном скане
локально (без 404), и все привязки уходят в БД на финале (аддитивно). Количество — всегда в базовой
единице товара, вводится вручную (ШК только идентифицирует товар, множителя упаковки нет — вариант A).

## Решение (модель)

- **`ШК → товар` — факт справочника (уровень товара), а не свойство строки остатка/партии/количества.**
  У товара сколько угодно ШК; все равноправны и лишь **идентифицируют** товар. Бэкенд это уже умел
  (таблица `barcodes`: `barcode` UNIQUE → один `good_id`; `Bind` аддитивен, P-FS-03) — **схему БД и
  бэкенд не трогали, изменения только в клиенте**.
- **Количество — вариант A:** ШК-псевдоним без вложенности. Скан короба и скан штуки одинаково ведут к
  товару, итог в базовой единице вводит оператор. Выбор пользователя: на текущем этапе нужна только
  идентификация, лишнего взаимодействия с 1С (справочник упаковок) не хотим до реального API.

## Что сделано (client-only)

- **`stock_entry_cubit.dart`:**
  - `EntryLineDraft` — убраны поля `bindBarcode`/`bindSymbology`; строка теперь чисто
    `(good, productionDate, qty)`.
  - Новый `BarcodeBinding` (`good` + `symbology`) и **копилка `Map<String, BarcodeBinding> barcodes`**
    в `StockEntryState` — собирается за **весь проход** (ключ — строка ШК, дубли исключены по
    построению), независима от строк остатка.
  - `localGoodForBarcode(code)` — теперь смотрит в копилку (`state.barcodes[code]?.good`) вместо
    перебора строк; узнаёт любой уже привязанный за проход ШК, сколько бы их ни было на товар.
  - `addLine(...)` — параметр `newBarcode`/`symbology`: новый (ранее не привязанный) ШК кладётся в
    копилку одновременно с добавлением строки. Слияние строк по грани `(товар, дата)` больше **не** несёт
    ШК → второй/третий ШК не теряется.
  - **Undo** — снимок (`BufferSnapshot`) теперь включает и строки, и копилку ШК: отмена откатывает и
    ошибочную привязку, а не только количество. `removeLine`/`editLine` привязку не трогают
    (идентификация валидна и без строки количества).
  - `finishSession` — вся копилка уходит `new_barcodes` с **первым** checkpoint (bind идемпотентен; при
    ретрае цикл снова стартует с первой ячейки → пере-отправка). `_barcodesPayload()` строится из карты,
    а не из строк ячейки.
- **`stock_entry_screen.dart`:** `_onScan` — резолв «копилка → сервер → ручная привязка (`newBarcode`)»;
  `_collectAndAdd(good, {newBarcode})`; убрана иконка ШК на строке (`_LineTile`) — строка ШК больше не
  носит.
- **Ввод даты (`date_input.dart`) — двузначный или четырёхзначный год.** В диалоге даты+количества
  дату можно ввести и как `14.08.2026`, и как `14.08.26`; на выходе всегда `дд.мм.гггг`. Форматтер
  авто-точек уже поддерживал 6 цифр (`140826` → `14.08.26`); `isValidEntryDate` расширен на `дд.мм.гг`
  (двузначный год → 20YY), добавлен `normalizeEntryDate` (приводит к 4-значному), `_DateQtyDialog._submit`
  нормализует значение перед возвратом. Хинт поля — `дд.мм.гг(гг)`.

## Проверка

- `flutter analyze` — **No issues**.
- Тесты (`test/features/stock_entry/stock_entry_cubit_test.dart`, обновлены + добавлены):
  - **несколько разных ШК на один товар (штука + короб)** — обе привязки уцелели, обе узнаются, строки
    слились по грани (10 + 120 = 130), `state.barcodes.length == 2`;
  - **undo откатывает привязку ШК**, не только количество;
  - `localGoodForBarcode` из копилки; `finishSession` — вся копилка (3 разных ШК) уходит с первым
    checkpoint, у последующих ячеек `new_barcodes` пуст.
- Тесты даты (`date_input_test.dart`): 2-значный год валиден (`15.01.26`, `29.02.24`→2024 високосный),
  `29.02.26` невалиден (2026 не високосный), 3-значный год невалиден; форматтер 6 цифр → `дд.мм.гг`;
  `normalizeEntryDate` приводит 2-значный год к 20YY, 4-значный не трогает.
  - Полный прогон — **62 теста зелёных** (регрессий нет).
- **Сборка ТСД-APK** `flutter build apk --release -t lib/main.dart --dart-define-from-file=.env` —
  зелёная (гейт компиляции точки входа).

## Границы

- Только клиент: без миграций, без правок бэкенда, без нового формата импорта из 1С.
- Множитель упаковки (короб = N штук с авто-умножением) — **сознательно не делаем** (вариант B отклонён
  на этом этапе). Вернуться при реальном API 1С / появлении справочника упаковок — потребует `+1`
  колонку `units_per_pack` в `barcodes` и шаг в диалоге привязки.
- Durability прохода до финала — по-прежнему вне объёма (P2, офлайн-ядро).
