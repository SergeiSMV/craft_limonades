# P-FS-07 · Flutter ТСД: поток ввода остатков

**Статус:** готово (ветка `p-fs-07-tsd-stock-entry-flow`); ⚠ вживую на DT50 ещё не проверял.
**Фаза:** P-FastStart (волна 1a — **завершающая задача**). ТЗ — [`p-faststart-1.md`](p-faststart-1.md).

## Задача

Экран ТСД для прохода склада: скан ячейки → скан/выбор товара (с привязкой ШК) → дата+количество →
буфер с Undo → завершение ячейки (checkpoint) → завершение ввода (finalize). Online, без Outbox.

## Критерий готовности

Кладовщик проходит цикл целиком: вход → «Ввод остатков» → скан ячейки (резолв/список) → определение
товара (ШК найден / привязка при не найденном / ручное добавление без ШК) → дата выпуска + количество
(скан +1 / ручной ввод) → Undo до 10 → «завершить ячейку» (checkpoint) → «завершить ввод остатков»
(финал); online; остаток появляется в «Остатках» после финала. Проверено на реальном DT50.

## Что сделано

- **`ApiConst`**: `cells`, `barcodeByCode(code)`, `stockEntrySessions`, `stockEntryCells(id)`,
  `stockEntryFinalize(id)`.
- **`catalog_models`/`catalog_repository`**: модель `Cell` + `listCells({query, warehouseId})` (резолв
  ячейки по адресу / выбор из списка).
- **`features/stock_entry/data/stock_entry_repository.dart`** (`@lazySingleton`): `resolveGoodByBarcode`
  (404 → `Right(null)` — «нужна привязка», не ошибка), `startSession`, `checkpoint`, `finalize`.
- **`features/stock_entry/presentation/stock_entry_cubit.dart`** (`@injectable` + freezed) — **вариант A
  (всё локально до финала)**:
  - `EntryLineDraft` — строка буфера, **грань `(good, productionDate)`** (один товар разными партиями
    = разные строки); опц. `bindBarcode` для попутной привязки ШК.
  - `CommittedCell` — пройденная ячейка со своими строками (держится **локально** до финала).
  - `selectCell` — **без сети**; если ячейка уже пройдена — открывает её на редактирование (строки
    возвращаются в буфер, ячейка убирается из списка пройденных).
  - `resolveBarcode` → `Good?` (null = не привязан); `localGoodForBarcode` ищет привязку по **всем**
    ячейкам (буфер + пройденные), чтобы повторный скан свежепривязанного ШК узнавался локально.
  - `addLine` / `editLine` / `removeLine` — та же грань → +qty; правка/слияние/удаление; каждый шаг —
    снимок буфера в стек **Undo (≤10)**. `undo` — восстановление буфера.
  - `finishCell` — **локально** кладёт ячейку в список пройденных (пустую не добавляет).
  - `removeCommittedCell` — удаление ошибочной ячейки из списка.
  - `finishSession` — вся сеть разом: **старт сессии → checkpoint каждой ячейки → finalize**; при
    ошибке прерывается, `sessionId` переиспользуется на ретрае. Даты `дд.мм.гггг` → `DD-MM-YYYY` в payload.
- **`features/stock_entry/presentation/stock_entry_screen.dart`** (`@RoutePage`): один экран-поток —
  выбор ячейки (скан-поле `TextInputType.none` + «выбрать из списка») со **списком пройденных ячеек**
  (тап — редактировать, долгое нажатие — «Редактировать/Удалить ячейку») и кнопкой «Завершить ввод»
  внизу → работа с ячейкой (скан товара, «добавить вручную», список строк новейшие-сверху, долгое
  нажатие по строке — «Редактировать/Удалить», Undo, «Завершить ячейку») → финальный экран. Подпотоки:
  привязка ШК при 404, `_GoodPickerSheet`/`_CellPickerSheet` (поиск+дебаунс, `Flexible`-список без
  оверфлоу под клавиатурой), `_DateQtyDialog` (`scrollable`, авто-точки `дд.мм.гггг` + валидация,
  без префилла). Busy-оверлей, снекбар ошибок.
- **`date_input.dart`**: `DateTextInputFormatter` (авто-точки `дд.мм.гггг`) + `isValidEntryDate`.
- **`stock` (P1-07)**: `stock_detail_screen` — дата партии показывается `дд.мм.гггг` (`_batchDate`).
- **Проводка**: маршрут `StockEntryRoute` (auto_route, под `AuthGuard`); **плитка «ВВОД ОСТАТКОВ»** в
  главном меню + вход из списка «Остатки»; i18n-секция `stock_entry`.

## Решения

- **Вариант A — всё локально до финала** (осознанное решение): пройденные ячейки редактируемы/удаляемы,
  на сервер уходят одним пакетом при «Завершить ввод». Даёт правку ошибочно просчитанных ячеек без
  правки бэкенда. Плата — **нет durability до финала** (полноценно — в P2, офлайн-ядро). Бэкенд не менялся:
  каждая ячейка checkpoint'ится один раз в чистую сессию.
- **Один экран со стейт-машиной** — проще Undo/буфер/список ячеек, чем набор маршрутов.
- **Грань `(товар, дата)`** — в ячейке один товар может лежать разными партиями; совпадает с гранью
  бэкенда `UNIQUE(session,cell,good,date)`.
- **Привязка ШК откладывается в строку** и уходит `new_barcode` в checkpoint — Undo откатывает её
  локально; резолв по всем локальным ячейкам до сервера.
- **Дата: ввод `дд.мм.гггг`** (авто-точки, без календаря); формат живёт только в UI, на границе API —
  `DD-MM-YYYY` (P-FS-04). Дата в карточке остатков — тоже `дд.мм.гггг`.
- **Скан-поле товара — `TextInputType.none`**: аппаратный сканер DT50 заполняет поле, софт-клавиатура
  не всплывает (после «Добавить»/скана возвращаем фокус без клавиатуры).
- **online-only** — без Outbox (P2); после финала данные видны в «Остатках» (P1-07).

## Проверка

- `flutter analyze` — **No issues**.
- Тесты (`test/features/stock_entry/`):
  - **cubit** (mocktail): грань — та же дата накапливает, **другая партия → новая строка**; Undo/
    `removeLine`/`editLine`(+слияние); `localGoodForBarcode`; `selectCell`/`finishCell` **без сети**;
    редактирование/удаление пройденной ячейки; `finishSession` = старт → checkpoint каждой ячейки →
    finalize (даты `DD-MM-YYYY`, уникальные ШК); `date_input` (авто-точки/валидация).

  **зелёная** (гейт компиляции точки входа).
