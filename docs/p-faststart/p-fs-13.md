# P-FS-13 · Неоморфизм «Остатков» + общепроектная структура page/bloc/widgets

**Статус:** ✅ влито в `dev` (PR #65/#66, ветка `p-fs-13-stock-ux-polish`).
**Фаза:** P-FastStart (UX-полировка + структурный рефактор). Дизайн-стиль — неоморфный (см. [`architecture.md`](../architecture.md), «Визуальный стиль»).

## Задача

Освежить UI «Остатков» (неоморфизм по макету), а по ходу — навести порядок в структуре presentation
и закрепить проектные соглашения (раскладка каталогов, порог размера файла, единый дизайн).

## Что сделано

### UI «Остатки» — неоморфизм
- Пакет **`flutter_neumorphic_plus`** (обкатанный форк; выбран после ревью — не niche-библиотеку).
- Токены `AppColors.kNeumorphic*` (фон `kNeumorphicBg`, светлая/тёмная тени); фон-подложка экрана,
  вдавленное поле поиска, выпуклые кнопки фильтра и плитки списка.
- Экран «Остатки» разбит на виджеты: `GoodsResult`, `ActiveChips`, `FilterButton`, `ErrorRetry`.
- Общий `PageHeader` вынесен в `core/widgets`, экраны переведены на него.

### Общепроектная миграция структуры (эталон — фича `stock`)
Внутри `presentation/` раскладка `{pages, bloc, widgets}`:
- `pages/` — `*_page.dart`, классы `XxxPage` (`@RoutePage`). **`page`, а не `screen`** — общепроектно
  (auto_route срезает суффикс `Page`/`Screen`, имя маршрута `XxxRoute` не меняется).
- `bloc/` — cubit/bloc (имя папки `bloc` даже для Cubit).
- `widgets/` — вынесенные виджеты; общие для нескольких страниц → `widgets/common/`, страничные → подпапка.
- Мигрированы **все фичи ТСД** (auth/debug/home/splash/stock/stock_entry) **и портал** (login→page,
  shell, `widgets/{tabs,common}`). `date_input.dart` → `core/utils`; общий `fmtQty` → `core/utils`.

### Декомпозиция `stock_entry_page` (1038 → 96 строк)
Вынесены в `widgets/`: `cell_entry_view`, `cell_select_view`, `date_qty_dialog`, `good_picker_sheet`,
`cell_picker_sheet`, `line_tile`, `finished_view`, `committed_cell_tile`, `failure_text`.

### Ревью-фиксы и чистота
- `ErrorRetry.onRetry`/`GoodsResult.retryLoad`: `watch` вне build → `read` (рабочий «Повторить»).
- Относительные импорты к core (без смешивания с `package:`), `const`-конструкторы, фигурные скобки в
  `if`, магические числа → `AppSizes`.
- **`///`-комментарии** ко всем логическим методам и хендлерам, где их не было (кроме lifecycle-оверрайдов
  и тривиальных геттеров — по договорённости).

### Соглашения зафиксированы в [`architecture.md`](../architecture.md)
Структура `presentation/{pages,bloc,widgets}`; `page` вместо `screen`; порог-запах ~200–250 строк
(генерённые файлы вне счёта); **дизайн опирается на уже реализованное — при неоднозначности сверяться
с эталонными экранами, а не изобретать свой стиль**; глубина относительных импортов к `core`.

## Решения
- **Не niche-пакет для неоморфизма**, а `flutter_neumorphic_plus`; выпуклые элементы можно и на native
  `BoxShadow`, но пакет даёт inset-состояния и единообразие.
- **`page` — общепроектное имя** (не только для `stock`); маршруты auto_route при переименовании целы.
- **Порог 200–250 строк — ориентир, не догма**; связный виджет чуть за порогом не дробим искусственно.
- Дизайн ещё формируется пользователем — вёрстка сверяется с эталонными окнами.

## Проверка
- `flutter analyze` — **No issues**; `flutter test` — все зелёные (структурный рефактор без регрессий).
- Сборки **APK (ТСД) и web (портал)** — зелёные (миграция не сломала оба приложения).
- Маршруты auto_route регенерированы, DI (injectable) — целы.

## Границы
- Presentation-слой + соглашения; домен/данные/бэкенд не менялись.
- Дальнейшая UX-доводка потока «Ввод остатков» — отдельной задачей (P-FS-14).
- Портал на проде обновляется вручную (не под CD) — как и прежде.
