# P-FS-16 · Поиск товара по штрихкоду в «Остатках» (ТСД)

**Статус:** готово (ветка `p-fs-16-stock-barcode-search`); ⚠ сквозной тест сканером на DT50 ещё не прогонял.
**Фаза:** P-FastStart (доработка раздела «Остатки» после P-FS-15).

## Задача

Не заставлять кладовщика набирать наименование: отсканировать товар в строке поиска «Остатков»
и сразу попасть в его карточку остатков.

## Почему этого не было

Плитка «НАЙТИ — поиск товара по ШК» есть в главном меню ТСД с P1-07, но стоит заглушкой:
на тот момент таблица `barcodes` была пуста — привязывать ШК было нечем. Данные появились
только с P-FS-11/12, где кладовщик привязывает ШК прямо на проходе склада.

Вторая причина: `GET /goods?q=` ищет `ILIKE` только по `name` и `code` (`catalog_read.go`),
штрихкоды в этот поиск не входят — отсканированный код просто не находился.

## Решения

- **«Если к ШК привязан один товар» — ветвление не нужно.** `barcodes.barcode` объявлен
  `NOT NULL UNIQUE` (миграция `000003`), поэтому один штрихкод всегда указывает ровно на один
  товар. Обратное неверно: у товара может быть несколько ШК — штука и короб (P-FS-11).
- **Скан от набранного текста отличаю по форме ввода:** только цифры и не меньше 8 знаков → это
  штрихкод, иначе обычный поиск подстрокой. Без такой проверки поиск по названию каждый раз
  упирался бы в «ШК не найден».
- **Плитка «НАЙТИ» в главном меню пока остаётся заглушкой** — решил не трогать в этой задаче.
| Изменения в API | Не требуются: `GET /api/v1/barcodes/{code}` есть с P-FS-03 |

## Что сделано

- **`CatalogRepository.resolveGoodByBarcode(code)`** поверх `GET /api/v1/barcodes/{code}`:
  товар либо `Right(null)` на 404 («ШК не привязан» — штатный исход, не ошибка). Такой метод
  уже был в `StockEntryRepository`, но фича `stock` не должна зависеть от `stock_entry`.
- **`GoodsListCubit.resolveBarcode(code)`** — резолв через репозиторий; сетевую ошибку кладёт
  в state (`status: error`), чтобы её показал общий блок ошибки списка, а не молчаливое
  «не найдено».
- **`core/utils/barcode.dart` `looksLikeBarcode()`** — цифры длиной от 8 (EAN-8/EAN-13 и числовые
  Code128). Отдельной функцией, потому что то же правило понадобится плитке «НАЙТИ».
- **Строка поиска «Остатков»** — обработчик `onSubmitted` (HID-сканер шлёт строку целиком и Enter;
  на софт-клавиатуре это «Поиск», `textInputAction: TextInputAction.search`):
  - похоже на ШК и он привязан → чистим строку поиска, гасим клавиатуру, открываем карточку товара;
  - похоже на ШК, но он не привязан → `SnackBar` «ШК … не привязан ни к одному товару»;
  - не похоже на ШК → обычный поиск подстрокой, **сразу**, без ожидания дебаунса.
  Отложенный дебаунс при submit отменяется — иначе после скана уходил бы ещё и бесполезный
  поиск по наименованию.
- Строка поиска чистится при переходе в карточку по скану: HID-сканер дописывает ввод в поле,
  и следующий скан склеился бы с предыдущим кодом.
- i18n: `stock_list_screen.barcode_not_found`.

## Границы

- Backend не затронут — эндпоинт `GET /api/v1/barcodes/{code}` существует с P-FS-03, миграций нет.
- Переход в карточку по успешному скану виджет-тестом не покрыт: навигация идёт через
  `auto_route`, которому нужен полноценный роутер. Логика этого пути покрыта на уровне cubit'а
  и репозитория; сквозную проверку сканером на DT50 ещё не прогонял.
- Плитка «НАЙТИ» в главном меню остаётся заглушкой.
