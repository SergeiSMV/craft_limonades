# P0-01 · Каркас и инфраструктура

**Статус:** ✅ завершена (проверено локально на Colima)
**Задача:** Монорепо + docker-compose (postgres + backend + nginx), `.env`, healthcheck.
**Критерий готовности:** `docker compose up` поднимает стек; бэкенд доступен через nginx.

Общая архитектура проекта — в [architecture.md](../architecture.md).

---

## Что сделано

| Артефакт                          | Назначение                                                                  |
|-----------------------------------|-----------------------------------------------------------------------------|
| `infra/docker-compose.yml`        | Стек из 3 сервисов (db + backend + nginx), healthcheck'и, `service_healthy` |
| `infra/nginx/nginx.conf`          | Reverse proxy → backend; единственная точка входа снаружи                   |
| `apps/backend/Dockerfile`         | Multistage-сборка Go (builder → alpine), запуск от non-root                 |
| `apps/backend/.dockerignore`      | Исключения из build-контекста                                               |
| `apps/backend/cmd/server/main.go` | Минимальный HTTP-сервер с `/health` (полный скелет — в P0-02)               |
| `apps/backend/go.mod`             | Модуль `craftwms`, Go 1.25                                                  |
| `.env` / `.env.example`           | Настройки и секреты (`.env` — в `.gitignore`)                               |
| `Makefile`                        | Обёртки `make up / down / logs / ps / build / restart`                      |

### Ключевые решения

- **Backend наружу не публикуется** — доступ только через nginx (порт `HTTP_PORT`, по умолчанию `8080`). Наружу торчит одна точка входа.
- **Точка входа — `make up`**, а не голый `docker compose up`: compose-файл лежит в `infra/`, а `.env` — в корне, поэтому оба пути передаются флагами (`--env-file .env -f infra/docker-compose.yml`).
- **Healthcheck'и обращаются к `127.0.0.1`, а не `localhost`** — внутри контейнера `localhost` может резолвиться в IPv6 `::1`, где nginx (`listen 80;`) не слушает → «connection refused».
- **Зависимости по здоровью:** backend стартует после «живой» БД, nginx — после «живого» backend (`condition: service_healthy`).

## Требования к окружению

- Docker с работающим демоном. Локально — Colima:
  ```bash
  colima start          # поднять docker-демон на macOS
  docker info           # проверить, что демон отвечает
  ```
- Плагин `docker compose` (при установке через Homebrew подключается симлинком):
  ```bash
  mkdir -p ~/.docker/cli-plugins
  ln -sfn /opt/homebrew/opt/docker-compose/bin/docker-compose ~/.docker/cli-plugins/docker-compose
  docker compose version
  ```
- Первый запуск: скопировать шаблон окружения:
  ```bash
  cp .env.example .env
  ```

## Запуск и остановка

```bash
make up      # собрать образы и поднять стек в фоне
make ps      # статус контейнеров и healthcheck
make logs    # логи всех сервисов (follow)
make down    # остановить и удалить контейнеры (данные БД сохранятся в volume infra_db_data)
```

Дополнительные варианты остановки:

```bash
# Пауза без удаления контейнеров (быстрее поднять обратно через make up)
docker compose --env-file .env -f infra/docker-compose.yml stop

# Полное удаление вместе с данными БД (volume infra_db_data тоже)
docker compose --env-file .env -f infra/docker-compose.yml down -v

# Остановить сам Docker-демон (Colima), когда работа закончена совсем
colima stop
```

Для обычного «выключить стек» достаточно `make down`.

## Проверка критериев готовности

### 1. Валидация compose (без запуска)

```bash
docker compose --env-file .env -f infra/docker-compose.yml config >/dev/null && echo "config OK"
```
Ожидаемо: `config OK` — синтаксис и подстановка переменных валидны.

### 2. Стек поднят и все контейнеры «живы» (healthy)

```bash
make up
make ps
```
Ожидаемо: три контейнера в статусе `Up ... (healthy)`:

```
NAME              SERVICE   STATUS                 PORTS
infra-db-1        db        Up ... (healthy)       0.0.0.0:5432->5432/tcp
infra-backend-1   backend   Up ... (healthy)       8080/tcp
infra-nginx-1     nginx     Up ... (healthy)       0.0.0.0:8080->80/tcp
```

### 3. Бэкенд доступен через nginx (главный критерий)

```bash
curl -s -w "\nHTTP %{http_code}\n" http://localhost:8080/health
```
Ожидаемо:
```
{"status":"ok"}
HTTP 200
```

### 4. Backend напрямую наружу не опубликован

```bash
docker compose --env-file .env -f infra/docker-compose.yml ps backend
```
Ожидаемо: в колонке `PORTS` у `backend` — только `8080/tcp` (внутренний), без `0.0.0.0:...->`. Наружу его порт не проброшен; доступ идёт через nginx.

### 5. Проверка healthcheck отдельного сервиса (диагностика)

```bash
docker inspect --format '{{.State.Health.Status}}' infra-nginx-1
docker inspect --format '{{range .State.Health.Log}}exit={{.ExitCode}} :: {{.Output}}{{end}}' infra-nginx-1 | tail -1
```
Ожидаемо: `healthy`; последний лог с `exit=0`.
