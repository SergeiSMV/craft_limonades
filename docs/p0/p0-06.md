## Что сделано

- **`lib/core/auth/token_storage.dart`** — `SecureTokenStorage` поверх `flutter_secure_storage`,
  дефолтная реализация `TokenStorage` (Android Keystore). `InMemoryTokenStorage` оставил
  для unit-тестов (P0-08) и снял с DI.
- **`lib/core/auth/auth_repository.dart`** — `hasSession()`: есть ли токен в хранилище.
  Нужен для тихого старта без лишнего запроса.
- **`lib/core/auth/auth_cubit.dart`** — `restore()`: тихое восстановление сессии при старте.
  Есть токены → `/auth/me`; интерсептор сам обновит access по refresh.
- **`lib/main.dart`** — вызов `AuthCubit.restore()` после сборки DI; состояние драйвит навигацию.
- **`lib/features/auth/presentation/login_screen.dart`** — переработан в **ожидание скана**:
  автофокусное поле ловит ввод HID-сканера (16 цифр + Enter), автосабмит при 16 цифрах,
  крупная подсказка, понятные ошибки, индикатор на время входа.
- **`lib/features/splash/presentation/splash_screen.dart`** — заставка, стартовый маршрут.
  Показывается, пока `restore()` проверяет сессию, чтобы при активной сессии не мелькал экран входа.
- **`lib/core/router/app_router.dart`** — `SplashRoute` как начальный маршрут (`initial: true`)
  вместо `LoginRoute`.
- **`assets/i18n/ru.i18n.json`** — строки экранов входа и заставки: подсказка скана, состояние
  входа, типизированные ошибки.
- **`lib/core/constants/app_sizes.dart`** — `kIcon96`, крупная иконка сканера.
- **`pubspec.yaml`** — `flutter_secure_storage: ^10.3.1`.

### Ключевые решения

- **Контракт бейджа не менялся:** клиент шлёт **полные 16 цифр** в `/auth/login`; разрез `login`(8)+`secret`(8) делает бэкенд (P0-04). Клиент лишь валидирует «ровно 16 цифр».
- **Сканер — заглушка (по P0-07):** одно автофокусное поле работает и как приёмник HID-сканера ТСД (цифры + Enter), и как ручной ввод на эмуляторе. Автосабмит при наборе 16 цифр или по Enter. Полноценная интеграция сканера — **P2-01**.
- **Secure storage:** `flutter_secure_storage` **v10** — на Android шифрует ключами из Keystore по умолчанию (параметр `encryptedSharedPreferences` в v10 deprecated и не нужен). Взята v10 (а не 9.x) из-за конфликта транзитивной зависимости `win32` с `share_plus` (тянет `talker_flutter`).
- **Восстановление сессии / авто-рефреш:** при старте `restore()` — нет токенов → сразу на вход; есть → `/auth/me`, при 401 интерсептор молча обновляет access по refresh и повторяет запрос. Refresh протух → интерсептор чистит хранилище → экран входа.
- **Стартовая заставка (splash):** начальный маршрут — `SplashRoute`, а не логин. Пока `restore()` проверяет сессию (state `unknown`), видна нейтральная заставка; `BlocListener` в `app.dart` уводит дальше по резолву (authenticated → меню, unauthenticated → вход). Так при активной сессии нет мелькания «логин → меню» на холодном старте.
- **Офлайн («мягкий режим»):** при старте без сети токены **не чистятся** (интерсептор чистит только на 401, не на сетевой ошибке) — остаёмся на входе с сообщением «нет связи»; при следующем онлайн-старте сессия восстановится. Полный офлайн-режим с кэшем профиля — **P2**.
- **In-memory стор** сохранён в коде (без DI-регистрации) для будущих unit-тестов интерсептора/репозитория/кубита (P0-08).

## Поток входа и восстановления

```
СТАРТ приложения (виден splash, экран входа не мелькает):
  main() → restore():
    нет токенов в secure storage ─────────────► экран входа (ожидание скана)
    есть токены → GET /auth/me
        200 ──────────────────────────────────► главное меню (сессия восстановлена)
        401 → интерсептор: POST /auth/refresh
              новый access ─► повтор /auth/me → 200 ─► главное меню (тихо продлили)
              refresh протух ─► чистим хранилище ──► экран входа
        нет сети ──────────────────────────────► экран входа («нет связи»), токены сохранены

ВХОД по скану:
  16 цифр (сканер/ручной ввод) → POST /auth/login → { access, refresh } → secure storage
  → GET /auth/me → профиль → главное меню
```

## Запуск и проверка критериев готовности

### 1. Статический контур (главный, воспроизводимый без стенда)

```bash
cd apps/craft_wms
dart run build_runner build --delete-conflicting-outputs   # после правок аннотаций/i18n
flutter analyze                                            # No issues found!
flutter build apk --debug                                  # ✓ Built …/app-debug.apk
```
Проверка minSdk в APK: `minSdk = 30` в `android/app/build.gradle.kts` (Android 11).

### 2. Полный цикл: вход через бэкенд + персистентность сессии

**a. Старт бэкенда** (из корня проекта):
```bash
colima start
make up && make migrate-up && make seed    # стек + схема + админ (ADMIN_BADGE)
```

**b. Запуск приложения.** Адрес бэкенда через `--dart-define`:
- **эмулятор** — дефолт `http://10.0.2.2:8080` (localhost хоста);
- **реальный ТСД/телефон** — LAN-IP Mac: `--dart-define=BASE_URL=http://<IP-Mac>:8080` (устройство и Mac в одной сети).
```bash
cd apps/craft_wms
flutter run --dart-define=BASE_URL=http://<IP>:8080
```
В приложении: отсканировать/ввести бейдж `1000000012345678` → автосабмит → меню (логин `10000000`, роль `admin`).

**c. Проверка авто-восстановления сессии:** закрыть и снова открыть приложение (или `q` в `flutter run`, затем повторный запуск) — **вход не запрашивается**, сразу главное меню (токены прочитаны из secure storage, access продлён при необходимости). «Выход» в меню чистит хранилище → следующий старт требует скан.

**d. Остановка (возврат к исходному):**
```bash
# в терминале flutter run — q
make down          # стек (из корня); данные БД сохранятся в volume
colima stop        # остановить docker-демон
```

## Границы задачи

- Скан — **заглушка** (автофокусное поле, ловит HID-ввод и ручной ввод); нативная интеграция сканера ТСД — **P2-01**.
- Офлайн-вход — «мягко»: токены переживают офлайн-старт, но экраны работы в офлайне и кэш профиля — **P2**.
- Проверка на реальном Urovo DT50 (права, кнопка сканера, вёрстка узкого экрана) — **P0-07**.
- Unit-тесты (`AuthInterceptor`, `AuthRepository`, `AuthCubit`) — **P0-08** (там же CI).

### ⚠️ Режим вывода сканера на Urovo DT50 (важно для P0-07/P2-01)

По умолчанию сканер DT50 отдаёт декодированный ШК **через broadcast Intent** сервису сканера (`com.ubx.uscanner`), а **не** печатает в фокусное поле — при скане слышен писк, но поле не заполняется. Заглушка P0-06 рассчитана на ввод «как с клавиатуры».

- **Интерим (проверено вживую):** в настройках сканера DT50 (`com.ubx.barcodescanner.tool`) переключить режим вывода **Intent → «Клавиатура» (Simulate keystroke / Fill in EditText)** — тогда скан заполняет поле, вход работает.
- **Правильное решение — P2-01:** нативный `BroadcastReceiver` UROVO ScanManager через platform-channel, чтобы приложение принимало скан независимо от настроек устройства (не зависеть от ручной конфигурации ТСД). Связано с открытым вопросом заказчика №7 (вариант ТСД DT50S/DT50P).
