# P0-05 · Flutter-скелет (Android/ТСД)

**Статус:** ✅ завершена (APK собран под Android 11, minSdk 30 подтверждён в APK)
**Задача:** Flutter-скелет: роутинг, DI, state, dio + JWT-интерсептор.
**Критерий готовности:** APK собирается под Android 11+; есть навигация, DI и управление состоянием; dio ходит на бэкенд с автоматической подстановкой и обновлением токена.

Общая архитектура — в [architecture.md](../architecture.md) (раздел «Слои клиента (Flutter)»).

## Что сделано

| Артефакт                                       | Назначение                                                                 |
|------------------------------------------------|----------------------------------------------------------------------------|
| `lib/main.dart`, `lib/app.dart`                | Bootstrap (DI → runApp), `MaterialApp.router` + гейт навигации по auth     |
| `lib/core/di/`                                 | get_it + **injectable** (`configureDependencies()`, генерация графа)       |
| `lib/core/router/`                             | **auto_route**: `AppRouter`, `AuthGuard`                                   |
| `lib/core/network/`                            | dio-фабрика (injectable-модуль) + **auth_interceptor** + talker_dio_logger |
| `lib/core/auth/`                               | `TokenStorage`, `AuthRepository`, `AuthCubit`, `Profile`                   |
| `lib/core/error/failure.dart`                  | `Failure` — freezed sealed-union (network/auth/server/unknown)             |
| `lib/core/theme/`                              | Тема под ТСД (крупные «пальцевые» элементы)                                |
| `lib/features/{auth,home,debug}/presentation/` | Экраны: вход, меню, просмотр логов (talker)                                |
| `android/app/build.gradle.kts`                 | `minSdk = 30` (Android 11)                                                 |

### Ключевые решения

- **Кодогенерация:** auto_route + freezed + json_serializable + injectable через `build_runner` (`dart run build_runner build`).
- **Ошибки:** `either_dart` (`Either<Failure,T>`) + freezed-union `Failure`; bloc делает `fold` в состояние — без try/catch в UI.
- **Логирование — talker (сразу):** `talker_dio_logger` в цепочке dio, `talker_bloc_logger` как `Bloc.observer`, `talker_flutter` — экран логов **на устройстве** (для ТСД без консоли). Единый `Talker` — синглтон в DI.
- **Токен-стор — in-memory** (в P0-06 заменится на flutter_secure_storage; абстракция `TokenStorage` останется).
- **Base URL** — через `--dart-define=BASE_URL=...` (дефолт `http://10.0.2.2:8080` = localhost хоста из эмулятора).
- **Навигация гейтится состоянием `AuthCubit`:** `BlocListener` в `app.dart` — единое место (вошёл → меню, вышел/протух refresh → вход).

## Два токена (access + refresh) — как работает клиентская часть

JWT-интерсептор (`core/network/auth_interceptor.dart`) — клиентская пара к middleware бэкенда (P0-04).

- **access** (короткий, 12 ч) — прикладывается к **каждому** запросу заголовком `Authorization: Bearer …`; бэкенд проверяет подпись без БД.
- **refresh** (длинный, 30 д) — не ходит с запросами; нужен, чтобы **молча получить новый access**, когда старый протух, не пересканируя бейдж.

```
1. Вход по бейджу ──► POST /auth/login ──► { access(12ч), refresh(30д) }  → в TokenStorage
2. Любой запрос:  GET /… + Bearer access ──► 200
3. access протух: GET /… ──► 401
                  интерсептор САМ: POST /auth/refresh { refresh } ──► новый access
                  → повторяет исходный запрос (пометка retried защищает от цикла) → 200
                  пользователь ничего не заметил
4. refresh протух (30 д): refresh ──► 401 → чистим токены → экран входа (пересканировать бейдж)
```

Ключевое: refresh делается **отдельным «голым» dio** (без этого интерсептора), иначе была бы рекурсия.
В P0-06 добавится персистентность токенов (secure storage) и авто-вход при старте.

## Запуск и проверка критериев готовности

### 1. Сборка APK под Android 11 (главный критерий)

```bash
cd apps/craft_wms
flutter build apk --debug
```
Ожидаемо: `✓ Built build/app/outputs/flutter-apk/app-debug.apk`.
Проверка minSdk в самом APK: `aapt2 dump badging …/app-debug.apk | grep minSdkVersion` → `minSdkVersion:'30'`.

### 2. Кодогенерация (после правок аннотаций)

```bash
cd apps/craft_wms
dart run build_runner build
flutter analyze          # No issues found!
```

### 3. Запуск на эмуляторе + вход через бэкенд (полный цикл)

**a. Старт бэкенда** (из корня проекта):
```bash
colima start                              # если docker-демон ещё не запущен
make up && make migrate-up && make seed   # стек + схема + админ
```

**b. Запуск приложения** (эмулятор; BASE_URL по умолчанию `10.0.2.2:8080` = localhost хоста):
```bash
flutter emulators --launch Pixel_8_Pro
cd apps/craft_wms
flutter run                               # выбрать устройство-эмулятор (emulator-5554)
```
В приложении: ввести бейдж (16 цифр, напр. `1000000012345678`) → «Войти» → меню с профилем
(логин `10000000`, роль `admin`). Меню → иконка «Логи» открывает talker-экран с запросами dio.

**c. Остановка (возврат к исходному состоянию):**
```bash
# 1) в терминале flutter run — нажать q (выход из приложения)
# 2) погасить эмулятор — закрыть его окно, либо adb (в Android SDK platform-tools):
~/Library/Android/sdk/platform-tools/adb -s emulator-5554 emu kill
make down                                 # 3) стек (из корня); данные БД сохранятся в volume
colima stop                               # 4) остановить docker-демон
```

> Экраны операций (приёмка/размещение/…) ещё не подключены — это оболочка. Реальный скан бейджа
> вместо поля ручного ввода и secure storage — задача **P0-06**.

## Границы задачи

- Ввод бейджа — **временное поле** (не скан); скан сканером ТСД / камерой — **P0-06**.
- Токены — **in-memory**; secure storage + авто-вход при старте — **P0-06**.
- Экранов бизнес-логики нет — только вход/меню/логи; операции — фазы P1–P6.
- Запуск/установка на реальный ТСД (Urovo DT50) — задача **P0-07**.
