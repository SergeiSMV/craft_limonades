# CZ-04 · Чтение по марке и коду агрегации: данные продукции, раскрытие агрегата

**Статус:** ✅ завершена (проверено на DT50S против прода: марка и транспортный короб).

## Задача

Научить ТСД понимать скан марки Честного знака и кода транспортного короба: показать данные
продукции из ЧЗ, товар справочника, где марка лежит в WMS и, для упаковки, её состав до единиц
с партиями. Сейчас марка `01…21…` уходит в текстовый поиск «Остатков», а код короба `00`+SSCC
принимается за ШК товара и ТСД предлагает привязать его к товару.

## Критерий готовности

По скану марки или кода агрегации на ТСД получены данные продукции и состав:

- скан марки в «Остатках» или «Номенклатуре» открывает карточку товара с блоком «Марка»
  (данные ЧЗ, приход и место в WMS);
- марка с незнакомым GTIN предлагает привязать ШК к товару поиском, затем открывает карточку;
- скан короба открывает карточку ГЕ, если короб есть в WMS, иначе — состав по ЧЗ:
  товар × партия × количество.

## Устройство

Решения (2026-10-23):

- **Скан марки — тот же сценарий, что скан ШК, с одним отличием:** открывается карточка товара
  и история этой марки. Наименование на марке может отличаться от номенклатуры 1С — товар
  определяет привязка ШК, а не название.
- **Незнакомый GTIN — привязка ШК поиском**, как у любого незнакомого ШК (ADHOC-06). Привязывается
  EAN-13 — GTIN-14 без ведущего нуля: тогда и обычный скан ШК той же бутылки найдёт товар.
- **История марки в CZ-04 — то, что известно сейчас:** даты ЧЗ (производство, ввод в оборот),
  приход в WMS и текущее место. Журнал движений марки появится вместе с движением марок в CZ-06.
- **Чтение — только онлайн:** True API работает только со связью. Без связи ТСД говорит
  «нужна связь»; приёмка без связи — долг 17, решается до CZ-05.
- **Код марки идёт на сервер в теле запроса,** не в пути: в КИ бывают `/`, `%`, `"`, а нынешний
  запрос ШК `barcodes/{code}` URL-кодирования не делает.
- **Сервер приводит код к ключу ЧЗ сам:** срезает префикс AIM (`]d2`, `]C1`) и криптохвост
  после GS. Вид кода: `00`+18 цифр — короб; `01`+14 цифр+`21`… — КИ марки или групповой упаковки,
  что именно — по ответу ЧЗ (`generalPackageType`).
- **Состав агрегата раскрывается до единиц:** ЧЗ по коробу отдаёт только КИ вложенных; сервер
  дочитывает их пачками до 100 кодов и спускается, пока не дойдёт до `UNIT`. Единицы
  сводятся по товару и партии — дате производства **единицы** (ADR-0017).

## План реализации

1. ✅ **Сервер, чтение по коду** — `CZService.Scan(code)` (`service/cz_scan.go`). Хранилище
   марок подключено к сервису интерфейсом `CZMarks`, без БД скан отдаёт только данные ЧЗ.
   Товар по GTIN ищется один раз на GTIN, вложенные коды, по которым ЧЗ отказал, идут
   отдельным списком «не прочитаны»:
   - разбор кода: префикс AIM, GS, вид; неверный код — ошибка ввода;
   - данные ЧЗ по коду (`cises/info`); товар справочника по GTIN (`CZMarkRepository`);
   - для марки — что знает WMS: статус, место, когда пришла (`cz_marks`);
   - для короба — ГЕ, если он есть в WMS (`cz_aggregates`);
   - для упаковки — состав до единиц, сведённый по товару и партии, с КИ.
2. ✅ **Ручка для кладовщика** `POST /api/v1/cz/scan {code}` (`handler/cz_scan.go`), любому
   вошедшему сотруднику. Ошибки — как у `admin/cz/info`, плюс `400` на код, который не марка и
   не короб: нет договора по группе — `422`, код не найден — `404`, ЧЗ недоступен — `502`, не
   настроено — `503`. Даты ЧЗ в ответе — днём (`YYYY-MM-DD`). Формат закреплён эталонами
   `testdata/cz_scan_mark.json` и `cz_scan_box.json`: Go-тест требует от настоящего роутера
   ровно их, Dart-тест (шаг 4) разбирает те же файлы.
3. ✅ **ТСД, разбор скана** (`core/scanner/cz_code.dart`, `scan_code.dart`): новые виды
   `czMark` и `czBox`, распознаются раньше «похоже на ШК». Префикс AIM срезается; GS по краям —
   явно, потому что `trim()` в Dart его не срезает. В шести экранах, где марки ещё не ждут
   (приёмка, размещение, перемещение, проблемы, возврат, содержимое), новые виды идут в ветку
   незнакомого кода. Код короба больше не уходит в «товар» с предложением привязать ШК. Юнит-тесты
   разбора на кодах короба пива с прода.
4. ✅ **ТСД, фича `cz`** по слоям (`domain` — сущности и интерфейс репозитория, `data` — API и
   реализация, `presentation` — кубит): запрос `cz/scan`, понятные ошибки. Код уходит в теле как
   есть, без кэша — данные ЧЗ живые. Таймаут 30 с: по коробу сервер делает несколько запросов в
   ЧЗ подряд. Кубит отбрасывает новый скан, пока читается предыдущий. Тест разбирает те же
   эталоны `cz_scan_*.json`, что сервер обязан отдавать.
5. ✅ **ТСД, сценарии в «Остатках» и «Номенклатуре»** (общий обработчик поиска
   `goods_search_handlers.dart`, ветка ЧЗ — раньше ячеек и ШК):
   - марка, товар известен — карточка товара с блоком «Марка» (`CzMarkSection`): наименование
     по ЧЗ своей строкой, статус в ЧЗ, даты, владелец, короб (короткий код), ячейка, приход;
   - марка, GTIN незнаком — «Привязать ШК?» с названием марки → выбор товара → карточка с
     блоком марки (тот же путь, что у незнакомого ШК);
   - короб в WMS — карточка ГЕ; короб не в WMS или групповая упаковка — экран состава
     `CzCompositionPage`: строка на товар × партию с количеством, нечитаемые коды — числом;
   - без связи — «Честный знак без связи не прочитать», отказ сервера — его словами.

   Куда вести по ответу, решает чистая функция `czScanTarget` — одно правило для всех мест
   скана, проверяется без страниц. Вёрстка — `SectionTitle` + `DetailCard`, каждый факт своей
   подписанной строкой, как в карточке проблемы. Сервер дополнен адресом ячейки марки
   (`cell_address`, ячейка короба или своя): на ТСД справочника ячеек по id нет. Кубит скана
   заводится первым сканом марки, а не с экраном.
6. ✅ **Проверка на проде** — релизная APK на DT50S, прод с CZ-04 (бэкенд после выкатки сам
   получил токен True API):
   - марка чипсов (чужой владелец, «выбыла из оборота», GTIN не был привязан) — предложение
     привязать ШК, после привязки — карточка товара с блоком марки: наименование по ЧЗ своей
     строкой, статус, даты, владелец, «на складе не числится»;
   - транспортный короб пива из CZ-02 — экран состава: 24 единицы, «короб не принят на склад»,
     одна строка — партия 12.10.2026, «товар не привязан, GTIN 04612728200172».

   Всё совпало с ответами ЧЗ.
7. ✅ **Документы:** этот файл, `docs/cz/README.md`, `docs/architecture.md` (ручка и фича ТСД),
   ADR-0017 («Последствия» для CZ-04).

## Проверка

Сервер (тесты ручки — без Docker, сценарные тесты пакета `handler` — с ним):

```bash
cd apps/backend
go test -run 'Scan|CZ' ./internal/service ./internal/handler
```

ТСД:

```bash
cd apps/craft_wms
flutter test test/core/scanner test/features/cz
```

Ожидаемо: `ok` и `All tests passed!` — разбор кодов со сканера, эталоны ответа, все исходы
`czScanTarget`, блок марки и экран состава.

На DT50S против прода (релизная APK): в «Остатках» отсканировать марку пива из CZ-02 —
карточка товара с блоком марки; марку с незнакомым GTIN — предложение привязать ШК;
транспортный короб пива — состав (короб ещё не принят) с 24 единицами.

## Границы задачи

- Приёмка марок и привязка к коробу и ячейке — CZ-05; журнал движений марки — CZ-06.
- Без связи марка не читается (долг 17).
- Паллеты (агрегат над коробами) раскрываются тем же спуском, но на живых данных не
  проверены: на складе пока не попадались (хвост CZ-01).
