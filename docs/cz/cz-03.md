# CZ-03 · Схема БД марок: марка ↔ товар / партия / короб / ячейка, коды агрегации

**Статус:** ✅ завершена (проверено интеграционными тестами и на тестовом стенде поверх снимка прода).

## Задача

Завести в базе марки Честного знака и агрегаты ЧЗ так, чтобы про каждую марку было известно:
какой это товар и партия, в каком коробе или ячейке она лежит, в какой упаковке ЧЗ она пришла
и вскрыта ли эта упаковка. Схема — основа для чтения (CZ-04), приёмки (CZ-05) и движения
марок (CZ-06).

## Критерий готовности

Марка и агрегат хранятся с привязкой к месту на складе: интеграционные тесты сохраняют
транспортный короб ЧЗ как ГЕ с составом марок, групповую упаковку внутри него и марку
россыпью в ячейке, находят ГЕ по SSCC и товар по GTIN марки. Миграция прогнана на тестовом
стенде поверх снимка прода.

## Устройство

Решения (2026-10-23):

- **Транспортный короб ЧЗ — это ГЕ WMS.** Его узнают по коду `00`+SSCC со штрихкода GS1-128,
  свой QR-ярлык на него не печатается. Размещение, перенос, история и содержимое — готовые
  механизмы ГЕ. Свой короб с QR остаётся для россыпи: в ЧЗ он не регистрируется (ADR-0017).
- **Код агрегата живёт в одном месте — `cz_aggregates`.** Связь «короб ЧЗ ↔ ГЕ» —
  `cz_aggregates.load_unit_id`, уникальная; `load_units` не меняется.
- **Агрегаты ЧЗ — коробы (`BOX`) и групповые упаковки (`GROUP`)**, вид — из
  `generalPackageType` (сверено на проде в CZ-02). Вложенность — `parent_code`: групповая
  упаковка внутри короба. Признак «вскрыт» — `opened_at`: из упаковки изъята марка (CZ-06).
- **Марка — ключ КИ** (`01`+GTIN+`21`+серийный, часть до GS). GTIN вычисляется из КИ
  (generated-колонка) — не хранится вторым экземпляром.
- **Марка всегда — единица остатка:** товар и партия обязательны, составной FK
  `(batch_id, good_id) → batches`, как у `stock` и `lu_content`. Марка неизвестного товара в
  остаток не попадает — это расхождение «не тот товар» для «Проблем склада» (CZ-05).
- **Место марки — ровно одно, пока она на складе:** в ГЕ (`load_unit_id`; место ГЕ хранится
  только в `load_units.cell_id`, марка его не дублирует) или россыпью (`cell_id` +
  `internal_warehouse_id` — грань остатка, ADR-0016). Ушедшая со склада марка (`shipped`,
  `written_off`, `returned`) места не имеет. Держит это `CHECK`.
- **Упаковка ЧЗ и место — разные вещи:** `aggregate_code` — в какой упаковке ЧЗ марка пришла
  (меняется только расформированием в ЧЗ), `load_unit_id`/`cell_id` — где она физически сейчас.
- **Товар по GTIN — через `barcodes`:** GTIN-14 единицы — это её EAN-13 с ведущим нулём
  (марка пива `04612728200172` ↔ ШК `4612728200172`). Отдельной колонки GTIN у товара не
  завожу: ШК из выгрузки 1С уже есть.

## План реализации

1. ✅ **Миграция `000026_chestny_znak_marks`** (up/down). На чистой базе прогнал полную
   цепочку up → down → up. Ручными вставками проверил: допустимое проходит, а 13 недопустимых
   вставок база отвергает — код с GS, ГЕ у групповой упаковки, вторая ГЕ у короба, повтор КИ,
   марка без места и в двух местах, чужая партия, сама себе родитель, удаление короба с
   упаковками.
   - `cz_aggregates`: `code` PK (`00`+18 цифр или КИ групповой упаковки), `kind`
     (`BOX`/`GROUP`), `parent_code` self-FK, `load_unit_id` UNIQUE FK (только у `BOX`),
     `opened_at`, `created_at`/`updated_at`;
   - `cz_marks`: `cis` PK, `gtin` generated, `good_id`, `batch_id` (составной FK), `status`
     (`in_stock`/`shipped`/`written_off`/`returned`), `load_unit_id`, `cell_id`,
     `internal_warehouse_id`, `aggregate_code`, `created_at`/`updated_at`;
   - `CHECK` формата кодов, вида упаковки и «ровно одно место у марки на складе»;
   - индексы под «марки короба», «марки ячейки», «марки упаковки».
2. ✅ **Модель** `model/cz.go`: марка, агрегат, статусы и ошибки-сигналы.
3. ✅ **Репозиторий** `repository/cz_marks.go` (запись — и функциями на `Querier`, чтобы
   приёмка CZ-05 писала марки в одной транзакции со своим документом):
   - сохранить агрегат и марки одной транзакцией;
   - ГЕ по SSCC, марка по КИ, марки ГЕ и ячейки, состав упаковки;
   - товар по GTIN через `barcodes`.
4. ✅ **Интеграционные тесты** (testcontainers, `cz_marks_integration_test.go`, одна база на
   семь случаев): короб ЧЗ как ГЕ с составом, групповая
   упаковка в коробе, марка россыпью, отказ `CHECK` на марку без места и с двумя местами,
   повторный КИ — конфликт, товар по GTIN. Короб с ошибочной маркой откатывается целиком —
   ни короба, ни остальных марок.
5. ✅ **Тестовый стенд.**
   - На стенде (база из снимка прода от 21.10, схема 25) `stand.sh migrate` поднял её до 26.
     Данные на месте: 7 ГЕ, 780 товаров, 209 ШК.
   - Пробная запись в транзакции с откатом на реальных данных: короб ЧЗ на ГЕ из снимка,
     марка в нём и марка россыпью находят товар по GTIN через ШК. После отката следов нет.
   - Откат и повтор — на черновой копии того же снимка, не на базе стенда: 22 → 26 подряд,
     откат 000026 убирает обе таблицы, повторный подъём возвращает 26.
6. ✅ **Документы:** `docs/data-model.md` (новые таблицы, инварианты), этот файл,
   `docs/cz/README.md`, ADR-0017 (раздел «Последствия» для CZ-03).

`TESTCONTAINERS_RYUK_DISABLED=true`):

```bash

go test -run TestCZMarks -v ./internal/repository
```

целиком, уникальность, одно место, «не найдено», товар по GTIN.

```bash
colima stop
```

## Границы задачи

- Ни ручек, ни экранов: чтение по скану — CZ-04, приёмка — CZ-05, движение марок — CZ-06.
- Журнала перемещений марок нет: место марки следует за ГЕ, а у ГЕ журнал уже есть
  (`placements`). Россыпь марок движется операциями CZ-06.
- Признак «маркируемый товар» (долг 16) и проверка марок без связи (долг 17) — до CZ-05.
- Найдено на снимке прода для CZ-04/05: пива «Голубые Гавайи 30 л» (марка из CZ-02) в
  справочнике нет вовсе, а ШК `4612728200172` — ни у одного товара. Марку товара, которого нет
  в номенклатуре 1С, `GoodByGTIN` не опознает. В справочнике есть и 14-значные ШК (GTIN
  короба `14620046021468`) — поиск находит их по полному совпадению.
