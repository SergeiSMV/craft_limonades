# Бизнес-процесс: ввод стартовых остатков (проход склада с ТСД)

**Назначение:** описать, как склад впервые заносит остатки в WMS — проходом с терминалом сбора
данных (ТСД), сканируя ячейки и товар. Это же — механизм **стартовых остатков перед пилотом**
(1С не знает ячейку, поэтому остаток заводится физическим проходом, а не импортом).

**Реализация:** фаза `P-FastStart` — ТЗ в [`p-faststart/p-faststart-1.md`](p-faststart/p-faststart-1.md), схема данных в
[`docs/data-model.md`](data-model.md). Здесь — процесс глазами пользователя, без кода.

---

## Роли

- **Кладовщик (`employee`)** — проходит склад с ТСД, сканирует, вводит количество. Привязывает ШК
  к товару прямо на проходе.
- **Оператор / администратор (`admin`)** — на портале печатает этикетки ячеек, а после прохода
  скачивает Excel-документ «ввод остатков» и сверяет с 1С.

---

## Предусловия

1. **Справочники загружены:** номенклатура (импорт `.xls` 1С) и ячейки (импорт `.xlsx`) уже в базе.
2. **Этикетки ячеек наклеены.** Администратор на портале (вкладка «Ячейки») скачивает
   **PDF-этикетки** (A4, 1 колонка × 8 этикеток; на каждой — штрихкод Code128 с адресом ячейки,
   крупный адрес и стрелка вниз для напольных). Этикетки печатают, режут и **клеят на ячейки**.
   Это делается **один раз** перед первым проходом.

---

## Основной сценарий

1. **Вход.** Кладовщик прикладывает бейдж → вход по бейджу. Открывает пункт меню **«Ввод остатков»**
   — начинается **сессия ввода** (один документ на проход).
2. **Ячейка.** Сканирует этикетку ячейки → система распознаёт ячейку по адресу и показывает её в
   шапке экрана. *(Если этикетка повреждена/не читается — ячейку можно выбрать из списка.)*
3. **Товар.** Берёт из ячейки физическую единицу и сканирует её штрихкод:
   - **ШК известен** → система сразу показывает товар.
   - **ШК неизвестен** (первый раз встречаем) → открывается привязка: кладовщик находит товар в
     номенклатуре и выбирает его. **Штрихкод привязывается к товару** — в следующий раз этот ШК
     определится сам. *(Так справочник штрихкодов наполняется прямо за первый проход.)*
   - **У товара нет штрихкода** (весовой и т.п.) → кладовщик **добавляет товар вручную** из
     номенклатуры, без привязки ШК.
4. **Партия.** Вводит **дату выпуска** (обязательно) — это и есть партия. Разные даты одного товара —
   это **разные строки**.
5. **Количество.** Набирает либо **сканируя единицу за единицей** (каждый скан +1), либо **вводит
   фактическое число** сразу. В пределах ячейки товар одной партии — одна строка, повторные сканы
   идут в неё.
6. **Отмена (Undo).** Ошибся — **откатывает последнюю операцию** (до 10 подряд). Откат снимает
   строку **целиком**: и количество, и — если этой строкой был привязан новый ШК — саму привязку.
   Отмена работает по **текущей ячейке, пока она не завершена**.
7. **Завершение ячейки.** Закончив ячейку, жмёт **«Завершить ячейку»** — введённое по ней
   фиксируется в документе (и сохраняется, чтобы не потерять при долгом проходе). После этого строки
   ячейки уже не откатываются кнопкой отмены.
8. **Следующая ячейка** — возврат к шагу 2. И так весь склад (или его часть за смену).
9. **Завершение ввода.** В конце жмёт **«Завершить ввод остатков»**:
   - все строки документа записываются в **остатки WMS** (количество в ячейке = введённому);
   - остатки становятся видны в разделе **«Остатки»** на ТСД;
   - на портале, в разделе **«Инвентаризация»**, появляется **Excel-документ «ввод остатков»**.

---

## После прохода: сверка с 1С

Администратор на портале открывает раздел **«Инвентаризация»**, скачивает Excel «ввод остатков»
(колонки: склад · ячейка · код товара · наименование · дата выпуска · количество) и **сверяет с
базой 1С** либо использует его, чтобы разнести остатки. Это ручная сверка — прямого обмена с 1С в
пилоте нет (по решению проекта отказ от REST-интеграции).

---

## Важные правила и границы

- **Количество — это «сколько лежит по факту»** (SET), а не «прибавить». Повторный проход той же
  ячейки/партии перезапишет значение, а не удвоит.
- **Дата выпуска обязательна** — без неё строку не завести (партия не определена).
- **Отмена — только по текущей, ещё не завершённой ячейке.** Исправить уже завершённую ячейку в
  первой версии нельзя (при необходимости — доработка позже).
- **Работа только онлайн.** Первый проход — под Wi-Fi; офлайн-режим (продолжать без связи) —
  отдельный этап (фаза P2).
- **Это не полная инвентаризация.** Здесь заводятся стартовые остатки и проверяется оборудование;
  циклический пересчёт со сверкой «ожидалось/факт» — отдельная фаза (остальной P10).

## Что видит кладовщик (кратко)

```
[Вход по бейджу]
      │
      ▼
[Меню] → «Ввод остатков»  ──► открыта сессия
      │
      ▼
┌─────────────────────────────────────────────┐
│ Скан ЯЧЕЙКИ (или выбор из списка)            │◄────────────┐
│   ▼                                          │             │
│ Скан ТОВАРА                                  │             │
│   ├─ ШК известен → товар                     │             │
│   ├─ ШК неизвестен → привязать из номенкл.   │             │
│   └─ без ШК → добавить вручную               │             │
│   ▼                                          │             │
│ Дата выпуска (партия) + Количество (+1/ввод) │             │
│   ▼                                          │             │
│ [Undo ≤10]   [Завершить ячейку] ─────────────┼── следующая ┘
└─────────────────────────────────────────────┘
      │
      ▼
[Завершить ввод остатков] → остатки в WMS + Excel в портале
```
