# P1-09-0 · Переезд API под префикс `/api/v1`

**Статус:** ✅ бэкенд готов, контур зелёный (build/vet, gofmt, golangci-lint 0 issues, сквозной смоук через стек). Переустановка ТСД и правка прод-nginx — при выкатке (см. «Границы»).
**Задача:** увести прикладной API под версионированный префикс `/api/v1`, освободив корень домена под статику веб-портала. Пробы `/health`, `/ready` оставить на корне.
**Критерий готовности:** ТСД логинится через `/api/v1/auth/login`; `/health` на корне отвечает 200; корень (`/`) свободен под статику портала.

---

## Зачем (ADR-0015)

Веб-портал (P1-09-1) занимает корень `craft.skogi.ru/`, поэтому API уезжает в свой неймспейс
`/api/v1/`. Выгода: **один origin** (портал и API на одном домене → без CORS, один сертификат),
версия в пути даёт запас на эволюцию без ломки клиентов. Схема URL обоснована в
[ADR-0015](adr/0015-url-scheme-api-v1-portal-root.md).

## Что сделано

- **`internal/handler/router.go`** — прикладные роуты (`/auth/*`, `/import/*` и все будущие)
  обёрнуты в `r.Route("/api/v1", …)`. Пробы `/health` и `/ready` **остались на корне**: их дёргает
  docker-healthcheck напрямую к контейнеру, и это не часть публичного API. Внутренняя структура групп
  (rate-limit на публичных auth-роутах, `Authenticator`/`RequireRole` на защищённых) не менялась.
- **`internal/handler/auth.go`, `import.go`** — doc-комментарии обновлены на полные пути
  (`POST /api/v1/auth/login` и т.д.).
- **`apps/craft_wms/lib/core/config/app_config.dart`** — дефолт `BASE_URL` →
  `http://10.0.2.2:8080/api/v1`. Пути в коде относительные (`dio.baseUrl + '/auth/login'`), поэтому
  версия задаётся в базовом URL, **кода приложения не касались**. Для прод-сборки —
  `--dart-define=BASE_URL=https://craft.skogi.ru/api/v1`.

### Ключевые решения

- **`/health`, `/ready` — на корне, вне `/api/v1`.** Это инфра-пробы: healthcheck compose бьёт
  `http://127.0.0.1:8080/health` напрямую в контейнер, поэтому менять его и `docker-compose` не нужно.
- **nginx не трогали в этой задаче.** Сейчас `location /` проксирует всё на backend — запросы
  `…/api/v1/*` и корневой `/health` продолжают ходить как есть. Разделение `location /api/ → backend`
  vs `location / → статика` появится вместе с бандлом портала в **P1-09-1** (без статики делать split
  нечем и незачем). Корень при этом уже свободен: backend отдаёт 404 на `/`, готов под статику.

## Границы задачи (доделывается при выкатке P1-09-1 / релизе)

- **Переустановка APK на DT50** с `BASE_URL=…/api/v1` — при выкатке. ⚠ Координация: авто-обновление
  pull-моделью подтянет новый бэкенд с прода за ~5 мин после мержа в `main`, и старый установленный
  APK в это окно перестанет логиниться — новый APK ставим в то же окно.
- **Прод host-nginx** (`infra/nginx/craft-wms.conf.template` и vhost на сервере): split
  `location /api/` / `location /` — в P1-09-1, когда появится статика портала.

```bash
make down && colima stop
```
